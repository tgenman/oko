# 03: Пауза и продолжение истории

**What to build:** В настройках фида пользователь приостанавливает начальную историю и продолжает её позже. Пауза сохраняет набор и прогресс, а сбор новых публикаций продолжается независимо.

**Blocked by:** 01 — Начальная история RSS/YouTube; 02 — Начальная история Telegram.

**Status:** done

- [x] Во время начальной загрузки доступна кнопка «Приостановить историю», в состоянии паузы — «Продолжить историю».
- [x] Пауза останавливает продолжение начальной истории и сохраняет уже полученный результат.
- [x] Новые публикации продолжают собираться во время паузы истории для всех трёх типов источников.
- [x] После перезапуска сохраняется состояние паузы; история не возобновляется самопроизвольно.
- [x] Продолжение использует прежний набор и границу; повторное сохранение не увеличивает прогресс.
- [x] Управление доступно для обоих режимов; завершённая история отображается без предложения повторной загрузки.

**Проверки:** HTTP API читателя: пауза, новые поступления, перезапуск и продолжение для RSS/YouTube и Telegram. Браузерный сценарий состояния кнопок и прогресса.

**Контекст:** Спецификация «Выбор начальной истории при подключении источника» в локальном трекере initial-history. Пауза начальной истории отличается от выключения всего фида. Реализация требует отдельного разрешения пользователя.

**Verification:** 23 focused HTTP/adapter tests (5 new pause cases covering RSS count/date, YouTube and Telegram); browser pause/resume/completion controls; mypy: 36 modules clean; diff check clean. Pause persists independently of feed transport, excludes archived fetch jobs, invalidates in-flight generations and preserves the selected boundary. A paused Telegram source establishes its live cursor without enrolling archive publications.
