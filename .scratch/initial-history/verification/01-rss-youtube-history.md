# Проверка задачи 01

## Результат

Форма RSS/YouTube сохраняет выбранную начальную историю до сбора. Последние N фиксируются при первом успешном XML-ответе. Сохранённые исходные публикации и анонсы поддерживают продолжение даже после выпадения из окна фида. Обычный планировщик загружает материалы по одному; прогресс отражает завершённые сохранения независимо от AI. Новые публикации не входят в исторический счётчик.

## Проверки

- HTTP: 8 сценариев начальной истории прошли — умолчание 20, фиксация набора и новые поступления, дубли записей XML не расходуют N, валидация, московская граница полуночи, включительность даты, восстановление 7 из 20 при сменившемся окне, YouTube и независимость от тезисов, большой целый N без продуктового ограничения.
- TDD: сначала наблюдались отсутствие initial_history, отсутствие сохранённого прогресса, отсутствие элементов формы. Затем каждый сквозной срез стал зелёным. Дополнительный red для повторённых XML-записей показал 1 вместо 2; выбор по уникальным исходным публикациям исправил результат. Большой N в десятичном текстовом транспорте сначала отвергался 422; теперь точное значение сохраняется.
- Python: полный набор 227 passed перед последним уточнением дублей/большого N; после уточнений целевые 8 passed и mypy чистый (36 модулей).
- Браузер: все 19 сценариев плюс служебный модуль passed (20 tests). Новый сценарий переключает количество/дату, проверяет отправленный часовой пояс и видимый прогресс.
- Форматирование diff: git diff --check чистый.

Проверки используют временное хранилище и управляемый HTTP-транспорт, без личных подписок и реальной AI-обработки.

## Контракт для следующих задач

- initial_history в контракте подключения: mode=count, count=20 по умолчанию; либо mode=date, count=null, date=YYYY-MM-DD, timezone=IANA. Большой count допускается десятичной строкой для точной передачи браузером; хранится целым числом.
- History.configure сохраняет выбор; History.freeze фиксирует исторические item IDs. Store.discovered вызывает freeze только если cursor содержит history_ids. Для пагинации Telegram допускается развитие этого интерфейса без пересоздания конфигурации.
- Общий ответ состояния фида: mode/count/count_text/date/timezone/since, frozen, paused, loaded, incomplete, viewed, available, state. count_text сохраняет точное представление количества для браузера. Состояния pending/loading/done. Исходы материалов pending/loaded/incomplete/viewed. Явный просмотр ожидающего материала завершает его ожидание без ложного увеличения loaded.
- HTTP status содержит initial_histories с feed_id. Настройки показывают history-progress, обновляемый обычным опросом состояния.
- Общий браузерный модуль предоставляет bindInitialHistory(prefix) и historyProgress(history); его можно использовать в форме Telegram.
- Особенности ограниченного окна, неизвестных дат, паузы, повторов и окончательной недоступности остаются в задачах 03–05.
