# Прототип: Telegram не предоставляет весь пост

Вопрос: как показать пост, полностью недоступный для веб-просмотра, отдельно от внешнего аудио и видео с подтверждённым ограничением размера?

Прототип удалён из рабочего frontend при реализации. Для просмотра восстановить локальную архивную ветку `codex/telegram-post-prototype-20261021` (коммит `d4c2a7b05f782511e9732802c1bde5fc3e95a503`) отдельно; в ней запуск `npm run prototype:telegram-post`.
URL: http://127.0.0.1:5188/?variant=A&case=post

A — отдельный экран поста; B — компактное пояснение; C — карточка ссылки.
Переключение снизу и стрелками клавиатуры. Строки слева переключают post/audio/video/error.

Пост 2806 проверен по публичному HTML 21 октября: `.text_not_supported_wrap` и явная заглушка `.message_media_not_supported`, без собственного текста. Тип не известен. Не считать его аудио или большим видео. Пустой ответ без явной заглушки не является этим состоянием.

Аудио и видео показывают текущие production-компоненты вложений, а не варианты нового состояния. Соседние тексты и макет ошибки демонстрационные. Весь прототип без API, пользовательских данных и сохранения; только внешние ссылки ведут к Telegram.

Проверка: Playwright + установленный Chrome, A/B/C и переходы audio/video/error; снимки просмотрены. Начальный запуск с bundled Chromium не выполнен: браузер не установлен; использован Chrome согласно инструкции репозитория. Автотесты для throwaway не добавлялись.

Выбран **вариант C — карточка ссылки** (21 октября 2026). Отдельное состояние всего поста не смешивается с внешним аудио и слишком большим видео. Итоговое поведение и критерии: [spec.md](spec.md). Primary source сохраняется в локальной ветке `codex/telegram-post-prototype-20261021`.
