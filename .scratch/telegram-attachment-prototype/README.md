# Прототип пометки внешнего Telegram-вложения

Вопрос: где показывать аудио, которое есть в посте, но не выдаётся публичным Telegram-предпросмотром, чтобы это не выглядело как ошибка загрузки?

Исторический запуск в архивном дереве: `npm run prototype:telegram-attachment`. После реализации throwaway-исходники удалены из рабочей ветки. Архив: `codex/telegram-external-prototype-20261021`, коммит `8f76c1ea65ecc7dea92925b34c335d105f76175b`; восстановление — [реестр прототипов](../../docs/agents/prototype-archive.md).
URL: http://127.0.0.1:5188/?variant=B (A/B/C; стрелки внизу и клавиши ←/→).
Отдельный dev entry на существующем маршруте `/`, настоящий ReaderShell, статическое содержимое выбранного публичного поста. Нет API, пользовательских источников, аккаунтов, сохранения состояния и изменений сборщика. Продакшен entry не подключает прототип. Соседний прототип открытого материала не менялся.

Варианты:

- A: компактная пометка после текста.
- B: самостоятельная карточка аудиовложения перед текстом с названием, автором и внешней ссылкой.
- C: общее пояснение под заголовком перед текстом.

2026-10-21 пользователь выбрал B для открытого материала. На этапе выбора варианта production-реализация ещё не начиналась; были запрошены план и прототип значка. План: [spec.md](spec.md). Для значка добавлен режим `?variant=B&listVariant=A/B/C`, сохраняющий карточку B справа. Пользователь выбрал A для списка и уточнил, что значок должен быть специфичным для аудио. Прототип обновлён: аудио — ноты, документ — файл; подписи называют конкретный тип и доступность в Telegram. Выбор зафиксирован в spec.md. Итоговая реализация и архив теперь зафиксированы: [отчёт](implementation-verification.md).

Поведение, определённое на этапе прототипа (итоговая реализация описана в отчёте):

- Известное ограничение публичного доступа показывать рядом с вложением как информацию «Аудио доступно в Telegram», без ошибки источника и бессмысленного повтора загрузки.
- Текст и доступные ресурсы сохранять обычным образом; отсутствие локального аудиофайла не скрывать и не маркировать материал «полностью сохранён».
- Ссылка открывает исходный пост. Прототип не обещает воспроизведение аудио в Око, переключение доступа или автоматическую отметку прочитанного в Telegram.
- Для подтверждённого аудио использовать его название; неизвестный тип не угадывать по тексту поста, показывать «Вложение доступно в Telegram».
- Таймаут, обрыв сети, отказ сервера, ошибка скачивания доступного URL или записи на диск сохраняются как реальные ошибки с восстановлением. Только ожидаемая недоступность через текущий способ доступа становится пометкой.

Название вложения «Остаться, уехать или вернуться?», автор «Радио Медуза». Время публикации `2026-10-21T11:13:01+00:00` = 14:13 Москвы.

Текущий `oko/collection/telegram/web.py` (ветка document_wrap) выдаёт kind=document, url=None, reason=«Файл документа не предоставлен публичным предпросмотром». Реальный `parse_page` на полученном HTML воспроизвёл эту классификацию и resource status=unsupported. Отсутствие URL подтверждено; сам аудиофайл и его воспроизведение в Telegram не проверялись.

## Фактическая проверка прототипа

Playwright / Chrome, настольная ширина 1440×1000 и мобильная 390×844, все A/B/C открыты. Снимки `A-desktop.png`–`C-desktop.png`, `A-mobile.png`–`C-mobile.png`. Просмотрены все настольные варианты и мобильный B. Заголовок, пояснение и внешняя ссылка читаются.

Проверены C→A клавишей, A→B кнопкой, сохранение B в URL после reload. На мобильной ширине document.scrollWidth=390 для каждого варианта; ссылка ведёт на заданный пост. Ошибок JavaScript нет. Модуль компилируется Vite при загрузке.

Первый запуск сервера в sandbox остановлен EPERM на loopback; запуск с разрешением успешен. Web-инструмент не смог открыть embed URL, поэтому проверен исходный HTML публичной истории через curl. Defuddle отсутствует; для установления наличия прямого media URL использован исходный DOM.

Тесты по правилам prototype skill не добавлялись, полный прогон не выполнялся. Работающий пользовательский экземпляр не менялся.

## Итог спецификации

Выбор подтверждён пользователем: в открытом материале B; в списке A на превью, с конкретным значком типа вложения. Для видео также выбран B: компактная карточка с обложкой, длительностью, заголовком «Видео слишком большое для веб-просмотра» и ссылкой «Смотреть в Telegram». Окончательные требования и критерии C1–C13 находятся в [spec.md](spec.md).

Рассмотренные варианты списка сохранены в прототипе: A — на превью, B — справа от заголовка, C — отдельная строка под заголовком. В реализацию входит A.
