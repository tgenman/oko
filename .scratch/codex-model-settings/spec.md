# Модель Codex по типу действия

Status: done
Label: ready-for-agent

Согласовано пользователем 2026-10-13. Реализация поручена через implement-spec и завершена; фактические проверки и ограничения: [отчёт](../../docs/verification/codex-model-settings.md).

## Проблема

Пользователь не видит, какую модель Codex Око использует для обработки, и не может выбрать её. Текущий `LocalCodex.complete` запускает `codex exec` без `--model` и с `--ignore-user-config`: выбор остаётся за CLI, а не настройками чата или пользовательским config. Имя модели не сохраняется вместе с результатом. Проверка Codex в интерфейсе сообщает CLI, авторизацию, лимиты и доступность изолированного запуска.

## Согласованные решения

- 2026-10-13: отдельная модель Codex для каждого типа действия. Между действиями модели могут различаться.
- Выбор общий для Око; отдельных моделей по папкам и фидам не требуется.
- Четыре типа действий: фильтрация, тезисы публикации, сводки событий, обзоры за период. Промежуточные и финальные этапы обзора используют одну выбранную для обзоров модель.
- Для каждого типа выбираются модель, усилие рассуждения и Fast. Fast по умолчанию выключен.
- Смена этих настроек применяется к новым запросам. Готовые результаты сохраняются со сведениями о прежней модели; пересоздание выполняется явным действием пользователя. Не запускать массовый пересчёт из-за сохранения настройки.
- Модели выбираются из каталога Codex. При первой настройке предлагаются текущая модель по умолчанию и её стандартное усилие рассуждения. При сохранении фиксируются конкретные значения; обновление CLI не меняет их молча. Недоступная модель даёт понятную ошибку без автоматической замены.
- Начатая работа заканчивает с прежними параметрами. Многоэтапный обзор сохраняет их для всех этапов и после перезапуска. Новая работа получает новый выбор.
- Раскрываемые сведения о результате показывают модель, усилие рассуждения и Fast. Для старых результатов — «Модель неизвестна»; текущую настройку нельзя выдавать за происхождение старого результата.
- «Пересоздать» относится к конкретным тезисам, событию или обзору и использует текущий выбор. Массовое пересоздание в этот объём не входит.
- Проектирование завершено. Пользователь отдельно поручил реализацию через implement-spec.

## Дерево решений

- Охват: по типам действий → согласовано.
  - Перечень типов, границы этапов обзора → согласовано: четыре типа, единая модель этапов обзора.
- Уровень: общая настройка Око → согласовано.
  - Представление выбора модели и источник списка → каталог Codex.
  - Начальное значение и переход существующей установки → предложение default с фиксацией при сохранении; старые результаты сохраняются с неизвестной моделью.
  - Усилие рассуждения и Fast → согласовано; Fast выключен по умолчанию.
- Применение изменений → только новые запросы, готовые результаты сохраняются.
  - Выполняющиеся задания и восстановление незавершённого обзора → зафиксированный выбор сохраняется.
  - Объём явного пересоздания → конкретные тезисы, событие или обзор.
- Прозрачность → текущий выбор в настройках, происхождение в сведениях готового результата.
- Заключительный раунд → согласовано: общее понимание, ошибки каталога/совместимости и переход старой незавершённой работы. Открытых продуктовых решений нет.

## Правила интерфейса и ошибок

Подтверждены пользователем в заключительном раунде:

- Раздел «Настройки Око → Подключения моделей → Codex» содержит четыре строки действий. Каждая имеет выбор модели, поддерживаемого ею усилия рассуждения и Fast; сохранение явно фиксирует значения. Первый выбор для всех строк предлагается из default каталога, Fast выключен. До сохранения значения являются предложением, а не установленной конфигурацией.
- Каталог сообщает варианты и поддерживаемые параметры, но не гарантирует доступ к модели. Если каталог недоступен, показываются сохранённые значения и ошибка обновления списка; выбранная конфигурация не стирается. Для ещё не настроенной установки требуется успешно получить каталог и сохранить явный выбор перед новой обработкой Codex.
- Несовместимый выбор усилия/Fast не исправляется молча: показывается ошибка и предлагается исправить параметры. Обновление списка не переключает выбранную модель; ошибка доступа или запрет Fast при запуске не запускают другую модель/Standard автоматически. Fast имеет краткое пояснение об увеличенном расходе лимита.

## Архитектурные границы

См. [ADR](../../docs/adr/0001-codex-execution-settings.md). Это изменение прежнего определения актуальности, а не добавление ещё одного поля в общий fingerprint.

- Текущие параметры по типу действия, зафиксированные параметры начатой работы и происхождение готового результата являются разными состояниями. Модель, усилие и Fast не включаются в основания автоматического пересоздания уже принятого результата.
- Изменения исходного содержимого, промпта, обработчика и разрешений сохраняют существующее поведение актуальности. Поздний ответ после смены только параметров выполнения допускается с прежним происхождением; после удаления материала или изменения входа/разрешений действуют прежние проверки допуска.
- Новый обзор фиксирует параметры до первого этапа. При восстановлении нельзя смешивать прежние промежуточные результаты с новым выбором. Если параметры старой незавершённой работы неизвестны, их нельзя выдумать или приписать ей текущие: нужен видимый запрос пересоздания с текущими параметрами.
- Store сохраняет конфигурацию, параметры восстанавливаемой работы и происхождение результата. Runtime владеет выполнением и отменой. ProcessingCoordination различает изменения правил актуальности и выбора для будущей работы; алгоритмы фильтра, тезисов, событий и обзоров остаются самостоятельными.
- Адаптер Codex получает явные параметры конкретной работы и передаёт их изолированному запуску. Изоляция, одноразовые задания, проверки публичного AI и удаления сохраняются. Получение каталога не требует доступа к материалам и не заменяет проверку подключения.
- `model-settings.js` владеет черновиком; поздние ответы загрузки/сохранения не затирают новый ввод и не меняют закрытый контекст. При выборе llama.cpp существующая конфигурация этого обработчика сохраняется; новый выбор относится к Codex.
- Для новых результатов сохраняются точные запрошенные параметры; если протокол подтверждает фактически использованные значения, они записываются отдельно. Запрошенный ID модели не выдаётся за подтверждение внутренней версии модели провайдера. Неизвестные фактические значения остаются неизвестными.

## Критерии приёмки будущей реализации

1. Через HTTP читателя и браузер можно прочитать, выбрать, сохранить и после перезапуска получить независимые параметры четырёх действий.
2. Новая работа каждого типа передаёт свой явный выбор; все этапы одного обзора используют один снимок параметров.
3. Сохранение нового выбора не повышает поколения готовых результатов, не ставит массовые задания и не отменяет начатую работу только из-за модели/усилия/Fast.
4. Задержанный ответ сохраняет прежнее происхождение; новая работа использует новые параметры. Перезапуск обзора сохраняет выбор и принятые этапы.
5. Изменение исходника, промпта, разрешений или удаление во время запроса сохраняет проверки актуальности и запрет восстановления удалённого.
6. Явное пересоздание конкретного результата использует текущие параметры и не меняет отметку просмотра; обзор сохраняет установленный состав публикаций.
7. Старый готовый результат доступен с неизвестной моделью; ему не приписывается текущий выбор. Старый незавершённый обзор с неизвестными параметрами не продолжает генерацию молча.
8. Проверки ошибок каталога, недоступной модели, несовместимого усилия/Fast и задержанных ответов UI не допускают скрытого fallback, потери сохранённого выбора или нового черновика.

Проверять на временном хранилище, синтетических материалах и управляемом адаптере. Отдельная проверка сборки аргументов Codex подтверждает модель, усилие и явный режим Standard/Fast, сохраняя изоляцию. Подставной ответ не доказывает доступность модели, реальный Fast или качество обработки; реальные вызовы потребуют отдельного задания.

## Проверенные факты

Изучен текущий checkout, без запуска обработки личных материалов:

- `oko/processing/codex.py`: изолированный одноразовый `exec`, модель явно не передаётся.
- `oko/web/model-settings.js`: Codex имеет проверку подключения; поля подключения и модели сейчас предусмотрены для llama.cpp.
- `oko/reader/runtime.py`: общий адаптер обслуживает фильтрацию, тезисы, события и этапы обзора.
- Согласование актуальности принадлежит `oko/reviews/coordination.py`; изменение модели должно учитываться в подготовке и принятии работы.
- Подписи результатов различаются: нельзя рассчитывать, что изменение одного общего счётчика автоматически корректно охватит все действия и только нужные действия.

Официальная [справка CLI](https://learn.chatgpt.com/docs/cli/reference) описывает `exec --model` для явного выбора модели. [App Server](https://learn.chatgpt.com/docs/app-server) описывает каталог `model/list`; применимость получения каталога к существующей изоляции Око требует проверки при выборе решения. Список каталога сам по себе не доказывает успешный доступ к модели.

[Fast в Codex](https://learn.chatgpt.com/docs/agent-configuration/speed) задаётся через `service_tier` и feature `fast_mode`; доступность зависит от модели и аккаунта, включение увеличивает расход лимита. Это отдельный параметр от усилия рассуждения. Совместимость точных значений с установленной CLI и явное отключение Fast должны проверяться при реализации; подмена параметров API параметрами CLI недопустима.

Локальная справка `codex exec --help` подтверждает `--model`, `--config`, `--enable`/`--disable` и `--ignore-user-config`. Генерация не запускалась.
