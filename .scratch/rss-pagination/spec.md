# Пагинация истории RSS/Atom

Status: draft — проектирование, реализация не разрешена
GitHub: не опубликовано

## Цель

Око собирает выбранное количество последних публикаций RSS/Atom, переходя
по предоставленным источником ссылкам продолжения. Если собрать выбранное
количество не удалось, читатель видит фактический результат и причину.
200 — пример запроса, а не отдельный фиксированный лимит.

## Согласовано с пользователем

1. Следовать только ссылкам страниц и архивов из RSS/Atom. Разбор сайта
   и подбор параметров адреса для отдельных источников в объём не входят.
2. Показывать «Загружено M из N» вместе с причиной недобора. Различать:
   доступная история закончилась; источник не предоставляет продолжение;
   загрузка прервалась из-за ошибки. Решение о повторе уточнено пунктом 7.
3. Сейчас выполняется только проектирование. Изменение приложения,
   публикация задач и запуск реализации не входят в текущий этап.
4. Пагинация применяется при подключении нового RSS/Atom-фида и при явно
   запрошенной догрузке истории уже подключённого фида.
5. Граница выбора истории фиксируется на начало подбора. Публикации,
   появившиеся после этой границы, собираются независимо и не расходуют N.
   Изменяемые страницы и неоднозначные даты не дают основания обещать точный
   набор без предупреждения.
6. Для количества выбираются первые N уникальных публикаций по ходу обхода,
   найденное упорядочивается по датам. При неизвестных датах либо нарушении
   порядка показывается предупреждение: «Точность выбора последних N не
   подтверждена». Полный обход ради строгого выбора N не требуется.
7. Ошибка страницы завершает попытку подбора. Уже найденные публикации
   сохраняются; недобор получает явную причину. Автоматические повторы и
   возобновление обхода после ошибки страницы не входят в объём. Пользователь может
   явно запросить новый подбор; дедупликация и отметки просмотра сохраняются.
   Это решение заменяет рекомендацию об автоматическом повторе из вопроса 6.
8. Пагинация применяется также к начальному выбору истории начиная с даты.
   Неподтверждённая полнота периода отражается предупреждением.
9. Для выбора по дате обход заканчивается на первой публикации с известной
   датой старше нижней границы. Начало выбранного дня включается с учётом
   выбранного часового пояса. Публикации новее границы начала подбора
   собираются отдельно, а не прекращают обход. Запись без даты не доказывает
   выход за нижнюю границу: она включается с предупреждением.
10. Обход ограничен 1000 страницами за попытку. Повтор адреса прекращает
    обход как цикл; лимит и цикл показываются как самостоятельные причины,
    а не как конец истории источника. Пользовательской настройки не требуется.
11. Полные тексты выбранных публикаций скачиваются после завершения подбора,
    в том числе после его завершения с частичным результатом из-за ошибки.

## Существующие опоры реализации

- Глоссарий определяет догрузку как выбор последних N публикаций источника,
  а не получение N новых карточек. Известные публикации учитываются,
  просмотренные не возвращаются.
- Общий результат discovery уже передаёт курсор, продолжение и ошибку повтора;
  Store умеет атомарно сохранять публикации, состав истории и курсор страницы.
- Повторная догрузка и управление ею сейчас доступны только для YouTube;
  потребуется расширить существующий сценарий на RSS/Atom.
- HTTP-контракт прогресса уже различает подбор истории, загрузку содержимого,
  ошибки, предупреждения и фактическое количество доступных публикаций.
- Читатель уже показывает запрошенное и доступное количество при недоборе.
  Не хватает причины завершения обхода; текст завершения сейчас общий.
- Выключение работы сохраняет очередь и запрещает приём позднего результата.
  Включение допускает продолжение сохранённой работы согласно
  `docs/architecture/work-power.md`.

## Ограничения формулировок

Отсутствие ссылки продолжения не доказывает отсутствие более старых публикаций
у источника. Такой результат должен описывать доступность продолжения,
а не утверждать, что вся история источника исчерпана.

Для выбора по дате первая более старая публикация завершает подбор, даже если
на следующих страницах могли находиться подходящие публикации. Данный способ
явно согласован пользователем вместо полного обхода цепочки. Достижение границы
не доказывает полноту периода; предупреждение сохраняется.

## Предлагаемый технический проект — на итоговое согласование

### Обход страниц

- Поддержать ссылки Atom `link rel="next"` для пагинации и
  `link rel="prev-archive"` для движения к более старым архивам. В RSS читать
  расширение `atom:link` на уровне channel; ссылки внутри публикаций не являются
  продолжением источника. `previous`, `next-archive`, `first`, `last`, `self`
  не использовать для подбора более старой истории.
- Относительные адреса разрешать относительно итогового URL документа после
  перенаправлений с учётом `xml:base`. Сохранять существующие проверки адресов,
  XML, размеров, таймаутов и числа перенаправлений RSS-адаптера.
- Если документ предоставляет и `next`, и `prev-archive`, сначала обходить
  `next`, сохраняя архивную ссылку как отложенное продолжение. Одинаковые цели
  объединять; выбор между несколькими различными ссылками одного отношения
  считать неоднозначным продолжением и завершать с предупреждением.
- Один шаг discovery получает один документ. Между страницами управление
  возвращается Runtime; сеть не удерживает блокировку действий.
- Хранить идентификатор попытки, границу начала, очередь продолжений,
  запрошенные и итоговые URL, число страниц, выбранные ID и предупреждения.
  Дубликаты публикаций не расходуют N. Пустая страница с продолжением
  сама по себе не заканчивает обход.
- Для N прекращать обход сразу после выбора N уникальных подходящих публикаций.
  Для даты применять пункт 9 в порядке записей источника. Сортировка найденного
  нужна для представления и не меняет выбранный по ходу обхода состав.
- Проверять даты относительно начала попытки. Даты не позволяют определить
  момент появления записи без даты или задним числом: такие случаи сохраняют
  предупреждение о неподтверждённой границе, а не обещание точного снимка.
- Обычное обновление новых публикаций читает текущее окно источника. Оно не
  начинает новый обход архивов и не перезапускает закончившийся подбор.
  Новые публикации после границы попадают в обычный сбор независимо от N.

### Выполнение и хранение

RSS-адаптер отвечает за разбор продолжений, отбор и подготовку результата одной
страницы. Runtime владеет допуском, выполнением и отменой. Store атомарно
принимает публикации, состав истории и курсор; поздний результат отменённой
или заменённой попытки не принимается. Отдельный worker или framework не нужен.

Использовать существующий механизм постепенного включения публикаций в историю
(`history_enroll`) и отметку окончания подбора. Сохранённые ID после страницы
не означают, что полные тексты уже загружены. Пока подбор не закончен,
не запускать загрузку содержимого его участников для обоих режимов выбора.
Существующие готовые материалы остаются доступны для чтения.

Ошибка страницы завершает именно подбор с частичным составом и причиной ошибки;
продолжение для этой попытки больше не планируется. Найденные участники
допускаются к обычной загрузке содержимого. Ошибки отдельных статей остаются
в существующем механизме загрузки материалов и не меняют результат обхода.

Штатное выключение работы и перезапуск не приравнивать к ошибке страницы:
применять существующие правила сохранённой очереди и допуска после Start,
без добавления отдельного механизма восстановления RSS. Явная отмена истории
закрывает попытку; поздние ответы не расширяют её состав. Уже сохранённые
материалы не удаляются. Новый подбор требует нового действия пользователя.

Расширить существующее действие управления историей на RSS/Atom и выбор по дате
в согласованном объёме. Название внутреннего YouTube-специфичного метода
обобщить по месту; общие правила Telegram/YouTube не менять.

### Результат и представление

Сохранить существующие количества: найдено (`available`), загружено (`loaded`),
просмотрено, неполно, недоступно и ошибки статей. Они описывают разные результаты:
200 найденных не означают 200 полных текстов или 200 новых карточек.

Добавить в результат истории закрытую причину окончания подбора (`stop_reason`);
для старых историй причина неизвестна и не восстанавливается догадкой.
Промежуточное состояние не имеет причины завершения. Предлагаемые значения:

| Причина | Значение для читателя |
| --- | --- |
| `count_reached` | Выбрано запрошенное N |
| `date_boundary` | Встречена публикация старше выбранной даты |
| `no_continuation` | Источник не предоставил продолжение |
| `archive_end` | Доступная цепочка архивов пройдена |
| `request_failed` | Не удалось получить или разобрать страницу |
| `cycle` | Продолжение ведёт к уже запрошенной странице |
| `page_limit` | Достигнут лимит 1000 страниц |
| `ambiguous_continuation` | Источник предоставил неоднозначное продолжение |
| `cancelled` | Подбор остановлен пользователем |

`archive_end` использовать только для явно объявленной архивной цепочки;
даже он не означает доказанную полноту всей истории сайта. Известные повторные
ссылки, отложенные из другой страницы и уже успешно обработанные, объединять;
причина `cycle` относится к возврату по текущей цепочке, а не к общей цели
разных ветвей. При перенаправлениях учитывать также итоговые URL.

UI разделяет «подбор закончился» и «тексты загружены». Для ошибки подбора,
цикла, лимита и неоднозначного продолжения не показывать безусловное
«История полностью загружена». Примеры:

- «Найдено 20 из 200. Источник не предоставляет продолжение».
- «Найдено 120 из 200. Не удалось загрузить следующую страницу».
- «Найдено 200 из 200. Загружено 175; 25 ожидают загрузки».
- «Подбор до выбранной даты завершён. Полнота периода не подтверждена».

Причина окончания подбора сохраняется и после загрузки текстов. Клиент владеет
текстами; сервер передаёт код. Ошибку первой страницы также завершать явно,
с нулевым результатом. Точные HTTP DTO и примеры обновляются через
`api/openapi.yaml` с генерацией по `api/README.md`, а не ручной правкой SDK.

### Критерии приёмки

Проверки реализации проводить через существующий HTTP читателя с временными
SQLite/файлами и синтетическими источниками. UI проверять Playwright и просмотром
его скриншотов. Обязательные сценарии:

1. 200 публикаций в одном документе; 200 на нескольких страницах RSS и Atom;
   цепочка `prev-archive`; совместные продолжения без потери отложенного архива.
2. Подключение нового фида и новый подбор уже подключённого; известные ID
   учитываются, дубликаты не расходуют N, просмотренные не возвращаются.
3. 20 из 200 без продолжения; конец архивной цепочки; ошибка первой страницы
   и ошибка после нескольких успешных страниц. Найденное сохраняется,
   автоматического повторного запроса упавшей страницы нет.
4. Нижняя дата включительна; первая более старая запись заканчивает подбор;
   последующие записи не выбираются. Неизвестные даты и неоднозначный порядок
   дают предупреждение, включая неполноту периода при остановке по дате.
5. Новые поступления после начала не расходуют N; записи без достоверной даты
   не создают обещания точного снимка; изменившаяся страница не создаёт дубликаты.
6. Относительные ссылки, `xml:base`, перенаправления, цикл, пустая страница
   с продолжением, неоднозначное продолжение и предел 1000 страниц.
7. Загрузка статей начинается после подбора, включая частичный итог;
   отдельная ошибка статьи не переписывает причину завершения обхода.
8. Выключение, Start и перезапуск сохраняют общие правила работы; отмена,
   новый подбор и удаление фида защищены от поздних ответов старой попытки.
9. Браузер показывает выбор количества/даты и управление историей RSS,
   реальные счётчики, причины недобора и предупреждения; собранный частичный
   результат доступен для чтения. Старые истории читаются без выдуманной причины.

## Проверка и фактические свидетельства

План проверок будет определён после согласования поведения. Предыдущая
проверка текущей реализации через HTTP с временным хранилищем показала:
200 публикаций из одного документа сохраняются; при 20 публикациях и ссылке
на следующую страницу сохраняются только 20, без запроса продолжения,
а история отмечается завершённой без предупреждения о недоборе.
Это свидетельство исходного поведения, не проверка будущей реализации.
