# Ускорение полного прогона

База: f213a76. Задание: существенно ускорить тесты, в том числе перераспределить
проверки по пирамиде. Рабочая установка и production defaults не меняются.

- RSS: лимит 1000 запросов, redirect/ветвление и выбор 200 записей проверяются
  настоящим RSSSource с MockTransport. HTTP оставляет малый многостраничный обход,
  сохранение/возобновление у лимита, проекцию stop_reason/requests и loaded.
- Performance browser: сохраняются 4 библиотеки, 40 первых + 40 повторных открытий,
  настоящий click, DOM observer, p95 <200ms и активная обработка. Убрать ожидание
  100ms между выборками: ждать сигнал observer через requestAnimationFrame. Часы браузера в benchmark не подменяются.
- Проверить четыре Python workers в полном прогоне. Сохранить каждый выбранный
  файл ровно один раз, независимые данные, ошибки, отмену, checkout guard и отчёты.
- Сравнить одинаковый полный `all tools` до/после и отдельно затронутые сценарии.
  Не вводить новые skips, не кэшировать исходы тестов и не менять продукт ради тестов.

- Чистые SDK/fetch контракты проверяются в Node с настоящими Request/Response:
  binary bytes/headers, авторизация, keepalive, JSON и матрица ошибок без retry.
  Browser сохраняет pagehide/pageshow и отображение malformed response/diagnostics.

- После замера bounded browser=8 оставлен автоматический выбор для >=12 logical
  CPU; на остальных/неизвестных остаётся 4. Существующий флаг допускает 2/4/8.
  Обязательные performance cases по-прежнему идут отдельной командой.
