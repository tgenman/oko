# 05: Синхронизация прочитанного Telegram

**What to build:** Настроить автопрочитывание либо подтверждение после просмотра, читать не по порядку и видеть отложенную синхронизацию, переживающую удаление и перезапуск.

## Критерии приёмки

- [ ] При автопрочитывании сообщение допустимо подтвердить только после полного сохранения, без удаления из Око. При выключенном режиме допустимость возникает от явного локального просмотра.
- [ ] Накопительное подтверждение продвигает только безопасную границу истории: более раннее неподтверждённое сообщение задерживает позднее. Пропуски числовых ID не считаются сами по себе пропусками истории.
- [ ] При просмотре позднего сообщения его контент удаляется немедленно, а UI объясняет ожидание ранних сообщений. Очередь подтверждений хранит только служебные данные.
- [ ] Отдельное разрешение очистки истории до начала импорта изначально выключено. При отказе старая непрочитанная история может задерживать синхронизацию; при включении применяется только согласованная граница.
- [ ] Внешняя отметка Telegram не удаляет локальный контент. Непроверенные topic-операции не заменяются подтверждением всего диалога.
- [ ] После сбоя между удалением и подтверждением очередь восстанавливается без текста; неизвестный результат допускает повтор того же безопасного подтверждения.
- [ ] Контракт работает с набором ID независимо от вида карточки, чтобы будущие сводки использовали тот же путь. Проверены накопительный порядок, ошибки и перезапуск; реальные отметки проверяются только на явно выделенном проверочном наборе.

## Общие условия выполнения

Реализовать законченный путь через хранение, API, UI и проверки поведения. Основные тесты — через API с настоящими временными SQLite/файлами и подменами внешних систем; браузер проверяет действия читателя. Восстановление, отмена и удаление проверяются для всех добавленных типов содержимого. Использовать глоссарий и раскладку A; не возвращать исключённые функции или смысловой архив. Реальные подключения проверять отдельно на ограниченном наборе; не выдавать подмены за проверку аккаунта. Более поздние адаптеры используют общий контракт без необходимости завершать все независимые ветви заранее.
