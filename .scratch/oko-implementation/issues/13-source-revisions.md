# 13: Правки и удаления в источниках

**What to build:** При обнаруженных изменениях источника показывать новую и предыдущую версии, обновлять зависимые тезисы и сводки, сохраняя удалённый источником материал до локального просмотра.

## Критерии приёмки

- [ ] Адаптеры RSS, Telegram и YouTube объявляют фактические возможности обнаружения изменений; ограничения видны, универсальное обнаружение не обещается.
- [ ] Обнаруженная правка создаёт актуальную версию с отметкой «Изменено», предыдущая раскрывается; повтор той же версии не порождает лишних копий.
- [ ] Затронутые тезисы, карточки событий и обзоры инвалидируются и обновляются по актуальным версиям с соблюдением разрешений; старый ответ модели не затирает новый.
- [ ] Обнаруженное удаление источником не удаляет непросмотренную локальную копию. Повтор/правка просмотренного ID не загружает его заново.
- [ ] Локальный просмотр удаляет все версии, вложения и производные представления; другие непросмотренные исходники пересекающихся сводок сохраняются.
- [ ] Сбой во время записи версии и генерации обновления восстанавливается без ложной полноты и возвращения просмотренного контента.
- [ ] Проверены API-сценарии с управляемыми изменениями и браузерное раскрытие предыдущей версии; реальные возможности каждого источника зафиксированы отдельно от имитации событий.

## Общие условия выполнения

Реализовать законченный путь через хранение, API, UI и проверки поведения. Основные тесты — через API с настоящими временными SQLite/файлами и подменами внешних систем; браузер проверяет действия читателя. Восстановление, отмена и удаление проверяются для всех добавленных типов содержимого. Использовать глоссарий и раскладку A; не возвращать исключённые функции или смысловой архив. Реальные подключения проверять отдельно на ограниченном наборе; не выдавать подмены за проверку аккаунта. Более поздние адаптеры используют общий контракт без необходимости завершать все независимые ветви заранее.
