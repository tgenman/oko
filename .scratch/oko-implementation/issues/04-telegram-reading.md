# 04: Чтение Telegram с медиа

**What to build:** Подключить существующий Telegram-клиент и читать публичные и приватные источники с локальными медиа, восстановлением и повтором неполной загрузки. Серверные отметки чтения добавляются следующим тикетом.

**Blocked by:** [02: Подписки и настройки папок](02-subscriptions-settings.md)

**Status:** integration-pending

**Label:** ready-for-agent

**Основание:** [Спецификация первой версии](../../oko-product/spec.md), [Глоссарий](../../../GLOSSARY.md), [Макет A и его ограничения](../../oko-product/prototype/README.md).

**Покрытие спецификации:** A02 A03 A04 A24 A26 A27 A28 A32. Критерии применяются к поведению, введённому этой задачей; общие гарантии расширяются следующими задачами.

## Критерии приёмки

- [x] Используется существующий авторизованный Python-клиент через проверенные операции библиотеки/MCP; секреты и сессии не копируются в новое хранилище и не попадают в тесты или вывод.
- [x] Публичный канал, приватный канал и обычная группа подключаются через UI; отсутствие доступа показано явно. Неподдерживаемая семантика forum topics обозначена ограничением.
- [x] Текст, изображения, видео и кружочки сохраняются заранее и доступны внутри Око. Все части альбома учитываются при определении полноты.
- [x] Частичный материал доступен с состоянием загрузки и повтором. Полнота наступает только после сохранения всех обязательных вложений.
- [x] Страницы, курсоры и задания сохраняются до продвижения сбора; повтор и остановка не дают дублей. Возврат после перерыва догоняет сохранённую позицию либо показывает пробел.
- [x] На этом этапе адаптер не отправляет read acknowledgements. Позиция получения, полнота, просмотр и будущая граница подтверждения независимы; UI не изображает рабочую синхронизацию.
- [x] Просмотр удаляет все загруженные части и временные файлы; позднее завершение загрузки не воскрешает материал. Ошибка одного фида не скрывает результаты остальных.
- [ ] Проверены обрыв вложения, перезапуск и удаление через API; ограниченная проверка существующего подключения документирует реально доступные операции без массового импорта аккаунта.

## Общие условия выполнения

Реализовать законченный путь через хранение, API, UI и проверки поведения. Основные тесты — через API с настоящими временными SQLite/файлами и подменами внешних систем; браузер проверяет действия читателя. Восстановление, отмена и удаление проверяются для всех добавленных типов содержимого. Использовать глоссарий и раскладку A; не возвращать исключённые функции или смысловой архив. Реальные подключения проверять отдельно на ограниченном наборе; не выдавать подмены за проверку аккаунта. Более поздние адаптеры используют общий контракт без необходимости завершать все независимые ветви заранее.

Совместимая блокировка сохраняет запрет второго подключения занятой сессии.

Подключение через существующий runtime/venv, каналы и обычные группы, локальные вложения/альбомы, продолжение истории, повтор и удаление реализованы. Отметки прочитанного не отправляются. После независимого ревью исправлена идентичность и обновление состава альбомов. 48 тестов проходят, mypy и синтаксис JS чистые. Браузер проверил форму подключения и синтетические локальные медиа.

Статус `integration-pending` означает незавершённую приёмку на реальном аккаунте: оба существующих аккаунта защищены занятой SessionLock. Отказ проверен, чужие процессы не остановлены. Реальное чтение публичного/приватного канала, группы и скачивание медиа остаются непроверенными; последний критерий не объявлен закрытым. Код и локальные проверки завершены. После освобождения одной существующей сессии выполнить ограниченную интеграционную проверку и только затем отметить done.
