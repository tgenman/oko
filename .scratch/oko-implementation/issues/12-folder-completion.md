# 12: Завершение разбора папки

**What to build:** Завершить разбор выбранной папки одним подтверждением с предварительным количеством, удалив скрытое и сводки без затрагивания других папок и новых неподтверждённых поступлений.

**Blocked by:** [11: Обзоры и сжатие истории](11-digests-compression.md)

**Status:** done

**Label:** done

**Основание:** [Спецификация первой версии](../../oko-product/spec.md), [Глоссарий](../../../GLOSSARY.md), [Макет A и его ограничения](../../oko-product/prototype/README.md).

**Покрытие спецификации:** A14 A16 A23 A25 A26 A28 A31. Критерии применяются к поведению, введённому этой задачей; общие гарантии расширяются следующими задачами.

## Критерии приёмки

- [x] «Всё просмотрено» показывает число карточек до подтверждения и фиксирует набор исходников всей папки, включая скрытое, сводки и карточки событий; не ограничивается видимым экраном.
- [x] При изменении набора до выполнения предварительный счётчик обновляется; новые неподтверждённые поступления не удаляются молча.
- [x] После подтверждения набор исчезает из UI и всех открытых вкладок, контент и производные копии удаляются; остальные папки не затронуты.
- [x] Пересекающиеся сводки разворачиваются в уникальный набор ID; повтор подтверждения безопасен. Не сохраняются смысловые отпечатки и архив прочитанного.
- [x] Отложенные Telegram-подтверждения живут независимо от удаления и используют общий контракт наборов; при наличии реального адаптера проверяется сквозной сценарий, без добавления искусственного блокера к работе UI.
- [x] Сбой в середине удаления восстанавливается до дальнейшего сбора; параллельные загрузки и AI-ответы не возвращают содержимое. Ошибка физического удаления видна, а не объявлена успехом.
- [x] Браузерный тест подтверждает предварительное количество и изоляцию папок; API/процессные тесты покрывают гонки, новые поступления и восстановление.

## Общие условия выполнения

Реализовать законченный путь через хранение, API, UI и проверки поведения. Основные тесты — через API с настоящими временными SQLite/файлами и подменами внешних систем; браузер проверяет действия читателя. Восстановление, отмена и удаление проверяются для всех добавленных типов содержимого. Использовать глоссарий и раскладку A; не возвращать исключённые функции или смысловой архив. Реальные подключения проверять отдельно на ограниченном наборе; не выдавать подмены за проверку аккаунта. Более поздние адаптеры используют общий контракт без необходимости завершать все независимые ветви заранее.

## Результат

2026-10-09. Реализация: `beebc23`; размещение кнопок: `87d8b68`; исправления изоляции вкладок: `0ae7374`, `e7e2dc5`. Завершение всей папки использует подтверждённый уникальный набор исходников и общий `viewed_set`; пересчёт требует повторного клика, физические ошибки видны, удаление восстанавливается после остановки процесса.

Приёмка: 10 API-тестов папки, 2 процессных сценария аварии, браузер с двумя вкладками, пересчётом и задержанным открытием материала другой папки. Полный набор: 161 passed; mypy: 18 файлов без ошибок. Standards и Spec: по 0 открытых замечаний после исправлений.

Telegram: общий контракт набора подготовлен; настоящие отметки прочитанного и их независимая очередь относятся к задаче 05 и здесь не реализованы. Проверка аккаунта остаётся отдельной границей задачи 04; пользовательская сессия не запускалась. Эта граница не блокирует завершение папки в UI.
