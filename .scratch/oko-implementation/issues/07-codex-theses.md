**What to build:** Выбрать Codex для публикации с явно разрешённым публичным AI, получить тезисы и удалить их; запрет передачи и изоляция соблюдаются во всём цикле.

**Blocked by:** [06: Тезисы через локальную модель](06-ollama-theses.md)

**Status:** in-progress

**Label:** ready-for-agent

**Основание:** [Спецификация первой версии](../../oko-product/spec.md), [Глоссарий](../../../GLOSSARY.md), [Макет A и его ограничения](../../oko-product/prototype/README.md).

**Покрытие спецификации:** A18 A19 A20 A26 A28 A30. Критерии применяются к поведению, введённому этой задачей; общие гарантии расширяются следующими задачами.

## Критерии приёмки

- [ ] Codex подключён к общему контракту обработки и наследованию настроек. Проверяются текущий доступ и пригодность запуска; отдельный платный API не становится обязательным.
- [ ] Перед запуском требуется разрешение публичного AI всех входных фидов. Производные тексты сохраняют те же ограничения; запрещённые данные не попадают во вход или доступные инструменты.
- [ ] Изоляция проверена технически: обработчик не имеет доступа ко всему хранилищу, Telegram-инструментам или посторонним источникам. Промпт и read-only сами по себе не считаются доказательством.
- [ ] Одноразовое задание возвращает валидируемые тезисы; контент не сохраняется в rollout, логах или неконтролируемых временных копиях. Если это обеспечить нельзя, подключение остаётся недоступным с конкретной причиной.
- [ ] Исчерпание лимита, авторизация, ошибка и отмена видны в UI; автоматического обхода разрешений и fallback нет.
- [ ] Остановка завершает только дочерние задания Око. Поздний ответ после просмотра/смены разрешений не публикуется; локальная отмена не обещает удаление данных у провайдера.
- [ ] Проверены отсутствие облачного вызова для запрещённого входа, косвенный доступ, очистка копий и ограниченная реальная обработка разрешённого примера; результат проверки аккаунта отделён от подмен в тестах.

## Общие условия выполнения

Реализовать законченный путь через хранение, API, UI и проверки поведения. Основные тесты — через API с настоящими временными SQLite/файлами и подменами внешних систем; браузер проверяет действия читателя. Восстановление, отмена и удаление проверяются для всех добавленных типов содержимого. Использовать глоссарий и раскладку A; не возвращать исключённые функции или смысловой архив. Реальные подключения проверять отдельно на ограниченном наборе; не выдавать подмены за проверку аккаунта. Более поздние адаптеры используют общий контракт без необходимости завершать все независимые ветви заранее.
