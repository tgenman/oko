# 02: Подписки и настройки папок

**What to build:** Импортировать OPML с папками, разрешить конфликты одинаковых источников и настроить представление фидов, важность, периоды и наследование параметров через UI.

**Blocked by:** [01: Первый путь читателя](01-first-reader-path.md)

**Status:** ready-for-agent

**Label:** ready-for-agent

**Основание:** [Спецификация первой версии](../../oko-product/spec.md), [Глоссарий](../../../GLOSSARY.md), [Макет A и его ограничения](../../oko-product/prototype/README.md).

**Покрытие спецификации:** A01 A02 A11 A17 A22. Критерии применяются к поведению, введённому этой задачей; общие гарантии расширяются следующими задачами.

## Критерии приёмки

- [ ] OPML импортируется с папками; повторный импорт не удваивает сопоставленные источники. Для одного источника в нескольких папках требуется выбор одной папки; конфликт не решается молча.
- [ ] Распознаваемые Telegram-адреса RSSHub сопоставляются с Telegram-фидами с сохранением исходного адреса. Неоднозначные подключения имеют явный статус; два сборщика одного источника не запускаются.
- [ ] Первоначальный период — сутки с изменением для фида; непрочитанный список News Explorer не переносится.
- [ ] Настройки режимов, промптов, расписания и обработчика наследуются Око → папка → фид. UI показывает эффективное значение и его источник; сброс отдельного поля возвращает наследование.
- [ ] Важность фида — Обычная / Повышенная / Высокая, не наследуется; числовые префиксы папок не задают важность. Работают обе временные сортировки и «Сначала важное», по умолчанию новые сверху.
- [ ] «Разрешить обработку публичным AI» и очистка истории до импорта выключены для нового фида. Режим автопрочитывания требует выбора; сохранение настроек само по себе не отправляет отметки Telegram.
- [ ] Конфигурация сохраняется после перезапуска. Все поля доступны потребителям через единый контракт эффективных настроек; реальные AI-вызовы и расписания обзоров добавляются последующими задачами.
- [ ] На импортном fixture проверены дубли, конфликт папок, повторный импорт, наследование и сортировки через API и UI; личные данные не встраиваются в тесты.

## Общие условия выполнения

Реализовать законченный путь через хранение, API, UI и проверки поведения. Основные тесты — через API с настоящими временными SQLite/файлами и подменами внешних систем; браузер проверяет действия читателя. Восстановление, отмена и удаление проверяются для всех добавленных типов содержимого. Использовать глоссарий и раскладку A; не возвращать исключённые функции или смысловой архив. Реальные подключения проверять отдельно на ограниченном наборе; не выдавать подмены за проверку аккаунта. Более поздние адаптеры используют общий контракт без необходимости завершать все независимые ветви заранее.
