# История YouTube: последние N без Shorts

Status: done
Assignee: primary agent

Реализация разрешена пользователем после проектирования, затем явно вызван implement-spec. Исходные решения: [design.md](design.md). Проверка изменений сравнивает их с состоянием checkout перед реализацией: `/tmp/oko-history-baseline`, HEAD `5d2740635c1bbd41b9acfa8a1ce595f1a439c2db`. Остальные локальные изменения не относятся к этой задаче.

## Поведение

1. При новом подключении YouTube в режиме количества история выбирается через yt-dlp. Старые фиды автоматически не начинают догрузку после обновления Око.
2. В настройках подключённого YouTube-фида есть количество и действие «Загрузить последние N видео». N — последние публикации источника, не N дополнительных карточек. Уже известные ID учитываются; просмотренные не возвращаются; уменьшение N не удаляет материалы.
3. История включает обычные видео и записи трансляций, исключает Shorts. Тип определяется списками YouTube, а не длительностью видео. Общий порядок берётся из Uploads; даты для объединения не выдумываются.
4. После выбора список, метаданные и порядок сохранены. Загрузка каждого материала не перечитывает списки yt-dlp или RSS. Последующие обновления идут через два RSS обычных видео/трансляций внутри одного фида Око.
5. Экономное перечисление получает ID, название и ссылки. Превью сохраняются отдельно. Дата/описание берутся из RSS, если доступны; ради недостающих полей отдельные страницы роликов не запрашиваются.
6. Материалы без даты находятся в существующей группе «Дата неизвестна». Внутри фида сохраняется порядок источника, обратный для «Старые сверху». Дата загрузки не заменяет дату публикации.
7. Текущий сборщик субтитров и условия его запуска сохраняются. Успешно сохранённые субтитры никогда не перезапрашиваются. Видео и аудио не скачиваются, API key и cookies пользователя не нужны.
8. Подбор выполняется ограниченными порциями. При ошибке или исчерпании порции результат сохранён, требуется ручное продолжение. RSS работает независимо. Подтверждённый конец источника с X меньше N показывается отдельно от ошибки и паузы.
9. Пауза и причина ожидания переживают перезапуск. Активная работа продолжается только при открытой вкладке. На фид действует одна операция истории. Для изменения N нужно закончить/остановить текущую операцию; остановка сохраняет материалы.
10. Простой вариант восстановления выбран исполнителем в рамках делегированного технического решения: новый worker может один раз перечитать прежний префикс для восстановления позиции. Его конечный бюджет учитывается отдельно от новых страниц, исключая вечное застревание. Законченный подбор для загрузки материалов не перечитывается. Долговременный кеш ответов не добавляется.
11. Уже сохранённые Shorts не удаляются автоматически. Режим истории по дате сохраняется в пределах RSS с предупреждением о глубине.
12. Распознанные будущие/текущие эфиры исключаются по имеющимся данным. Неизвестный статус не вызывает отдельного запроса ролика. До распознавания анонс может временно попасть в список; прежний пропуск распознанного анонса сборщиком субтитров сохраняется.
13. Ошибка одной RSS-ленты не уничтожает успех другой и не включает смешанный фид с Shorts. Детали ошибок доступны в диагностике.

## Проверки

- HTTP читателя, временная SQLite/файлы, синтетические внешние ответы: 60 материалов, отсутствие запросов списков на каждый материал, перезапуск, сохранённые субтитры, известные/просмотренные ID, смена N, пауза, остановка, ручное продолжение после ошибки, независимые новые RSS-поступления.
- Реальный yt-dlp с синтетическим HTTP: обычные видео и трансляции в общем порядке, исключённые Shorts, частичный ответ/бюджет, продолжение, неподдерживаемый ответ, отсутствие запросов видео/субтитров/медиа при перечислении.
- Настоящий браузер через HTTP: ввод N, запуск, ожидание, продолжение, остановка, блокировка второй операции, поздний ответ при смене фида.
- Обязательные проверки UI (включая выдачу JS через HTTP), серверные проверки, mypy и независимые Standards/Spec review. Фактические результаты записываются отдельно.
