# 02. Контракты, transport и сессия читателя

Status: ready-for-agent
Blocked by: 01

Спецификация: [spec.md](../spec.md). Реализация пока не разрешена.

## Результат

Новые React-участки получают типизированные данные, ошибки и операции, а вкладка имеет одного владельца heartbeat, polling и межвкладочных сообщений.

## Объём

- Получать TS-типы для пяти существующих wire responses из серверных JSON Schema закреплённым генератором. Проверить optional/null/discriminators и drift без изменения source checkout.
- Перенести transport, описание ошибок и ui-operations на strict TS. Сохранить диагностические/action headers, confirmed/expected error, media, signal, keepalive и авторизацию только своего origin.
- Выделить владельца сессии из app.js: tab ID, heartbeat, refresh admission, BroadcastChannel, pagehide/pageshow и прекращение работы. Не менять интервалы/политику повторов и семантику остановки.
- Старые callers подключить к единственному implementation временным узким адаптером. Каталог непокрытых контрактами форм/команд распределить между последующими этапами.

## Приёмка

- [ ] Смена области, просмотр и остановка отбрасывают старые ответы; независимые операции не отменяют друг друга.
- [ ] Реальная HTTP-ошибка, ошибка сети и не-JSON ответ сохраняют прежнее различение; токен не уходит на чужой origin.
- [ ] Повторный setup/cleanup не создаёт второй цикл polling/heartbeat и не отправляет stop/close из-за React-размонтирования.
- [ ] Протокол последней вкладки, keepalive, межвкладочный просмотр и восстановление страницы сохранены; transport не повторяет мутации автоматически.
- [ ] Генерируемые типы совпадают с серверным контрактом; отсутствие типа остальных endpoints не спрятано в any/assertions.

## Проверка

`test_transport.cjs`, `test_contracts.cjs`, `test_reader_http.cjs`, затронутые проверки Runtime/вкладок через HTTP. На интеграции первого React-участка повторно проверить подписки в StrictMode. Моки не подменяют владельца актуальности.
