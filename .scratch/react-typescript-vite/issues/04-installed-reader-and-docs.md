# 04: Готовая поставка Око и встроенный Swagger

**What to build:** Установленное приложение работает без checkout и Node, а пользователь читает контракт и вручную проверяет API через встроенный Swagger.

Blocked by: 03 — Первый React-сценарий через сгенерированные библиотеки.

Status: done
Assignee: contract

Parent: [Спецификация](../spec.md). Подготовка тикета не разрешает реализацию.

- [x] Python-поставка содержит build, generated backend-библиотеку и документацию одной ревизии; неправильное сочетание ревизий блокирует подготовку поставки.
- [x] Установленный пакет запускается из другого рабочего каталога без исходников и Node; проверены ошибки свежести source checkout.
- [x] Встроенный Swagger показывает canonical bundle с локальными assets под текущим CSP, без token в документе и без постоянного хранения авторизации.
- [x] Try требует явной авторизации и команды пользователя; docs не создают reader lease, standalone-просмотр из первого тикета остаётся доступен после остановки Око.
- [x] Smoke установленного пакета и настоящий браузер проверяют UI, контракт и авторизованный запрос на синтетических данных; остальные продуктовые функции не меняются.

- [x] Для затронутого сценария сохранены существующие API/security, оформление и поведение; реальные HTTP/browser-проверки выполнены на временных данных и синтетических adapters. Фактический результат записан отдельно.

## Comments

2026-10-14: поставка строится во временном source tree из проверенных generated библиотек и одной frontend generation. Встроенные Swagger HTML/initializer/assets входят в тот же manifest с contract digest и hashes. Документация зарегистрирована до static fallback, bearer применяется только после Authorize и Execute, token не вставляется в документ/не сохраняется, lease не создаётся.
