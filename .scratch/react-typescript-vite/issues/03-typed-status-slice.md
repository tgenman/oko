# 03: Первый React-сценарий через сгенерированные библиотеки

**What to build:** Индикатор состояния Око в интерфейсе получает настоящий ответ через цепочку OpenAPI → Python-модель → HTTP → TypeScript SDK → React.

Blocked by: 01 — Полный контракт API и самостоятельный Swagger; 02 — Существующий читатель через сборку Vite.

Status: ready-for-agent

Parent: [Спецификация](../spec.md). Подготовка тикета не разрешает реализацию.

- [ ] Из полного OpenAPI воспроизводимо генерируются обе локальные библиотеки; required/optional/null, PATCH, unions и ошибки проверены до подключения остальных операций.
- [ ] Операция чтения состояния использует generated DTO на бэкенде и SDK на фронтенде; настоящий HTTP-ответ проходит контрактную проверку.
- [ ] В React перенесён существующий индикатор состояния/числа проблем; старый renderer перестал менять только этот контейнер, остальная панель работает как прежде.
- [ ] Сохранены ожидание, отсутствие связи, подтверждённая остановка и известное число проблем; token, headers и ошибки проходят через настроенный fetch client.
- [ ] Stale generated output и несовместимый schema dialect дают ошибку сборки; библиотеки содержат одну ревизию контракта, проверки не перезаписывают сохранённый output.
- [ ] Остальные потребители временно работают через прежние interfaces; это расширение перед последовательным подключением generated-моделей, а не второй независимый контракт.

- [ ] Для затронутого сценария сохранены существующие API/security, оформление и поведение; реальные HTTP/browser-проверки выполнены на временных данных и синтетических adapters. Фактический результат записан отдельно.
