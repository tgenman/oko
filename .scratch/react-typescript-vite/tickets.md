# Предложение разбивки на тикеты

Status: done

Реализация всей спецификации разрешена пользователем через implement-spec 2026-10-14. Предыдущие десять тикетов сохранены в previous-issues-20261014; текущие двадцать задач находятся в issues/. База реализации: 5b7a7e823480fc6fc9836ab8f994e586cf3dfded.

Задачи 01 и 02 независимо подготавливают контракт с просмотром и доставку прежнего UI. Задача 03 замыкает первый полный путь через generated-модели, HTTP, SDK и React. Далее каждый сценарий подключает свои операции и удаляет заменённый renderer. Существующие interfaces сохраняют возможность проверять ветки независимо. Общая модель данных полностью описана до React-переноса; подключение generated DTO к обработчикам выполняется по законченным сценариям. Все промежуточные результаты должны проходить затронутые проверки.

1. **Полный контракт API и самостоятельный Swagger**. Блокируют: нет. Разработчик читает полный действующий контракт Око в локальном Swagger, даже когда читатель остановлен. [Полный тикет](issues/01-contract-viewer.md).

2. **Существующий читатель через сборку Vite**. Блокируют: нет. Пользователь запускает прежний интерфейс обычным способом, а разработчик собирает и проверяет его через Vite. [Полный тикет](issues/02-build-existing-reader.md).

3. **Первый React-сценарий через сгенерированные библиотеки**. Блокируют: 01, 02. Индикатор состояния Око в интерфейсе получает настоящий ответ через цепочку OpenAPI → Python-модель → HTTP → TypeScript SDK → React. [Полный тикет](issues/03-typed-status-slice.md).

4. **Готовая поставка Око и встроенный Swagger**. Блокируют: 03. Установленное приложение работает без checkout и Node, а пользователь читает контракт и вручную проверяет API через встроенный Swagger. [Полный тикет](issues/04-installed-reader-and-docs.md).

5. **Сессия вкладки, сбор и остановка**. Блокируют: 03. Пользователь запускает сбор, останавливает Око и работает с несколькими вкладками с прежней семантикой через typed API. [Полный тикет](issues/05-reader-session-and-stop.md).

6. **Панель состояния и действия восстановления**. Блокируют: 05. Пользователь читает текущие проблемы и завершённые действия в React-панели и переходит к нужному действию восстановления. [Полный тикет](issues/06-status-panel.md).

7. **Диагностика и неизвестные исходы команд**. Блокируют: 06. Пользователь видит журнал и достоверные исходы команд, включая неотправленные ошибки и последующую сверку с сервером. [Полный тикет](issues/07-diagnostics-and-action-results.md).

8. **Меню, переходы и одно поле настроек**. Блокируют: 05. Пользователь открывает меню, меняет одно поле, уходит и возвращается без потери черновика и ошибочной навигации. [Полный тикет](issues/08-menus-and-one-setting.md).

9. **Все настройки и редактор фида**. Блокируют: 08. Пользователь редактирует настройки Око, папки и фида с прежним наследованием, параметрами и независимыми черновиками. [Полный тикет](issues/09-settings-and-feed-editor.md).

10. **Подключение RSS**. Блокируют: 08. Пользователь проверяет RSS-источник, выбирает папку и начальную историю, затем получает подключённый фид. [Полный тикет](issues/10-rss-connection.md).

11. **Подключение и переподключение Telegram**. Блокируют: 09. Пользователь подключает Telegram-фид или меняет его подключение, сохраняя аккаунт, тему форума, историю и автопрочитывание. [Полный тикет](issues/11-telegram-connection.md).

12. **Импорт OPML**. Блокируют: 08. Пользователь выбирает OPML, проверяет план и конфликты и получает импортированные фиды без потери текущего контекста. [Полный тикет](issues/12-opml-import.md).
