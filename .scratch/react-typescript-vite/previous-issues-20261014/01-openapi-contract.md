# 01. Канонический OpenAPI-контракт

Status: ready-for-agent
Blocked by: None

Спецификация: [spec.md](../spec.md), детали: [API-first](../api-contract.md). Реализация пока не разрешена.

## Результат

`api/openapi.yaml` регламентирует полный текущий HTTP interface читателя и становится источником дальнейших изменений API.

## Объём

- Составить inventory всех reader method/path по текущему app и HTTP-проверкам, включая команды, формы, диагностику, tab lifecycle и media.
- Описать OpenAPI 3.1: operation IDs, параметры, тела, DTO, required/optional/null, ответы/ошибки/headers, bearer security и синтетические примеры.
- Перенести смысл существующих wire types и request models без автоматического признания code-first экспорта истиной. Отдельно проверить PATCH, полиморфные карточки, error detail и бинарные responses.
- Зафиксировать совместимый schema dialect, локальные refs, bundled output и правила изменения версии/совместимости. Добавить воспроизводимую валидацию спеки.

## Приёмка

- [ ] Все реальные `/api/` method/path имеют уникальные operation IDs; исключены только явно перечисленные служебные маршруты.
- [ ] Документ отражает фактические успешные и ошибочные ответы; нет произвольных object/default responses вместо известных структур.
- [ ] Отсутствие PATCH-поля, null и значение сохраняют различие; media и OPML описаны по реальному HTTP.
- [ ] В YAML нет token, персональных примеров или сетевых refs. Правки API начинают с этого файла.
- [ ] Lint/bundle и выбранные настоящие HTTP-сценарии подтверждают baseline; найденные расхождения не скрыты ослаблением схемы.

## Проверка

Статическая валидация документа, сверка route inventory и текущие HTTP-тесты на синтетических данных. Неполноту текущей типизации не считать разрешением придумать контракт. Фактическую проверку записать отдельно.
