# 03. Сборка, доставка и Swagger UI

Status: ready-for-agent
Blocked by: 02

Спецификация: [spec.md](../spec.md). Реализация пока не разрешена.

## Результат

Существующий браузерный UI работает из Vite build до переноса компонентов. Обе сборки используют generated-библиотеки из OpenAPI; контракт доступен через Swagger UI и самостоятельный локальный просмотр.

## Объём

- Подобрать и закрепить совместимые React/React DOM, TypeScript, Vite/plugin-react и ESLint tools; сохранить один root package.json/lock и проверить Node engines.
- Создать frontend config, strict TS и production entry; переместить существующие файлы без копий в временную legacy-область. Сохранить CSS и исключить прототипы из выдачи.
- Добавить отдельные typecheck/build/watch команды. Реализовать свежесть сборки по влияющим входам и согласованную публикацию assets; не выполнять npm из пользовательского запуска.
- Включить в frontend/backend build валидацию и генерацию своей библиотеки, проверку drift и общего digest. Сохранённый generated output проверяется во временном каталоге; не обновлять его скрыто при сборке.
- Добавить `api:docs` без запуска Runtime и `/docs`/`/openapi.json` у работающего Око. Swagger получает canonical bundle, локальные assets и внешний initializer; static viewer только читает контракт, встроенный Try требует явного bearer и действия пользователя.
- Настроить выдачу dist в checkout и включение этих же assets в Python-пакет. Отсутствующая/устаревшая сборка диагностируется до начала Runtime; установленный пакет не ищет исходный checkout.
- Адаптировать runner, staged-проверки и CI к TS/TSX, hooks, сборке и asset tests. `types` сохраняет смысл Python/mypy, frontend-types выделен отдельно. Чистые Python-проверки не требуют frontend toolchain.

## Приёмка

- [ ] Существующие UI и HTTP-сценарии проходят на production build; визуальный baseline не изменился.
- [ ] API/mime/CSP/host/origin и защита traversal/symlink сохранены; неизвестные пути не превращаются в HTML.
- [ ] Нет Node-процесса/установки зависимостей при обычном запуске. Отсутствующая и устаревшая сборки имеют проверенные ошибки, актуальная работает из другого cwd.
- [ ] Python-дистрибутив с assets установлен во временное окружение и запущен без source checkout; сборка package не принимает устаревшие assets.
- [ ] Неверный TS-тип и неуспешный build дают ранний FAIL, выходные файлы не загрязняют checkout; manifest/browser проверяют фактическую выдачу вместо regex по исходным imports.
- [ ] Устаревшие SDK/DTO или разные contract digests блокируют сборку/упаковку; установленные пакеты используют generated output без генераторов при запуске.
- [ ] Swagger работает под текущим CSP без CDN/remote validator; документ совпадает с YAML/bundle, токен не сохраняется и не встроен в spec.
- [ ] Standalone docs читаются при остановленном Око; встроенные docs не создают reader lease и не меняют shutdown. Просмотр документации сам не выполняет API-команды.

## Проверка

Существующие `test_frontend_delivery.py`, `test_web_assets.py`, `test_security.py`, проверки runner и staged-границы; свежая сборка и браузерные сценарии по риску общей доставки. Swagger проверяется настоящим браузером с блокировкой внешней сети, bearer Try — на синтетическом backend. До/после — desktop/mobile снимки. Фактические команды, результаты и ограничения записать отдельно.
