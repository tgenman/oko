# 05. Панель состояния и диагностика в React

Status: ready-for-agent
Blocked by: 04

Спецификация: [spec.md](../spec.md). Реализация пока не разрешена.

## Результат

Первый React-контейнер работает на снимках status; затем панель и журнал полностью получают декларативное представление с прежними исходами действий и диагностикой.

## Объём

- Начать со списка/карточек проблем внутри стабильной оболочки. Явно определить контейнер React и запретить legacy-модулям менять его потомков.
- Сделать раскрытие деталей, текущую группу и порядок состоянием представления. При завершении проблемы раскрытая карточка остаётся на месте по прежним правилам.
- После проверки списка перенести оболочку панели, journal view и локальные исходы reader-actions. Внешние menu/open-material остаются callbacks; перемещение debug DOM и управление чужими диалогами заменить явным взаимодействием владельцев.
- Использовать generated SDK для диагностики/исходов действий, сохранить маскирование, очередь, дедупликацию, retry и удаление просмотренных объектов.
- Подключить ошибки React render к существующей диагностике с пригодным UI ошибки; async-действия обрабатываются отдельно. Ошибка доставки не зацикливается.

## Приёмка

- [ ] Polling не сбрасывает раскрытие и фокус, не меняет произвольно порядок; завершённая карточка перемещается только по прежним правилам.
- [ ] Переключение панели/журнала, mobile dialog, inert, Escape и возврат фокуса работают, включая открытие настроек поверх панели.
- [ ] Неизвестный результат команды не превращается в автоматический повтор; receipts и локальные исходы согласуются.
- [ ] Диагностические данные не теряются при закрытии панели; токены/секреты маскируются, рекурсивной отправки ошибок нет.
- [ ] Заменённые DOM renderers удалены; StrictMode не удваивает подписки и команды.

## Проверка

`test_status_panel.cjs`, `test_feed_debug.cjs`, затронутые HTTP-проверки status/debug и сценарии меню. Просмотреть desktop/mobile снимки панели и журнала. Использовать существующие синтетические данные и transport.
