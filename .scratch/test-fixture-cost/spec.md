# Ускорение подготовки тестовых сценариев

База: 6e4843e. Продолжение ускорения по запросу пользователя.
Рабочее Око и его настройки не меняются.

1. Один Chromium на команду node --test, независимое соединение каждого файла,
   новый context каждого сценария. Обычные браузерные файлы и performance по-прежнему
   выполняются отдельными командами. Прямой запуск файла работает без wrapper.
2. Владелец Chromium закрывает его после success, failure и interrupt; сигнал во
   время startup не оставляет процесс без владельца. PID-регрессии проверяют cleanup.
3. Fixture записанного альбома оставляет оригинальный HTML альбома/9 видео, но
   исключает 18 посторонних публикаций. HTTP-проверки состава/локального сохранения
   и отсутствия отдельных карточек для частей альбома сохраняются.
4. Сравнить полный all tools на одной базе и зафиксировать ограничения измерений.

Профиль HTTP: повторная регистрация FastAPI/Pydantic существенна, но оптимизация
отложена: тестовая подмена framework ослабила бы boundary, а перенос handlers
превратился бы в продуктовый рефакторинг. Проверки ответов не отключаются.

5. API YAML использует CSafeLoader при наличии, SafeLoader как fallback. Модели,
   digest и validation не меняются; нормализованный полный контракт сравнивается.
6. YouTube future-live fixture держит reader presence до подключения и не меняет
   importance после старта captions. Проверки настоящего worker, диагностик,
   tombstone и повторного запуска сохраняются.
7. Все 19 публикаций записанной Telegram-страницы проверяются parser без загрузок:
   отсутствие дубликатов частей остаётся отдельно от короткого HTTP-сценария.
