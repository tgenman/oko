# Telegraph: отдельный блок и ссылки ошибок

Пользователь выбрал вариант A UI-прототипа и поручил реализацию.

Primary source: локальная ветка `codex/telegraph-prototype-20261022`, коммит `58ab5f9a13ad942fb55c049674641510c53a3501`. Исходный прототип и скриншоты находятся в этой ветке.

## Требования

- Telegram-пост и загруженная по прямой ссылке статья Telegraph показаны отдельно: статья открытым блоком с подписью Telegraph, ссылкой на оригинал и обозначенным концом.
- При ошибке первоначальной загрузки статьи исходная ссылка остаётся в тексте поста с причиной ошибки рядом.
- При ошибке медиа внутри статьи его ссылка и причина остаются на месте ресурса; сохранённый текст читаем.
- Сохранённая полная копия и медиа не теряются при неудачном повторе. Предыдущие версии получают представление своей ревизии.
- Обычные ссылки внутри статей не обходятся. AI продолжает получать прежний объединённый текст; представление не меняет фильтрацию.
- Сокращённый фильтром текст и доступность медиа при свёрнутом полном исходнике сохраняются.

## Границы

Добавляется совместимое необязательное `linked_content` в существующие HTTP-представления: post_text и статьи (источник, заголовок, текст, ошибка, URL локальных медиа). Для старых материалов без манифеста — null и прежнее отображение. Адреса ресурсов записываются при новой загрузке и маскируются штатным redact; старые адреса, которых нет в манифесте, не восстанавливаются догадками или сетевыми запросами.

Политика повторов и критерий полноты в этой задаче не меняются. Обновление рабочего выпуска не запрошено.

## Проверка

Синтетические Telegram web/client + Telegraph API через настоящий HTTP interface и временное хранилище: успех, HTTP 403 изображения, HTTP 503 статьи, старая версия и сохранение полной копии. Playwright на production HTTP reader: отдельные блоки, inline-ссылки, причины, обновление страницы, узкий экран. Generated-контракт, типы и затронутые наборы.
