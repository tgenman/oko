# 05: Диагностировать ошибки источников, обработки и дочерних процессов

Status: done
Approval: разбиение, зависимости и проверки согласованы 2026-10-12
Execution: реализация разрешена пользователем 2026-10-12

**What to build:** Пользователь получает в общей панели исходные исключения проверки фида, сборщиков, обработки и фоновых задач, включая traceback дочернего процесса и принадлежность конкретному фиду.

**Blocked by:** 04: Показывать сгруппированные ошибки API в долговечной нижней панели

**Основание:** [Согласованная спецификация](../spec.md).

**Покрытие:** U03 (серверная ошибка в диагностике), D02 (серверные и дочерние процессы), D04, D06, D07.

## Acceptance criteria

- [x] Обработанные и неожиданные исключения внешних источников, AI-обработки, подготовки работы, удаления и фонового цикла фиксируются с понятным контекстом.
- [x] При использовании формы URL её серверная ошибка проверки также появляется в журнале.
- [x] Дочерние YouTube/Telegram-процессы передают исходный тип/сообщение и traceback; диагностические детали сохраняются при переводе в пользовательское сообщение.
- [x] Одинаковая ошибка двух фидов даёт разные группы; прохождение одного исключения через адаптер и Runtime считается одним возникновением.
- [x] Плановая отмена, штатное обнаружение удаления публикации и обычное отсутствие ещё не созданного результата не загрязняют журнал.
- [x] Повторы, сохранение материала, разрешения AI, остановка и очистка продолжают прежние сценарии; сбой диагностики не меняет их исход.
- [x] В исходных и переданных traceback скрыты учётные данные, а переменные стека отсутствуют.

## Testing Decisions

Проверять через публичный HTTP читателя и настоящие временные файлы; подменять внешние системы. Пройти ошибку сборщика, обработки и исходную ошибку worker, отмену и ожидание результата. Проверку формы совместно с №01 включить в итоговую приёмку; №01 не блокирует самостоятельный путь диагностики уже существующего источника.

Согласованные границы: публичный HTTP API читателя и существующий браузерный сценарий; утверждены вместе с разбиением. Проверки внутренних методов не являются приёмкой.

## Completion

Продемонстрировано поведение задачи и выполнены её критерии. Изменения не нарушают уже готовые ветви; согласованная спецификация определяет общие ограничения. Наличие преждевременного локального черновика не означает готовность задачи.
