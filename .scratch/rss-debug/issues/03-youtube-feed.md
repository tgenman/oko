# 03: Автоматически обрабатывать собственные фиды YouTube

Status: done
Approval: разбиение, зависимости и проверки согласованы 2026-10-12
Execution: реализация разрешена пользователем 2026-10-12

**What to build:** Пользователь вставляет URL собственного YouTube RSS/Atom-фида в ту же форму, получает название и после добавления читает собранный материал через существующий YouTube-сборщик.

**Blocked by:** 01: Проверить и добавить RSS/Atom по URL

**Основание:** [Согласованная спецификация](../spec.md).

**Покрытие:** U06, U07.

## Acceptance criteria

- [x] Приведённый в спецификации фид 3Blue1Brown проходит тот же сценарий проверки и добавления, распознаётся как YouTube и не требует выбора типа сборщика.
- [x] Появляются обновления видео и превью; доступные субтитры запрашиваются при включённых тезисах или высокой важности, по текущим разрешениям и обработчику.
- [x] Недоступные субтитры имеют существующее явное состояние; полное видео и аудио не скачиваются.
- [x] Обычный RSS с ссылкой на YouTube остаётся обычным RSS и не переключается на обработку видео.
- [x] Импорт OPML сохраняет автоматическое подключение распознанных YouTube-фидов и не получает новую массовую проверку URL.

## Testing Decisions

Через HTTP проверить путь от проверенного фида до собранного материала с подменами Atom, превью и субтитров; в браузере — отсутствие ручного выбора сборщика. Реальную доступность YouTube указать отдельно от подменённых проверок. Дубли сохраняют общий контракт, завершённый в №02, и не требуют отдельного YouTube-механизма.

Согласованные границы: публичный HTTP API читателя и существующий браузерный сценарий; утверждены вместе с разбиением. Проверки внутренних методов не являются приёмкой.
