# 06: Сохранять ошибки браузера и доставлять их после восстановления связи

Status: done
Approval: разбиение, зависимости и проверки согласованы 2026-10-12
Execution: реализация разрешена пользователем 2026-10-12

**What to build:** Ошибки интерфейса, сети и Promise попадают в ту же нижнюю панель даже при закрытом тоггле. При недоступности сервера пользователь видит несохранённые ошибки, а после восстановления они доставляются в журнал.

**Blocked by:** 04: Показывать сгруппированные ошибки API в долговечной нижней панели

**Основание:** [Согласованная спецификация](../spec.md).

**Покрытие:** U03 (ошибки формы в диагностике), D02 (браузер), D04 (повторная доставка), D07, D08, D09 (недоступный сервер).

## Acceptance criteria

- [x] Обработанные исключения UI, сетевых запросов, неожиданные JS-ошибки и отклонённые Promise собираются независимо от открытия панели.
- [x] Сетевая/клиентская ошибка формы URL видна возле формы и в диагностике, когда форма из №01 доступна.
- [x] При недоступном сервере записи остаются в текущей вкладке, отображаются как несохранённые и повторно отправляются после восстановления связи.
- [x] Повторная доставка одной записи и повторный перехват того же исключения не создают ложных повторов; отдельные возникновения корректно увеличивают счётчик.
- [x] Токены/учётные данные скрыты до показа и передачи; плановая отмена браузерного запроса не становится ошибкой.
- [x] Ошибка запроса самого журнала не вызывает рекурсивную отправку ошибок; чтение, выбор карточки и обработка остаются работоспособными.
- [x] После успешной отправки группа доступна после перезапуска; закрытие вкладки до отправки допускает потерю неотправленных записей, как оговорено в спецификации.

## Testing Decisions

В существующем браузерном сценарии воспроизвести пойманную ошибку, глобальную JS-ошибку, Promise, отказ сервера, восстановление и повторную доставку; через HTTP подтвердить долговечную группу. Проверку формы совместно с №01 включить в итоговую приёмку; №01 не блокирует самостоятельный путь диагностики других действий интерфейса.

Согласованные границы: публичный HTTP API читателя и существующий браузерный сценарий; утверждены вместе с разбиением. Проверки внутренних методов не являются приёмкой.
