# 01: Проверить и добавить RSS/Atom по URL

Status: done
Approval: разбиение, зависимости и проверки согласованы 2026-10-12
Execution: реализация разрешена пользователем 2026-10-12

**What to build:** Сначала проверить текущий URL, получить название, затем явно сохранить подписку в выбранной или новой тематической папке. Пользователь видит ошибки проверки и может повторить действие.

**Blocked by:** None

**Основание:** [Согласованная спецификация](../spec.md).

**Покрытие:** U01, U02, U03 (отображение возле формы), U04.

## Acceptance criteria

- [x] RSS и Atom проходят проверку; название берётся из фида, редактируется или вводится вручную при его отсутствии.
- [x] После проверки пользователь выбирает существующую папку или указывает новую; подписка и новая папка создаются только по «Добавить» и доступны после перезапуска.
- [x] HTML, плохой XML, неподдерживаемый формат, ошибка сети и таймаут оставляют объяснение возле формы и возможность повторить проверку, не меняя подписки и папки.
- [x] Изменение URL сбрасывает проверку. Поздний ответ предыдущего URL не разрешает добавление текущего; повторное нажатие блокируется.
- [x] Прямой запрос сохранения не обходит проверку. Остановка Око при ожидании не допускает позднего создания подписки.
- [x] Проверка использует текущие ограничения сетевого доступа; импорт OPML сохраняет прежнее поведение.

## Testing Decisions

Через HTTP проверить проверку/сохранение с временным хранилищем, отказы и перезапуск; в браузере пройти форму, смену URL и запоздалый ответ. Для существующего фида безопасно возвращать конфликт без изменения настроек; окончательное открытие существующего фида покрывает №02. Передача ошибок формы в диагностику покрывается №05/№06.

Согласованные границы: публичный HTTP API читателя и существующий браузерный сценарий; утверждены вместе с разбиением. Проверки внутренних методов не являются приёмкой.

## Completion

Продемонстрировано поведение задачи и выполнены её критерии. Изменения не нарушают уже готовые ветви; согласованная спецификация определяет общие ограничения. Наличие преждевременного локального черновика не означает готовность задачи.
