# Контекстное меню тематической папки

Status: implementation-authorized
GitHub: не опубликовано

## Запрос

Проработать меню папки по правому клику, как существующее меню фида:
переименовать, удалить, всё прочитано, настройки. Подписи интерфейса — на английском.
Пользователь выбрал вариант A и поручил реализацию 2026-10-19.

## Меню

Предлагаемый порядок повторяет расположение общих действий в меню фида;
удаление находится внизу и отделено разделителем.

```text
Mark All as Read
Settings…
Rename…
────────────────
Delete…
```

Оформление, иконки, размеры, опасный цвет Delete… и размещение у края экрана
соответствуют меню фида. Меню открывается на строке конкретной папки,
включая свёрнутую. All Items не является папкой и такого меню не получает.
Правый клик не меняет выбранную область чтения и раскрытие папки.
Действия относятся к папке под курсором, даже когда читается другая папка или фид.

ContextMenu / Shift+F10 открывают меню у строки в фокусе. Стрелки, Home/End,
Enter/Space, Escape, Tab, закрытие снаружи, при прокрутке и изменении окна —
как у фида. После отмены фокус возвращается к исходной строке, если она существует.
Открытие нового контекстного меню закрывает предыдущее.

## Действия

### Mark All as Read

Использовать существующее завершение папки: preview, подтверждение и token
точного состава. Охват включает скрытые, незагруженные и нечитаемые публикации
всех фидов папки. Фиды и настройки сохраняются, новые публикации продолжают поступать.

Заголовок подтверждения: `Mark All as Read · {folder}`; кнопки `Cancel` /
`Mark All as Read`. Показать число публикаций и предупреждение:
`Collected text, versions, media and processing results for this folder, including hidden and unloaded items, will be deleted. Feeds stay connected. Telegram read status will sync according to your current settings.`

При изменении состава нужно повторное подтверждение. Видимый счётчик 0 сам по себе
не отключает действие: в папке могут оставаться скрытые материалы. Подтверждение
недоступно при загрузке preview и нулевом числе публикаций в нём.

### Settings…

Открыть существующий редактор настроек сразу на уровне выбранной папки.
Сохранить правила наследования Око → папка → фид и черновики владельца настроек.

### Rename…

Открыть диалог `Rename Folder` с полем `Name`, заполненным текущим названием;
текст выделен. Кнопки `Cancel` / `Save`; Enter сохраняет, Escape отменяет.
Внешние пробелы обрезаются. Пустое название и совпадение с названием другой папки
отклоняются с сообщением у поля; неизменное название не отправляет запись.
Регистрозависимость совпадений следует действующему ограничению уникальности названий.

ID папки — внутренний непрозрачный идентификатор, независимый от названия.
Новые папки получают случайный ID, существующие сохраняют свои ID без миграции связей.
После переименования прежнее название можно использовать для новой папки с другим ID.
Повторное создание после удаления также получает новый ID.
Меняется только название, стабильный ID папки сохраняется. Привязки фидов,
настройки, выбор, раскрытие и материалы сохраняются. Дерево обновляет название;
существующая сортировка учитывает числовой префикс названия, поэтому место папки
может измениться. Ошибка сохраняет введённое название для исправления.

### Delete…

Решение пользователя: блокировать удаление непустой папки и показывать
всплывающее предупреждение.

Пустая папка — папка без фидов. Нулевой счётчик материалов, скрытые прочитанные
фиды и свёрнутое дерево не означают пустоту. Учитываются все привязанные фиды,
включая недоступные и ещё удаляемые. Delete… остаётся доступным для непустой папки,
чтобы нажатие объясняло причину запрета.

Предупреждение: заголовок `Folder Is Not Empty`, текст
`Move or delete all feeds in “{folder}” before deleting this folder.`, кнопка `OK`.
Данные не меняются; фиды автоматически не переносятся и не удаляются.

Для пустой папки — подтверждение `Delete Folder`, текст
`Delete “{folder}” and its folder settings?`, кнопки `Cancel` / `Delete Folder`.
Успех удаляет папку и её настройки. Другие папки и фиды сохраняются.
Пустые папки доступны через существующий Show Read.

Сервер проверяет отсутствие фидов атомарно с удалением. Если после открытия
подтверждения в папку добавили или перенесли фид, удаление отклоняется и показывается
то же предупреждение. Проверки только по браузерному каталогу недостаточно.

## Границы реализации

Проверено по текущему коду: меню фида находится в
`frontend/src/reading/feed-actions.tsx`, дерево — в `tree.tsx`, завершение папки —
в `folder-actions.tsx`. `settings/owner.ts` поддерживает выбор уровня папки.
В `api/openapi.yaml` есть preview/завершение папки и настройки; операций
переименования и удаления папки нет. Для них потребуется расширить существующий
HTTP-контракт и сгенерировать SDK по `api/README.md`.

Цель меню фиксируется по ID. Поздние ответы закрытого меню не управляют новым
меню, диалогом или выбором чтения. Успешная серверная запись согласуется с деревом
даже после закрытия диалога; дублирующая отправка блокируется. Исчезновение цели
закрывает её меню. Удаление выбранного объекта требует согласования области чтения
и открытого материала по действующим архитектурным правилам.

## План проверки реализации

- Playwright: четыре английских пункта, правый клик и клавиатура, свёрнутая папка,
  границы окна, отмена и возврат фокуса; выбранная область не меняется при открытии.
- Папка A в меню при чтении B: действие касается только A; поздние ответы после
  закрытия и открытия меню B не изменяют его состояние.
- HTTP с временным хранилищем: rename сохраняет ID/фиды/настройки, отклоняет пустое
  и занятое название; completion включает скрытые материалы и проверяет token.
- Settings открывает нужную папку и сохраняет существующие черновики.
- Delete непустой папки показывает предупреждение и сохраняет данные, в том числе
  при нулевом счётчике, скрытых, недоступных и удаляемых фидах.
- Удаление пустой папки: отмена сохраняет её, подтверждение удаляет папку и её
  настройки; другие объекты сохраняются. Добавление фида перед записью блокирует
  удаление на сервере. Show Read позволяет добраться до пустой папки.
