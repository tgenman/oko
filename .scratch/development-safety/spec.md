# Среда разработки: безопасные снимки и синтетические проверки

Status: done
Assignee: primary

По запросу пользователя реализовать четыре результата ретроспективы Codex-настроек. Исходный HEAD ce82b70; прежние незакоммиченные правки сохраняются.

## Результат и границы

1. Общий CLI снимка получает только Git inventory: tracked и untracked, с учётом ignore. Содержимое игнорируемых файлов и целей symlink не читается. Снимок вне checkout, с manifest исходного HEAD, индекса, путей, режимов и байтов; ошибки пути/индекса явные.
2. Тестовая фабрика production HTTP-приложения по умолчанию предоставляет синтетические Codex, субтитры и историю YouTube, транспорт, запрещающий сеть; явный транспорт допускает только точный origin принадлежащего тесту loopback-сервера. Явно переданные внешние adapters используются для проверок их границы с синтетическими SDK/процессами. Product defaults не меняются. Обычные тесты и дочерние тестовые серверы используют эту фабрику.
3. Общий Codex double типизирован согласно CodexClient. Детерминированная проверка наследуемых тестовых клиентов обнаруживает устаревшие сигнатуры до запуска большого набора; включена в runner и hooks/CI через существующие команды. Невалидный пример отклоняется, совместимый принимается.
4. CLI строит diff задачи относительно снимка, готовит только явно выбранные изменения к коммиту поверх HEAD, сохраняет прежние unstaged/staged изменения, проверяет подготовленное содержимое и выполняет явную команду коммита. Никаких reset/clean/автоматического разрешения конфликта: конфликт останавливает подготовку, его конкретное содержимое доступно для исправления в временной копии. Изменение HEAD/индекса после снимка/подготовки обнаруживается до записи. Работа в основном checkout; реальный индекс и файлы не меняются при подготовке/ошибке.

## Проверки

CLI через subprocess в временном Git repo: ignored data, tracked/untracked, symlink, удаление/переименование, бинарные файлы и пробелы в путях, исходные staged изменения, конфликты, дрейф HEAD/индекса/подготовленного состояния, сохранение working tree и состава коммита. HTTP фабрики с временными данными: синтетические defaults, явный adapter и отсутствие реального worker. Проверка контрактов через subprocess на валидном и ошибочном Python-корпусе. Затронутые наборы, весь Python, типизация, checks и независимое ревью; результаты отдельно в docs/verification.
