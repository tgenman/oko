# Предпросмотр ответа Telegram — UI-прототип

Status: selected — пользователь выбрал A 21 октября 2026
GitHub: https://github.com/tgenman/oko/issues/70

Спецификация реализации: [парсинг ответов и вариант A](../telegram-reply/spec.md). После этапа проектирования пользователь разрешил реализацию через implement-spec.

Вопрос: как показать цитируемое сообщение отдельно от собственного текста, сохранив компактность чтения?

## Решение

Выбран A: компактная карточка перед собственным текстом, автор и две строки доступного фрагмента, раскрытие фрагмента и переход к цитируемому посту. Заголовок материала и карточки чтения берётся из собственного текста. B и C остаются в архиве для контекста выбора.

Это решение о представлении. Макет не реализует изменение Telegram-парсера, хранения или HTTP-контракта; рабочий экземпляр не менялся. Исходники и решение сохраняются в локальной ветке `codex/telegram-reply-prototype-20261021`.

Запуск: `npm run prototype:telegram-reply`.
URL: http://127.0.0.1:5190/?variant=A (также B и C).

- A: карточка как в Telegram перед текстом — автор, две строки фрагмента, раскрытие полного доступного фрагмента и переход к цитируемому посту.
- B: одна первоначально свёрнутая строка «В ответ Varlamov News» перед текстом; раскрытие показывает фрагмент и ссылку.
- C: собственный текст первым, контекст ответа отдельной областью после него.

Все варианты показывают заголовок из собственного текста, включая заголовок в списке карточек. Внизу — переключатель A/B/C с кнопками и клавишами ←/→, URL сохраняет выбор. «Данные макета» раскрывают используемую структуру title/text/reply.

Снимок данных взят из указанного пользователем публичного поста https://t.me/varlamov_news/75124; ответ ведёт на https://t.me/varlamov_news/75122. Автор, фрагмент и собственный текст извлечены отдельно. Это подготовленные данные макета; рабочий парсер пока не изменён. Фрагмент уже усечён самим Telegram — прототип не обещает полный текст цитируемой публикации и не загружает его.

Код расположен рядом с областью чтения: `frontend/src/reading/telegram-reply.prototype.{tsx,css,json,mjs}`. Отдельный Vite dev-сервер подменяет entrypoint на существующем `/`; рабочий entrypoint не менялся. Нет запросов к API читателя, личным подпискам, аккаунтам или обработчикам. Кнопки рабочего shell отключены.
