# Интервал обновления фидов

Статус: согласовано пользователем 2026-10-19; реализация разрешена.

GitHub: https://github.com/tgenman/oko/issues/46

## Согласовано 2026-10-19

- В «Настройках Око» появляется одна общая настройка «Интервал обновления фидов». Она действует на все подключённые фиды; отдельных значений папки или фида нет.
- Значение задаётся целым числом минут от 1 до 1440 включительно.
- По умолчанию — 15 минут, в том числе для существующих установок без сохранённого значения. Сейчас в коде задано 5 минут.
- Сохранённое значение переживает перезапуск Око.
- После сохранения срок следующего автоматического обновления пересчитывается от последней автоматической постановки обновлений в очередь. Если срок уже прошёл, обновление сразу ставится в очередь.
- Изменение интервала не прерывает текущий сбор.
- Ручное «Обновить» доступно независимо от интервала. Обновление одного фида или всех фидов не сдвигает автоматический таймер.

## Границы изменения

- Используются существующие правила редактора: явное сохранение и сброс. Сброс возвращает 15 минут.
- Существующие условия допуска работы, поведение при запуске и остановке, повтор после ошибки и ограничения источников сохраняются. Сохраняется значение интервала; перенос автоматического таймера между запусками не добавляется.
- Интервал определяет постановку обновлений в очередь, а не гарантированное время получения публикаций.
- Сохранение только интервала не отменяет текущую работу и не делает готовые результаты ИИ неактуальными.

## Проверенные факты текущей реализации

- Runtime ставит обновление всех активных источников в очередь каждые 300 секунд. Ручной сбор не меняет этот таймер.
- Существующий редактор настроек использует явные сохранение и сброс, сохраняет новый ввод во время запроса и согласует выполненную запись независимо от навигации.
- Общие параметры чтения наследуются от Око папкам и фидам. Интервал должен оставаться глобальным параметром.
- Текущий общий путь записи настроек отменяет выполняемую работу. При реализации интервала необходимо обеспечить согласованное отсутствие прерывания сбора.

Источники: `oko/reader/runtime.py`, `oko/subscriptions/subscriptions.py`, `frontend/src/settings/owner.ts`, [владение настройками](ui-settings.md), [управление работой](reader-work.md).

## План проверок реализации

- HTTP interface с временным хранилищем: default 15, сохранение и чтение после перезапуска, сброс, строгая проверка целых значений 1–1440 и запрет переопределений папки/фида.
- Синтетические источники и управляемое время: автоматический сбор по выбранному интервалу, пересчёт при увеличении и уменьшении, немедленная постановка при истёкшем сроке, отсутствие прерывания текущей работы и сдвига таймера ручным сбором.
- Настоящий браузер через Playwright: поле в «Настройках Око», сохранение, сброс, ошибки ввода, сохранение более нового черновика при задержанном ответе. Просмотр снятого скриншота.
- Проверка затронутого OpenAPI-контракта и сгенерированных клиентов при его изменении.
