# Подключение Telegram и темы форумов

> Решение о подключении темы отдельным фидом заменено 15 октября 2026: [одна группа — один фид в одной папке](../telegram-access/spec.md#3-группа-целиком-без-отдельных-фидов-тем). Удаление этой функциональности и упрощение кода запланированы, но ещё не реализованы. Ниже сохранено описание предыдущей версии.

Основание: запрос пользователя 12 октября 2026. База ревью: 6979747 (подтверждена пользователем).

- Аккаунт выбирается из доступных аккаунтов собственного клиента Telethon. Список загружается при открытии настроек; доступны повторная загрузка и явные состояния ошибки/пустого списка.
- Подключение недоступно без аккаунта, корректного username/ID и непустой папки, а также во время запроса. Поля очищаются только после успешного подключения. Ошибка позволяет повторить запрос.
- Для форумной группы пользователь загружает список тем и выбирает одну тему. Каждая тема, включая «Общее» (ID 1), — отдельный фид с независимыми настройками, курсором и отметками прочитанного. Подключение форума без темы отклоняется с понятным сообщением; обычные каналы/группы продолжают работать.
- Аккаунт + peer + topic определяют идентичность. Повторное подключение той же темы не создаёт дубль; разные темы не переподключают существующий фид. Существующие подписки сохраняются после миграции.
- Сбор, повторная загрузка, альбомы и медиа ограничены выбранной темой. Ссылка ведёт на сообщение в теме. Курсор переживает перезапуск, в том числе страницы без сообщений выбранной темы.
- Автопрочитывание подтверждает сообщения после полного сохранения, обычный режим — после «Просмотрено». Для темы используется её серверная граница и отметка только этой темы, без подтверждения всего диалога и без fallback к нему.
- При смене аккаунта/peer старый список тем сбрасывается; поздний ответ не меняет новый выбор. Запрос подключения не допускает повторного отправления.
- Подписи отражают работающий собственный клиент, выбор тем и текущую синхронизацию чтения; убрать устаревшие упоминания MCP и будущего этапа.

Проверки на ранее согласованных границах: API читателя с временным хранилищем/подменяемым Telegram; браузер с настоящими HTML/JS и подменяемым внешним транспортом. SDK-запросы дополнительно проверяются через subprocess собственного worker с внешним SDK fixture. Реальная Telegram-проверка — отдельно, без новых отметок личных сообщений.

Источники протокола: [форумы Telegram](https://core.telegram.org/api/forum), [readDiscussion](https://core.telegram.org/method/messages.readDiscussion). В установленном Telethon 1.45.0 методы списка тем находятся в `functions.messages`, а не в старом `functions.channels`.
