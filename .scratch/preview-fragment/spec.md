# Фрагменты пяти пересланных постов Telegram
База 62436a77df1a2df145379130b2a8b2775469fe44. Запрос пользователя: доступный фрагмент с пометкой неполноты и ссылками на пост/оригинал, без source errors/autoretries, manual retry, main+deploy. Предыдущие Telegraph/hidden fallback/network partial не менять.

Подтверждённая text_not_supported_wrap без собственного тела/медиа остаётся заглушкой даже при forwarded_from. Только для таких пересылок fetch получает metadata обычной страницы того же сообщения. Строго проверить идентичность script[data-telegram-post]/app-link и редирект, не принимать описание канала. Не считать metadata полной копией, не угадывать URL встроенных ссылок/медиа, не раскрывать og:image как вложение. Использовать существующий HTTP admission, cancellation и version ownership.

Хранить preview_fragment отдельно от исходного тела/атрибуции в SourceManifest; читатель показывает его с явной пометкой и stable permalink. Это принятый неполный результат без проблемы и повторов. Сбой metadata сохраняется как видимая причина; SourceDeferred/429 остаётся ожиданием. Старую пригодную полную копию не заменять обрезанным fragment; прежняя false unsupported-классификация переходит в fragment без авторской версии. По fragment не запускать AI и Telegraph crawling. Wire API не расширяется: имеющиеся linked_content + неполнота/сообщение отображают фрагмент и ручной retry. Пять записей после deploy перепроверить штатным API.
