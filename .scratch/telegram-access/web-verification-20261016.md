# Telegram #20: web, история, Telegraph и медиа

Дата: 2026-10-16. База diff: `9e75b0d` (задача #19).
Задача: https://github.com/tgenman/oko/issues/20.

## Реализовано

- Python-порт HTML-разбора RSSHub с атрибуцией точного commit и полным AGPL-3.0; web без Telegram-профиля, cookies и account fallback.
- Общий типизированный HistoryEnvelope, перенос старого client cursor, ограниченные страницы, возобновляемый catch-up, разделение live/archive и атомарное сохранение manifest/cursor.
- Устойчивые альбомы и members; обновление адреса не создаёт второй материал и не возвращает просмотренное.
- Общий web/client Telegraph: текст и локальные медиа, уникальные прямые ссылки; iframe/неподдерживаемые части имеют причину неполноты. Произвольные ссылки не обходятся.
- Resource/Article/Source manifests, стабильные ключи ресурсов и имена, различие первого дополнения и изменения известных текста/байтов. Ошибки/смена CDN-подписи не становятся авторской версией и не инвалидируют принятую обработку.
- Потоковое скачивание в принадлежащий заданию staging, проверка admission/path/size/hash при сохранении; SDK worker перемещает spool. Ранее принятые файлы сохраняются без чтения всего набора в RAM.
- Предел 200 MiB на файл, терминальные ошибки требуют ручного повтора; transient ошибки используют backoff и сохраняют читаемую копию.
- Публичный transport проверяет URL/redirect/DNS, подключается к проверенному IP и сохраняет TLS hostname; private/local адреса запрещены. Запоздалый ответ после удаления не начинает новые загрузки и не публикует файлы.

## Пределы доказательства

Fixture/SDK проверки подтверждают локальные алгоритмы и границы; они не доказывают текущее поведение реального Telegram/CDN/Telegraph. Web username не доказывает устойчивый numeric peer и не гарантирует распознавание неизвестного переименования. Совместимость остальных API и итоговая UI-приёмка проверяются следующими задачами.
