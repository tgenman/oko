# CI и скорость тестов после Telegram-ретро

Status: claimed
Base: 675b795b97a4333303eff89d9f524a7d8e625e99

Цель: убрать подтверждённую гонку browser presence, воспроизвести и исправить
сбой reconciliation после потери ответа, ускорить synthetic Telegram checks,
сделать наблюдаемыми длительности pytest и точнее выбирать tools-наборы.
Рабочую установку/настройки Око не менять; тестовые лимиты задавать только во
временных тестовых хранилищах через существующий HTTP интерфейс. Production
лимиты, проверка бюджета/FloodWait/backoff и их сценарии сохраняются.

Критерии:
- [ ] C1. Browser helper подтверждает регистрацию сессии перед требующими её
  командами; управляемая задержка регистрации проверяется через Playwright.
- [ ] C2. Потерянный ответ настроек проверяется при управляемом восстановлении
  соединения: исход известен без повтора команды, новый черновик сохраняется.
- [ ] C3. Обычные synthetic Telegram-сценарии используют явные быстрые тестовые
  настройки. Сравнимый замер 25 сценариев и специализированные budget-тесты проходят.
- [ ] C4. Отчёт runner хранит pytest длительности по файлам/сценариям и корректное
  elapsed группы при FAIL; полнота и отмена сохраняются.
- [ ] C5. Tools выбираются по детерминированной карте входов к тестовым семействам;
  неизвестные изменения в tooling выбирают полный набор. Есть CLI-проверки выбора.
- [ ] C6. Целевые и полные проверки выполнены в изоляции, есть независимое ревью
  и отдельный отчёт фактических результатов. Рабочая установка не тронута.
