# 05: Самостоятельный фронтенд при одном запуске

Status: done

**What to build:** Браузерный код расположен отдельно от Python-кода и доставляется вместе с ним. Один существующий запуск Око открывает рабочий читатель; новый браузерный module доступен без изменения серверного перечня файлов.

**Blocked by:** None (can start immediately).

Спецификация: [явное разделение фронтенда и бэкенда](../spec.md). Реализация поручена пользователем через implement-spec 2026-10-13.

- [x] Все браузерные production-файлы перенесены в согласованный самостоятельный каталог без копий и реэкспортов. Серверный код остаётся в Python-пакете.
- [x] Существующая команда и параметры запуска обслуживают страницу и данные на одном origin. Отдельный процесс, порт, обязательный сборщик и Node при пользовательском запуске не появляются.
- [x] Существующие URL страницы, скриптов, CSS и данных сохранены; запуск из другого рабочего каталога выдаёт те же файлы.
- [x] Общая выдача статики обслуживает вложенные ES imports с корректными MIME-типами без регистрации каждого имени в Python. Настоящий браузер загружает весь импортируемый граф.
- [x] Выдача статики не перехватывает маршруты данных и не превращает неизвестный маршрут в HTML. Сохранены локальная сессия, host/origin-проверки, CSP и остальные защитные заголовки.
- [x] Проверены попытки обхода пути и symlink: файлы за пределами каталога фронтенда недоступны.
- [x] Runner, линтер и staged-проверки находят браузерные файлы после переноса, включая вложенные modules. Существующие команды проверок и тестовые каталоги сохранены.
- [x] Действующая документация запуска и подготовки окружения обновлена. HTTP-проверки выдачи и затронутые браузерные сценарии проходят; результаты записаны отдельно.

## Результат

Критерии выполнены. Фактические проверки, первоначальные падения, итоговые повторы и независимое ревью записаны в [общем отчёте](../../../docs/verification/frontend-backend-separation.md).
