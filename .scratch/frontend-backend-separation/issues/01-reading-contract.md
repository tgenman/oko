# 01: Проверяемый контракт списка чтения

Status: done

**What to build:** Карточки и навигация доходят от сервера до браузера с явными контрактами данных. Настоящие ответы и снимки браузерных сценариев проверяются по одному серверному описанию; несовместимое изменение обнаруживается автоматически.

**Blocked by:** None (can start immediately).

Спецификация: [явное разделение фронтенда и бэкенда](../spec.md). Разбиение согласовано 2026-10-13; пользователь отдельно поручил реализацию через implement-spec.

- [x] Перед изменением зафиксированы текущие URL, варианты ответов списка чтения и результат затронутых проверок. Учтены публикации, события, обзоры, скрытые и неполные материалы, варианты сортировки и выбора области.
- [x] Карточки, папки, фиды и счётчики описаны существующими средствами моделирования проекта. Внутреннее устройство Store и Runtime не становится частью HTTP interface.
- [x] Контракты сохраняют все существующие поля, типы, обязательность, различие отсутствующего поля и null; сериализация не добавляет defaults, меняющие смысл ответа.
- [x] Из одного серверного описания локально экспортируется машинно проверяемая схема. Независимо написанной дублирующей JavaScript-схемы и нового публичного маршрута для схем нет.
- [x] Общий механизм проверки применён к настоящим HTTP-ответам и снимкам браузерных сценариев карточек и навигации. Он обнаруживает неверный тип и отсутствие обязательного поля.
- [x] Настоящий браузер сохраняет выбор тематической папки и фида, список карточек и счётчики. Сквозной сценарий без подмены browser fetch подтверждает согласованность списка и навигации.
- [x] Проверки используют временные хранилища и синтетические внешние adapters; результаты и ограничения записаны отдельно от плана.

## Результат

Критерии выполнены. Фактические проверки, первоначальные падения, итоговые повторы и независимое ревью записаны в [общем отчёте](../../../docs/verification/frontend-backend-separation.md).
