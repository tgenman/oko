# 04: Единый транспорт всех действий читателя

Status: done

**What to build:** Чтение, настройки, медиа, диагностика и закрытие вкладки используют общие правила передачи. Пользователь сохраняет существующее поведение действий и сообщений об ошибках, а правила запросов меняются в одном module.

**Blocked by:** None (can start immediately).

Спецификация: [явное разделение фронтенда и бэкенда](../spec.md). Реализация поручена пользователем через implement-spec 2026-10-13.

- [x] Module транспорта принимает зависимости и предоставляет небольшой interface для JSON-запросов, медиа и отправки при закрытии вкладки. Отдельного метода для каждого серверного маршрута нет.
- [x] Все браузерные callers, включая диагностику, медиа и закрытие вкладки, используют общие правила авторизации и передачи. Реальный fetch adapter и управляемый транспорт проверок проходят тот же interface.
- [x] Сохранены методы, тела, правила кэширования, AbortSignal, keepalive и существующие URL; токен не передаётся на посторонний origin.
- [x] HTTP-ошибка сохраняет detail, диагностический идентификатор и различение ожидаемых ошибок. Сеть и не-JSON ответ дают обрабатываемую ошибку.
- [x] Транспорт не владеет DOM, выбором материала или поколениями UI. Успешная запись после закрытия формы сохраняется; поздние сообщения допускаются владельцем UI-состояния.
- [x] Не добавлены автоматические повторы мутаций, скрытый polling и единый отменяемый контекст всех экранов. Время жизни медиа и blob URL сохраняет существующее владение.
- [x] Очередь, повторная доставка и дедупликация диагностики сохраняются. Ошибка её доставки не порождает рекурсивный поток запросов.
- [x] Настоящие браузерные сценарии подтверждают чтение, настройки и черновики, медиа, ошибки, задержанные ответы и закрытие вкладки. Проверки и ограничения записаны отдельно.

## Результат

Критерии выполнены. Фактические проверки, первоначальные падения, итоговые повторы и независимое ревью записаны в [общем отчёте](../../../docs/verification/frontend-backend-separation.md).
