# Сигналы завершения и матрицы черновиков

База: main `08eec5e`. Рабочие настройки/данные и установленный выпуск не менять.

1. Telegram reload: заменить фиксированные ожидания завершением collection через HTTP; для проверки отсутствия retry после перевода часов наблюдать реальные проходы существующего reader_advance, сохраняя исходный callback. Не подменять выполнение Runtime или ответы HTTP. Ожидание имеет ограничение времени и падает, если цикл не идёт. Только синтетические functional web fixtures используют существующий configure_fast_web; тесты ограничителей не меняются.
2. Матрицы сохранения черновиков: существующий MenusOwner, настоящий generated SDK/Fetch adapter и управляемые ответы в Node без DOM/сервера. Проверить типы полей, сохранение/сброс, разные объекты, ABA ввод (изменение и возврат значения), поздний успех/отказ, независимость полей, discard и контекст команды. Удалить только повторные browser-проверки тех же правил; сохранить пользовательские сценарии открытия, focus/navigation, поздние ответы и реальные HTTP save/reset/failure на представителях.

Сохраняются реальный браузер, lifecycle/cancel/restart, все performance-профили, 320 кликов, порог p95 <200 мс и прежние пользовательские skips. Не кэшировать результаты тестов. Production-код и его настройки не меняются.

Проверки: целевые Python/Node/browser, отрицательный опыт для сигнала цикла и новых матриц, независимое ревью, staged и полный `all tools` с сопоставлением исходного замера. Все FAIL и ограниченные повторы отражать отдельно.

Обнаруженная нестабильная проверка reply-preview: учитывать штатный polling отдельно от новых запросов; known_version материальных ресурсов сверять с фактически доставленным ответом, не разрешать повторное чтение с null.
