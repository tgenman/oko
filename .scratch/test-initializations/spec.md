# Сократить повторную подготовку тестов

Пользователь разрешил уменьшить повторные инициализации, перенести матрицы ниже HTTP и ускорить браузерную часть. Рабочие настройки и запуск Око не изменяются. Публикация и слияние в этой задаче не запрошены.

## Проверяемое поведение

- Закрытые синтетические библиотеки строятся по ключу один раз за один runner; разные процессы получают независимые копии SQLite/файлов и metadata. Блокировка публикует только полностью закрытый успешный seed. Ошибка/смерть builder не публикует результат; новый прогон имеет новый каталог. Владельцем каталога и очистки после завершения дочерних процессов остаётся runner. Прямой запуск сохраняет прежние временные шаблоны процесса.
- Матрица 6 видов источников × pending/available проверяет реальные text/legacy проекции и Store без scheduler/HTTP. Два HTTP-представителя сохраняют проверку changed frame, status и паритет. Матрица трёх внешних кодов ошибок проверяет реальную problem projection; один HTTP-сценарий сохраняет source failure, waiting/retry_at и material recovery. Все прежние большие SQL/file/VM бюджеты и обработанные материалы остаются HTTP-проверками.
- Несколько браузерных файлов регистрируются в каждом из прежнего числа worker-процессов; worker переиспользует imports и Python-host, сценарий сохраняет собственные Store/Runtime, токен, origin, context и cleanup. Глобальные hooks владельцев выполняются после всех зарегистрированных сценариев группы. Сохраняются имена, --match, failure exit status, все сценарии, два прежних skips и все 320 performance-кликов с прежним p95.
- Группировка не применяется к произвольному command/eval, одиночному файлу и performance-файлу. Временные batch entrypoints очищаются после process group.

## Приёмка

Проверить конкурирующую публикацию, failed builder, независимость копий/metadata и нового run, группировку/failure/filter/hooks; настоящий браузерный набор включает HTTP isolation, abort, restart и suite process cleanup. Независимое ревью по состоянию и владению. Затем один полный all tools до и после, одинаковые workers и окружение; не совмещать их с другими тестами. Не выдавать успешный ограниченный повтор за зелёный полный прогон.

Уточнение по найденному full-run падению: локальное раскрытие reply-preview допускает только штатный PUT browser-session heartbeat; прочие foreground requests и guards id/known_version для reading/check сохраняются. Регрессия явно вызывает авторизованный heartbeat.
