# Настройки фида: вариант B

Status: done
GitHub: не опубликовано
Дата: 2026-10-19

## Решение и объём

Пользователь выбрал вариант B прототипа: основные поля и описание слева,
активность справа. Сначала была подготовлена только спецификация;
2026-10-19 пользователь отдельно поручил реализацию по ней.

Уточнение пользователя: Link можно только копировать; рядом нужна маленькая
кнопка копирования. Редактирование адреса и переход по нему не входят в сценарий.

Основной результат будущей реализации — обновлённая страница настроек конкретного
фида в существующем окне Feeds and Folders. Варианты A/C, переключатель и синтетические
данные в рабочий интерфейс не переносятся. Language, Favorites и Articles отсутствуют.
Подписи интерфейса — на английском, в текущем стиле Око.

## Компоновка

Существующее дерево папок/фидов остаётся способом выбора объекта. При открытии
Settings… из меню фида выбран именно этот фид. Блок варианта B размещается в его
редакторе; отдельное второе окно настроек не создаётся.

Вверху редактора — сохранённое название фида, существующая иконка/аватар при наличии,
тип источника и действующий способ подключения. Не подменять способ доступа Telegram
надписью RSS, использованной в синтетическом примере.

Слева, под заголовком Feed details:

1. Title — редактируемое локальное название фида.
2. Link — адрес источника только для чтения и маленькая кнопка копирования справа.
3. Folder — выпадающий список существующих тематических папок.
4. Description — описание внешнего источника только для чтения, с переносами строк.

Справа, в отдельной спокойной по цвету панели Activity:

- крупное число Unread;
- Created;
- Modified;
- Last update;
- Marked read.

Title, Link и Folder расположены вертикально, как в B. Панель Activity выровнена
по верхнему краю основных полей. Длинные название, URL и описание не расширяют окно:
текст переносится, адрес допускает горизонтальную прокрутку внутри своего поля.
Редактор прокручивается по вертикали. При нехватке ширины доступного редактору места
Activity располагается под основными полями; информация и действия сохраняются.

Существующие Connection and Options, важность, разрешение публичного AI, история,
настройки Telegram/YouTube, удаление и наследуемые параметры чтения/обработки остаются
доступны. Новые основные поля находятся на домашней странице настроек фида; Folder
не дублируется в Connection and Options. Нижние действия нового блока не сохраняют
черновики других страниц и не запускают сбор/догрузку/обработку.

## Поля и действия

### Title

Начальное значение — сохранённый `title`. При сохранении обрезаются внешние пробелы;
допускается 1–200 символов после обрезки. Пустое значение отклоняется у поля.
Совпадающие названия разных фидов допустимы: идентичность задаётся ID/источником.
Переименование сохраняет ID, адреса, доступ, историю, материалы и локальные настройки.
Сбор метаданных источника не перезаписывает пользовательское название.
После успеха новое название появляется в деревьях и остальных представлениях,
использующих название фида, без смены выбранного объекта.

### Link и копирование

Link показывает адрес подключения, а не адрес карточки, API, текущей страницы
читателя или произвольный URL из описания. Основное значение — первый сохранённый
`original_urls`; при нескольких адресах остальные перечислены ниже как Additional
links, каждый со своей кнопкой копирования. Так существующие адреса не теряются.
Порядок адресов сохраняется. При отсутствии адреса — `Not available`, кнопки нет;
внутренний identity не выдаётся за URL. Это применимо и к demo/старым фидам.

Адрес — selectable read-only input, без ссылки и без обработчика перехода.
Рядом компактная кнопка с иконкой двух листов, доступная с клавиатуры и с видимым
фокусом; accessible name `Copy link`, tooltip `Copy link`. Для дополнительных
адресов accessible name различается номером. Копируется полный исходный адрес
без изменения query string, обрезки или раскрытия URL.

Кнопка не отправляет запись на сервер и не меняет черновик. После подтверждённого
успеха clipboard API — короткое сообщение `Copied` в области live status.
При отказе — `Could not copy. Select and copy the link manually.`; адрес остаётся
выделяемым. Успех не показывается до результата операции. Поздний результат
копирования фида A не меняет сообщение повторно открытого редактора или фида B.

### Folder

Использовать ID и названия из актуального каталога подписок; выбран текущий
`folder_id`. Каждый фид принадлежит ровно одной папке. Изменение селектора создаёт
черновик, перенос происходит только по Save. Создание папки из этого селектора
не добавляется; существующее действие создания/перемещения остаётся доступно в меню.

Перенос сохраняет ID фида и материалы, обновляет принадлежность в деревьях и составе
чтения. Собственные переопределения фида сохраняются; унаследованные значения после
переноса вычисляются от новой папки. Удалённая/исчезнувшая папка назначения отклоняется
сервером без частичного переименования или переноса.

### Save, Reset, Cancel

Кнопки относятся к Title и Folder нового блока. Save и Reset доступны только при
изменениях; Enter в форме сохраняет. Отправляются только изменённые поля, совместно
одним атомарным PATCH. Нормализованное неизменное название само по себе запись
не создаёт. Двойная отправка для одного фида блокируется до завершения запроса.

Reset восстанавливает последние подтверждённые Title/Folder и оставляет редактор
открытым. Cancel отменяет изменения этого блока и закрывает окно настроек; черновики
других страниц сохраняются. Общие Close/Escape диалога сохраняют существующее правило
владельца настроек о черновиках при закрытии. При повторном открытии состояние
подтверждённых полей и оставшихся черновиков восстанавливается владельцем настроек.

Ошибка валидации/записи оставляет ввод для исправления. При неизвестном исходе
команды используется существующая сверка receipt; автоматической повторной отправки
нет. Успешная запись согласуется с каталогом даже после переключения фида, но не
меняет выбор, фокус, сообщение и новый ввод другого контекста. Изменения, введённые
после начала сохранения, остаются в черновике. Фоновое обновление Activity не
перезаписывает несохранённые Title/Folder.

## Смысл информационных полей

| Поле | Смысл |
|---|---|
| Created | Время создания подписки в Око, не дата создания внешнего канала. |
| Modified | Время последнего фактического изменения собственных настроек этого фида: Title, Folder, параметры подключения или локальные переопределения. Изменение родительских настроек и фоновый сбор сюда не относятся. |
| Last update | Последний успешно принятый и сохранённый результат поиска публикаций этого фида, в том числе результат без новых публикаций. Запуск Refresh, загрузка отдельного материала, AI-обработка и неудачная попытка дату не меняют. |
| Marked read | Последняя успешно сохранённая отметка «Просмотрено» хотя бы одной публикации этого фида в Око: отдельное действие, диапазон, завершение фида или папки. Открытие материала, Telegram auto-read, удаление фида и завершение пустого состава дату не меняют. |
| Unread | Число известных исходных публикаций фида без отметки «Просмотрено» в Око, включая скрытые, загружаемые и недоступные. Не число карточек после группировки и не внешний счётчик Telegram. Не зависит от Show Read/Show Hidden и текущей области чтения. |
| Description | Полученное описание внешнего канала/ленты, не описание отдельной публикации, не возможности обнаружения правок и не текст, сгенерированный AI. |

Время передаётся сервером в UTC в принятом формате API, отображается в локальной
временной зоне браузера. Полная дата и время доступны без относительного `Today`.
Открытие окна само по себе не инициирует обращений к источнику.

Created/Modified/Last update/Marked read сохраняются между перезапусками.
Неизвестная историческая дата — `—` с пояснением `No recorded date`; дата миграции,
время файла и максимальная дата публикации не используются как замена. Для нового
фида Created и Modified изначально равны времени создания. Реальный последующий
переход устанавливает соответствующую дату независимо от наличия старых дат.

Нулевой Unread показывается как 0. Ошибка/загрузка данных не показывается как 0:
используются Loading… / Unavailable с возможностью повторного чтения.
Описание без полученных метаданных — `Not available`. Описание выводится как текст,
без исполнения разметки. Недоступность метаданных не блокирует Title/Folder.

## Изменения границ и данных

Проверено по исходникам на 2026-10-19:

- `SubscriptionFeed` уже содержит title, folder_id и original_urls. В `FeedPatchRequest`
  и внутреннем FeedPatch нет title; сохранение локального названия нужно добавить.
- `Subscriptions` хранит каталог и изменения параметров; в таблице feeds нет
  требуемых временных меток и описания внешнего источника.
- `Store.discovered` принимает результат обнаружения публикаций; `Store.viewed_set`
  фиксирует «Просмотрено». Это границы записи Last update / Marked read после
  проверки актуальности операции. Непринятый поздний результат дату не меняет.
- Существующий `NavigationFeed.count` считает видимые исходные публикации, исключая
  скрытые; `has_unviewed` — boolean,
  включающий скрытые/незагруженные публикации. Ни один не подменяет определённое выше
  числовое Unread; его нужно получить по полному составу публикаций фида.
- `SourceObservation` передаёт identity и возможности источника, но не общее
  описание канала; `Material.description` относится к отдельной публикации.
- `MenusOwner` уже владеет каталогом, выбранным объектом, черновиками и допуском
  поздних ответов. Новую независимую систему UI-состояния создавать не требуется.

Реализация расширяет канонический API v3: title в существующем PATCH с закрытым
перечнем полей команды; информационный снимок фида в существующем чтении его
настроек. Снимок содержит nullable даты/описание и числовой Unread. Названия wire-полей
и схема определяются в `api/openapi.yaml`; generated Python/TypeScript библиотеки
обновляются по `api/README.md`. Прямое чтение SQLite из frontend и отдельный
параллельный HTTP API не вводятся.

Хранение обеспечивает атомарность Title+Folder+Modified и обновления Marked read
вместе с соответствующей отметкой. Метки времени берутся из управляемых серверных
часов. Повтор без фактического изменения не продвигает Modified/Marked read.
Миграция сохраняет ID, данные и неизвестность старых дат. Все пути создания фида,
включая RSS/YouTube, Telegram, импорт и demo, учитывают новую модель метаданных.

Описание доставляется через результат существующего adapter и сохраняется при
обычном сборе, когда источник действительно его предоставил. Отсутствующее поле
в результате отличается от явно пустого описания: первое сохраняет прежнее,
второе очищает его. Не добавлять отдельные сетевые запросы только ради открытия
редактора; неподдерживаемый источник честно показывает Not available.

Activity обновляется при открытии/возврате на страницу и при уже существующем
обновлении состояния читателя после сбора/просмотра. Ответ относится к конкретному
ID и времени жизни редактора. Новый самостоятельный постоянный polling не нужен.

## Критерии приёмки и план проверки реализации

1. В настоящем редакторе виден вариант B с полным набором полей; Language, Favorites
   и Articles отсутствуют. Длинные значения не перекрывают поля и действия.
2. Title и Folder сохраняются одной командой, переживают перезапуск, обновляют
   деревья и наследование; ID, доступ, история и материалы сохраняются. Ошибка
   любого поля не оставляет частичной записи. Пустое/длинное название отклоняется.
3. Link неизменяемый, не открывается по нажатию; маленькая кнопка копирует точный
   адрес. Проверены несколько адресов, отсутствие адреса и отказ clipboard API.
4. Save/Reset/Cancel действуют только на новый блок. Существующие страницы настроек,
   черновики, удаление и управление историей работают по прежним правилам.
5. Поздние ответы чтения, копирования и записи A после перехода к B или повторного
   открытия A не управляют новым UI. Успешная старая запись всё же отражается в каталоге;
   ввод, сделанный после отправки, не теряется.
6. На временном хранилище проверены смысл и сохранность каждой даты: создание,
   изменение/no-op, удачное/ошибочное/устаревшее discovery, отдельное/групповое
   «Просмотрено», удаление и Telegram read acknowledgement. Старые даты остаются
   неизвестными, повторная миграция безопасна.
7. Unread включает скрытые, незагруженные, недоступные публикации, корректно считает
   альбомы/группировку по исходным публикациям, уменьшается после «Просмотрено»
   и сохраняет новые публикации после завершения старого подтверждённого состава.
8. Описание берётся из метаданных источника; отсутствие, пустое описание, длинный
   текст и потенциальная HTML-разметка обработаны без подмены данными публикации.
9. Контракт/generated drift и типизация проходят. HTTP-проверки используют временные
   SQLite/файлы и синтетические adapters; браузер — Playwright со скриншотами и их
   просмотром. Личные подписки, аккаунты и настоящий обработчик не используются.

Выбрать затронутые существующие наборы настроек, состава чтения, сбора и миграций;
новые сценарии добавить по их ответственности. Перед реализацией сохранить грязный
checkout по `docs/agents/task-changes.md`. Независимое ревью требуется для изменений
состояния/хранения по порядку разработки.

Выбранный макет: `frontend/feed-settings-prototype.html?variant=B`;
исходники — `frontend/src/settings/feed-settings-prototype.{tsx,css,md}`.

реализация выбранного решения, написанная с обычными проверками; остальные варианты
и переключатель удаляются после сохранения первичного источника.
