### Сохранённые критерии

Идентификатор C — прежний номер тикета и номер критерия; он сохраняет прослеживаемость после перенумерации. Составные пункты читаются с распределением ответственности в индексе задач.

- [ ] **C07.01** RuntimeStatus содержит lifetime/runtime_state и typed work entries; клиенты не должны сравнивать русскую строку stage.
- [ ] **C07.02** Problems сохраняют identity, current/retrying/finished, affected resources, времена, последствия и недавнюю историю.
- [ ] **C07.03** RecoveryIntent закрыт по kind; нужные target/fields обязательны, неизвестное действие и material без ID отклоняются.
- [ ] **C07.04** Backend и Store не формируют page/home/field/menu/reconnect-screen; рекомендации предметные и проходят повторную server admission при выполнении.
- [ ] **C07.05** Публичные problem codes имеют полный mapping producer; внешние exception names не расширяют enum; legacy записи сохранены без ложного действия.
- [ ] **C07.06** План и реализация адаптации сохранённых проблем не теряют identity, timestamps, причины и завершённые исходы.
- [ ] **C07.07** Recovery не содержит OPML/topics; profile/source identity конфликты, неподтверждённая роль и локальная очистка отображаются предметными code/target, а не экраном или текстом popup.
- [ ] **C07.08** reconnect_feed не генерируется и не принимается как новый recovery. Старый source-reconnect не превращается в ложную команду. Для известной роли предлагается configure_telegram_profile; для legacy без роли сохраняются affected feed/привязка без выдуманной цели.
- [ ] **C07.09** Конфликт identity не предлагает изменение binding или автоматические delete/connect; смена источника требует отдельного явного действия пользователя.
- [ ] **C10.04** Панель строит тексты и порядок по стабильным кодам, recovery intent отображается в локальную навигацию и typed команды.
- [ ] **C10.05** Сохранены раскрытая завершённая проблема, стабильный порядок/фокус, счётчик текущих проблем и неизвестный исход действия.
- [ ] **C10.07** Панель не содержит dispatch для reconnect_feed; историческая проблема отображается без исполнимой старой команды. Проблема legacy без роли отображается без fabricated role.
- [ ] **C11.06** Все переходы из предметных recovery реализованы здесь локально, без ожидания page от backend.

Дополнительно: проверить все критерии этого тикета через указанные выше HTTP/UI-сценарии. В задаче 01 проверки остальных семейств относятся к гарантиям инструментария; их полное поведение принимается в соответствующих задачах 02–06.

## Границы и проверка результата

Все требования родительской спецификации, дизайна контракта и исправления ревью обязательны. Здесь меняется разбиение работы, не продуктовый объём. Типы и ошибки сценария, серверный путь, generated consumer и существующий UI проверяются вместе. Поздние ответы, отмена, no-store, bearer своего origin и ограничения host/origin сохраняются. Новых клиентов, remote auth, личных подключений, редизайна, ORM, универсального scheduler или автоматического replay не добавлять.

Проверки используют настоящий HTTP, временные SQLite/файлы и синтетические источники/модели; браузер — Playwright. Для затронутого UI сделать и просмотреть desktop/mobile screenshots. Computer Use и личные аккаунты/модели не использовать. Проверять наблюдаемое поведение, не расположение внутренних модулей. Предметные DTO не обходить Any/cast, generated-файлы не править вручную.

Фактические команды, результаты, неудачные прогоны, ограничения и артефакты записать отдельно. Candidate допускает поведенческие проверки до baseline, но PENDING_REVIEW не является PASS совместимости или разрешением выпуска. Обычные gates сохраняют строгость. Исторические отчёты не переписывать; служебные миграции обратимы, материалы и настройки сохраняются. По умолчанию работает один исполнитель; зависимости не означают поручения параллельным агентам. Коммит, публикация и перезапуск пользовательского экземпляра не входят в задачу.
