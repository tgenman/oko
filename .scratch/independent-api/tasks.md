## Порядок

В каждой функциональной задаче контракт, сервер, generated consumer, веб-сценарий и проверки проходят вместе. Задача 01 сначала подготавливает контракт/инструментарий и демонстрирует запуск/сессии. Затем перенос выполняется в общей непубликуемой интеграционной ветке через expand–contract: прежний путь временно доступен, каждый завершённый срез проверяем отдельно; полный обычный PASS обещается после интеграции 07. Baseline обновляется только после полного candidate evidence и semantic review, затем проходят обычные gates. Временная смесь API не выпускается.

Зависимости — результаты, необходимые для начала, не поручение параллельным агентам. По умолчанию один исполнитель. Входные решения: [удаление групповых результатов](../remove-aggregate-summaries/spec.md) и [Telegram-план](../telegram-access/spec.md). Telegram modules — внешняя зависимость задачи 05, без отдельного предварительного breaking release. Общий выпуск не готов без их реального evidence.

## Составные критерии и границы ответственности

- C01 и C02 в задаче 01 задают полный контракт и общую строгость. Они не требуют переноса всех handlers/UI до задачи 02; каждый последующий срез доказывает эти гарантии на своих операциях, задача 07 проверяет полноту.
- C05.02: общие PATCH-правила и отказ смены binding — 02; новые web/client и подтверждение прежних привязок — 05.
- C06.01 и C11.04: удаление OPML и сохранение RSS/YouTube forms — 04; удаление публичных тем и новые Telegram forms — 05; processor forms — 02. Полный составной пункт закрывается в 05.
- C06.09: настройки/каталог/проверка обработчиков — 02; RSS verify/add и YouTube credentials — 04. В 04 проверяется сохранение обеих частей.
- C05.06, C05.08, C11.09: общие типы, default AddFeed, отсутствие старой истории и её отображение — 04; конкретные Telegram default/history/live/manifest — 05. Итоговая проверка составных пунктов — 05.
- Receipts, producer ошибок и минимальное отображение исхода первой настройки готовы в 02. Каждый последующий срез добавляет свои коды/ошибки и локальный UI. Объединение панели в 06 не блокирует работоспособность предыдущих срезов.
- Независимый запуск и package smoke — 01; отключение старых routes и удаление переходных consumers — 07. Миграция receipts — 02, проблем — 06, общий откат — 07.

## Завершение

Задача готова после доказательства своего сквозного результата и сохранённых критериев в её области. Полный результат требует реализации всех семи задач, предметных Telegram-зависимостей, независимого ревью и обычных gates после baseline. Наличие YAML или зелёного typecheck само по себе не является готовностью.
