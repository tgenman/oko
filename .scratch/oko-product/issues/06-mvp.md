## Question

Какой минимальный набор согласованных сценариев достаточно полезен для перехода в Око? Какие ограничения по периодичности работы на компьютере, времени ожидания, затратам, хранению и передаче содержимого приватных источников на обработку нужно учесть перед техническим проектированием?

## Comments

### Ограничения запуска и обработки: ответы пользователя 2026-10-07

- Предпочтительный обработчик — Codex: «в идеале это должен делать кодекс». Это предпочтение, а не подтверждение технической интеграции или бюджет отдельного платного API. Совместимость исследуется в вопросе [«Подключение Codex для обработки материалов»](08-codex-processing.md).
- Нужна галка фида с точной формулировкой «Разрешить обработку публичным AI». Значение по умолчанию не выбрано. Поведение при выключенной галке уточняется: оригиналы без ИИ либо иной способ обработки. Фраза пользователя «И ещё дополнительно» не содержала законченного дополнительного требования.
- Пользователь отклонил постоянную фоновую работу независимо от открытого Око. Желаемый сценарий: открыть Око, оставить обрабатывать, затем читать готовое. Приложение работает только пока включено пользователем; способ технически привязать остановку к закрытию уточняется при проектировании запуска. Закрытие одной вкладки при нескольких открытых и другие детали не выбраны.
- Фраза об индикаторе окончания обработки распозналась неоднозначно. Уточняющий вопрос задан; наличие и вид индикатора пока не утверждены.
- Подтверждён первоначальный импорт всего OPML с папками; история по умолчанию — последние сутки с возможностью выбрать период для конкретного фида. Накопленный непрочитанный список News Explorer не переносится автоматически.

Вопрос не закрыт до уточнения индикатора и режима фида с запрещённым публичным AI. Подключение Codex проверяется независимо, без передачи контента пользователя.

Исследование выполнимости завершено: [Подключение Codex для обработки материалов](08-codex-processing.md). Поддерживаемые программные способы существуют; фактический доступ по подписке и пригодность для требуемого объёма остаются непроверенными. Конкретный способ интеграции не выбран.

### Уточнение пользователя: индикатор и свои модели

Пользователь подтвердил индикатор и уточнил: нужна функциональность подключения кастомных моделей, например развёрнутых локально через Ollama. Предложение оставлять только оригиналы при запрете публичного AI не принято как единственный режим.

## Answer

Согласованные границы первой версии и условия проектирования:

1. Источники — публичный и приватный Telegram, YouTube и RSS. Ранее выбранные сценарии чтения, фильтрации, сводок, сжатия и удаления просмотренного остаются в описании первой версии. Подкасты отложены.
2. Предпочтительный обработчик — Codex; дополнительно нужны подключаемые кастомные модели, включая локальные через Ollama. Галка «Разрешить обработку публичным AI» относится к допустимости внешней обработки, а не к запрету любого ИИ. Техническая выполнимость Ollama проверяется в [отдельном вопросе](09-custom-models.md).
3. Наличие локального режима не означает подтверждённого выбора конкретной модели, её скорости или качества. Отдельный платный API и денежный бюджет не выбраны. Поведение выбора обработчика, наследование этой настройки и состояние без доступного разрешённого обработчика проверить на макете; запрещённый публичный AI не должен включаться скрыто.
4. Око работает только пока явно включено пользователем. Сценарий: открыть, оставить на обработку, затем читать. Постоянной фоновой обработки при закрытом Око нет; расписания ограничены временем работы приложения.
5. Нужен индикатор: число обработанных источников из общего числа, текущий этап и итог «Готово» либо «Завершено с ошибками».
6. На первом запуске импортируется весь OPML с папками, история по умолчанию — последние сутки с возможностью выбрать период фида. Накопленный список непрочитанного News Explorer автоматически не переносится.

Детали настроек и поведения UI остаются предметом следующего макета; конкретный стек, интеграции, производительность и работа на реальных данных здесь не утверждались.
