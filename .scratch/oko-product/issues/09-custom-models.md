# Подключение своих моделей через Ollama

## Question

Какие официально поддерживаемые интерфейсы Ollama подходят для подключения локальной модели к Око: адрес сервера, выбор модели, структурированный ответ, потоковый результат и ошибки? Как различить локальное выполнение и облачные возможности Ollama, чтобы галка «Разрешить обработку публичным AI» имела определённый смысл? Установку, запуск и скачивание моделей не выполнять. Проверить только достаточность интерфейса для проектирования настроек и будущего узкого эксперимента; не выбирать модель или стек реализации.

## Context

Пользователь: «там надо будет функциональность подключения кастомных моделей. Например развернутых локально. Через olama». Название продукта нормализовано как Ollama. Предложение оставлять фид без ИИ при выключенной галке публичного AI не принято: нужна возможность своей обработки.

Исследование — отдельный Markdown-документ; Git в проекте не инициализирован, исследовательскую ветку не создаём.

## Answer

Интерфейсов Ollama достаточно для проектирования подключения: серверный адрес, список и выбор модели, структурированный ответ, поток и признаки завершения/ошибки документированы. Подробности и официальные источники: [исследование Ollama](../../../docs/research/ollama-processing.md).

Ollama поддерживает как локальные, так и облачные возможности; название обработчика само по себе не определяет допустимость для фида с запрещённым публичным AI. Для требуемого сценария нужна именно локальная модель и проверка режима подключения. Установка, запуск модели, чтение пользовательских настроек и проверка производительности не выполнялись.
