# Полнота материалов и поведение при недоступности

## Question

Что пользователь ожидает увидеть для Telegram-медиа, RSS-статьи и YouTube-видео, если оригинал, медиа или субтитры недоступны? Нужны ли офлайн-просмотр и хранение полной истории; как показывать неполный сбор, правки и удаления источников? Какой результат считать достаточным для отметки «получено» перед автопрочитыванием?

## Comments

### Подтверждено пользователем 2026-10-07: загрузка материалов

В ответ на вопросы о Telegram-медиа, YouTube, RSS и неполной загрузке пользователь ответил: «1 да / 2 видео не нужно конечно / 3 ок / 4 ок».

- Telegram: картинки, видео и кружочки скачиваются на компьютер заранее вместе с публикацией для просмотра внутри Око.
- YouTube: само видео скачивать не нужно. Ответ подтверждает именно это; предложение отложить расшифровку аудио при отсутствии субтитров отдельного подтверждения пока не получило.
- RSS: пытаться получать и сохранять полный текст статьи с изображениями. Если это не удалось, показывать доступный анонс и ссылку с явной пометкой, что статья неполная.
- При неполной загрузке показывать уже доступную часть со статусом загрузки и возможностью повторной попытки.
- Для Telegram с включённым автопрочитыванием отмечать пост прочитанным только после сохранения всего материала, включая медиа.

На момент этого раунда оставались открыты срок хранения, поведение при правках и удалении оригиналов, отсутствие субтитров YouTube. Уточнения следующего раунда записаны ниже.

### Подтверждено пользователем 2026-10-07: недоступность и удаление после просмотра

Ответ пользователя: «1 ок / 2 ок / 3 просмотрено удаляет контент».

- Если субтитры YouTube недоступны, в первой версии оставлять карточку без summary с пометкой «Субтитры недоступны» и ссылкой на видео. Расшифровка аудио отложена.
- Если Око обнаружит удаление оригинала источником, сохранённая копия остаётся доступной. Это действует до локального удаления по отметке «Просмотрено».
- При обнаруженной правке показывать новую версию с отметкой «Изменено», предыдущую сохранять для раскрытия; затронутую сводку обновлять. Хранение версий также подчиняется удалению контента по отметке просмотра.
- Пользователь отклонил предложенное бессрочное хранение просмотренного: действие «Просмотрено» удаляет контент из Око. Это меняет прежнюю модель хранения оригиналов после просмотра; сама генерация сводки не является удалением.

На момент этого раунда оставался открытым точный состав удаления. Финальное уточнение записано в ответе ниже.

## Answer

Согласовано по результатам раундов выше; финальное «ок» пользователя 2026-10-07 подтвердило состав удаления и различие локального просмотра и автопрочитывания Telegram.

1. Telegram-текст и медиа (картинки, видео, кружочки) сохраняются локально заранее. Для источника с включённым автопрочитыванием отметка в Telegram выполняется после сохранения всего материала.
2. YouTube-видео не скачивается. При недоступных субтитрах остаётся карточка без summary с явной пометкой и ссылкой на видео; расшифровка аудио отложена за пределы первой версии.
3. Для RSS нужно пытаться сохранить полный текст статьи с изображениями. Если получение не удалось, остаются доступный анонс и ссылка с обозначением неполноты.
4. Частично загруженный материал показывается сразу со статусом загрузки и возможностью повторной попытки.
5. При обнаруженном удалении оригинала источником локальная копия сохраняется до отметки просмотренным в Око. При обнаруженной правке показывается новая версия с отметкой «Изменено», предыдущая доступна для раскрытия, затронутая сводка обновляется. Это желаемое поведение при обнаружении события, не утверждение о гарантированном обнаружении всех изменений каждым адаптером.
6. Явная отметка новости или сводки «Просмотрено» удаляет её контент из Око. Для сводки удаляются сама сводка и все обработанные ею исходные тексты, медиа, субтитры и сохранённые версии. Правило охватывает весь обработанный набор, включая материалы, исключённые фильтрами из текста сводки.
7. Остаются только служебные данные — идентификаторы, ссылки, отметки обработки, — чтобы не загружать просмотренное повторно. Архив прочитанного содержимого не сохраняется.
8. Автопрочитывание в Telegram при получении не удаляет локальный контент. Локальное удаление запускается явной отметкой «Просмотрено» в Око. Само открытие, копирование ссылки, генерация или сжатие сводки не являются согласованными триггерами удаления.

Автоматический срок удаления непросмотренного не задан. Последующее решение [«Повторы новости после удаления просмотренного»](12-dedup-after-view.md) исключает хранение смыслового описания после просмотра; дедупликация ограничена оставшимся контентом и служебными идентификаторами. Технический состав служебного состояния для повторной попытки синхронизации с Telegram предстоит определить без сохранения удаляемого содержимого.
