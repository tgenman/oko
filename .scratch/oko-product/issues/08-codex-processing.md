## Question

Каким поддерживаемым способом локальное Око может вызывать Codex для фильтрации и summary через существующий доступ пользователя? Проверить программный запуск, авторизацию через подписку, структурированный результат, прогресс, остановку обработки при закрытии Око и ограничения. Отдельно выяснить, где могут сохраняться копии входного контента, с учётом требования удалять просмотренное из Око. Не запускать обработку пользовательских материалов, не менять настройки и не читать секреты.

## Context

- Пользователь: «в идеале это должен делать кодекс».
- Продуктовые материалы: [CJM и требования](../../../docs/discovery.md), [Полнота материалов и поведение при недоступности](05-media.md).
- Существующие локальные средства и текущие официальные источники проверяются только чтением. Репозиторий пока не инициализирован как Git; вместо создания исследовательской ветки результаты сохраняются отдельным документом, без изменения Git-состояния.

## Answer

Проверено 2026-10-07: [исследование подключения Codex](../../../docs/research/codex-processing.md).

Программный запуск поддерживается установленным CLI; документированы обработка отдельных заданий и протокол приложения с прогрессом и отменой. Запуск через существующий ChatGPT-вход технически возможен, но фактическая авторизация пользователя, квоты и производительность для его подписок не проверялись. Рекомендуемый следующий шаг — ограниченная проверка интеграции после выбора архитектуры; реализация и запуск модели в этом исследовании не выполнялись.

Ключевые условия для продуктового решения: Codex с OpenAI-моделью является облачной обработкой и подчиняется галке фида; запрет должен исключать косвенное чтение запрещённых материалов. Удаление локального контента не означает удаления данных у провайдера. Сохранение локальных копий входа/ответа и остановка при закрытии приложения требуют отдельной проверки выбранного способа интеграции. Детали и источники находятся только в исследовании по ссылке.
