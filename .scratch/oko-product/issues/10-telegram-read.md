# Отметки прочитанного Telegram при чтении не по порядку

Type: research
Label: wayfinder:research
Status: resolved
Assignee: codex
Parent: ../map.md
Blocked by: none

## Question

Позволяет ли Telegram API отметить отдельные произвольно выбранные сообщения прочитанными, не затрагивая более ранние непросмотренные? Проверить приватные каналы и группы, влияние max_id и границы чтения. Каковы ограничения согласованного правила Око: без автопрочитывания отражать явный просмотр новости или сводки в Telegram, хотя пользователь может читать не по порядку? Исследовать только документацию и исходный код, не читать реальные сообщения и не менять read state.

## Context

Правила: [сжатие и просмотр](01-history.md), [удаление просмотренного](05-media.md), [режимы фидов](02-prompts.md). Сбор ведётся только при работе Око. Результат сохранить отдельным исследовательским документом; Git не инициализирован, ветку не создавать.

## Answer

Подтверждено по официальным исходникам Telethon: обычная отметка истории накопительная, до указанного max_id включительно. Отметить сообщение 120 прочитанным, сохранив 119 непрочитанным в том же диалоге, этим способом нельзя; переданный список сообщений также сводится к максимальному ID. Это касается обычной истории каналов, обычных групп и supergroups; forum topics отдельно не проверены.

Полный результат, ссылки, границы проверки и рекомендации: [исследование прочитанного Telegram](../../../docs/research/telegram-read-state.md). Прямые страницы Telegram в этом исследовании были недоступны; подтверждение получено из живого официального репозитория Telethon. Реальные сообщения и read state не затрагивались.

Продуктовый выбор способа синхронизации и начальной границы выделен в отдельный вопрос. Отложенное продвижение границы — предложение, а не автоматически принятое решение.
