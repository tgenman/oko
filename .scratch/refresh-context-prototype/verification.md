# «Обновить» в меню папки и фида — прототип, 2026-10-19

Вопрос: единая команда собирает новое от текущего указателя и повторяет незавершённые загрузки и ошибки сбора в выбранной области.
Источник: frontend/refresh-context-prototype.html. Ветка скилла LOGIC; автономный HTML, данные в памяти.

## Фактическая проверка

Playwright с headless Google Chrome. Все кнопки пяти пошаговых сценариев нажаты последовательно: один фид, вся папка, повторный сбой, пересечение запусков, новое во время сбора. Каждый сценарий достиг сообщения о завершении; ошибок JavaScript не было. Это проход демонстрации, не автоматические тесты корректности модели.

На узком экране нет горизонтального переполнения документа; таблица состояния прокручивается внутри блока.
Первый запуск Chrome в sandbox завершился SIGABRT; запуск с разрешённым доступом выполнен успешно.

## Ограничения и решения

Реальный HTTP interface, личные подписки, загрузки и обработчик не использовались. Основной интерфейс не изменён. Полные проверки приложения не запускались. Новый HTML не входит в вывод обычного git diff --check, поскольку ещё не добавлен в индекс.

Поведение ошибок ИИ-обработки и правила допустимости ретраев не определены. Защита от повторного запуска, граница текущего сбора и независимость фидов показаны как предположения для обсуждения.

Вердикт пользователя ещё не получен; переноса в рабочий код, архивирования на throwaway-ветке и публикации в issue пока нет. Сохранение первоисточника на ветке и указателя в issue выполняется после выбора поведения согласно prototype/LOGIC.md.
