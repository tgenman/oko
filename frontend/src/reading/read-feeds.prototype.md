# THROWAWAY: показ прочитанных фидов

Вопрос: где разместить переключатель показа фидов, в которых всё просмотрено?
Вердикт пока не выбран: пользователь сравнивает A/B/C. Это UI-прототип, не реализация продукта.

```sh
npm run prototype:read-feeds
```

- http://127.0.0.1:5187/?variant=A — кнопка над деревом, прочитанные возвращаются в свои папки.
- http://127.0.0.1:5187/?variant=B — фильтры «С новыми / Все / Прочитанные».
- http://127.0.0.1:5187/?variant=C — отдельный сворачиваемый раздел прочитанных фидов.

Внизу страницы: стрелки вариантов, клавиши ←/→, сброс и полное состояние. Изменяется только URL выбранного варианта; остальные данные находятся в памяти страницы. «Просмотрено · завершить пример» меняет только синтетический фид. Backend, личные подписки, авторизация и Telegram не используются.

Рядом используются настоящая оболочка ReaderShell и CSS читателя. Vite-конфигурация подменяет entry только для команды прототипа на существующем маршруте `/`. Реальный main.tsx не меняется. Переключатель/варианты отсутствуют в штатной production-сборке.

Предварительные правила для обсуждения:

- По умолчанию прочитанные фиды скрыты. Все материалы и сам фид остаются сохранены согласно обычным правилам Око; переключатель меняет только навигацию.
- Фид с ещё не просмотренными скрытыми материалами не считается прочитанным. Пример «Рабочая группа» имеет нулевой видимый счётчик и два скрытых материала. Для реализации нельзя приравнивать существующий feed.count===0 к полному завершению разбора: нужен серверный признак с учётом скрытых/незагруженных публикаций.
- Когда просмотрен последний материал выбранного фида, текущий фид остаётся видимым до смены выбора. Это позволяет оценить переход без внезапного исчезновения текущего контекста.
- У полностью пустой папки в A/B нет строки в режиме «С новыми». В C прочитанные фиды сгруппированы отдельно с указанием прежних папок.
- Речь о разборе в Око, а не о внешней отметке «прочитано в Telegram».

Проверено интерактивным просмотром в Playwright: переключатели трёх вариантов показывают 8 примерных фидов; завершение текущего оставляет его видимым; стрелка вправо меняет variant в URL. Скриншоты A/B/C просмотрены, page errors отсутствуют. Автоматические тесты продукта не добавлялись, как требует prototype.

После выбора варианта его нужно реализовать и проверить отдельно в основном интерфейсе. Эту ветку с вариантами не сливать в main; сохранить её как первичный источник решения.
