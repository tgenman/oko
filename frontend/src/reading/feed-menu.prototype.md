Вопрос: какой способ вызова делает действия фида понятными и доступными, сохраняя удобное переключение между фидами?

Запуск: `npm run prototype:feed-menu` → http://127.0.0.1:5188/?variant=A

- A: компактное контекстное меню по правому клику; обычный клик выбирает фид.
- B: видимая кнопка «⋯» открывает меню с подсказками; правый клик тоже работает. Обычный клик выбирает фид.
- C: обычный клик выбирает фид и раскрывает две строки действий под ним.

Внизу переключатель A/B/C, стрелки клавиатуры, сброс и полное состояние примера. Вариант хранится только в URL; данные — только в памяти. Макет встроен в настоящий ReaderShell на существующем маршруте `/`, запускается отдельным Vite entry point только в DEV, не обращается к API.

## Поведение для обсуждения

1. «Прочитать всё» всегда выше «Удалить»; удаление выделено красным.
2. «Прочитать всё» завершает разбор всех известных материалов фида, включая скрытые; фид остаётся подключённым. Если материалов нет, действие выключено. Открытый завершённый фид остаётся видимым, как в #31.
3. «Удалить» требует подтверждения с названием и последствиями; отмена ничего не меняет.
4. Для веб-доступа удаляется локальный фид целиком со всеми его материалами.
5. Предварительная трактовка для доступа через аккаунт: локальный фид и материалы удаляются, подключённый аккаунт и внешняя подписка в Telegram сохраняются. Пользователю задан уточняющий вопрос: требуется ли дополнительно сохранять запись самого фида в Око. Ответ пока не получен; этот пункт не является утверждённым решением.
6. Вопрос реальной отметки Telegram при «Прочитать всё» нужно согласовать с существующей безопасной границей и настройками автопрочитывания. Макет не посылает никаких внешних отметок и не устанавливает новую серверную семантику.
