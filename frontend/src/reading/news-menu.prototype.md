# Прототип контекстного меню новости

THROWAWAY. UI-варианты на существующем маршруте `/` внутри ReaderShell. Вопрос: как расположить пять действий отдельной карточки и понятно показать охват Above/Below?

Запуск: `npm run prototype:news-menu` → http://127.0.0.1:5189/?variant=A

- A — компактный список по правому клику, в том же стиле, что утверждённое меню фида.
- B — группы This publication / Current list, числа затрагиваемых новостей.
- C — широкое меню, чтение и действия оригинала в двух колонках.

Нижняя плавающая панель и стрелки ←/→ переключают варианты, URL сохраняет вариант при обновлении. Данные только в памяти; «Состояние» показывает выбранную область, сортировку, открытую карточку, цель меню, охват, captured IDs подтверждения, последнее действие и все оставшиеся новости. Reset возвращает пример. DEV-only entry point и отдельный Vite config не подключают production API.

## Действия

1. Mark Above as Read
2. Mark Below as Read
3. Mark as Read
4. Open in Browser
5. Copy Link

Правый клик действует на карточку под указателем и не меняет открытый материал. Обычный клик открывает материал.

Предварительная семантика для обсуждения: Above/Below — все карточки выше/ниже цели в текущем показанном списке, включая находящиеся за границей viewport. Учитывается выбранный фид и текущая сортировка (новые/старые/важность); сама цель исключена, материалы вне области не затрагиваются. В первой/последней строке пустое действие выключено. Скрытых карточек в примере нет; рабочая реализация должна явно определить, что диапазон относится к показанному списку, а не ко всем скрытым публикациям фида.

При наведении подсвечивается охват. Для диапазона показывается подтверждение точных ID и заголовков; отмена ничего не меняет. Single Mark as Read удаляет из примера только цель. Открытый материал остаётся, если его ID не попал в действие.

Open in Browser открывает новую вкладку с локальным оригиналом примера (`?original=id`), Copy Link копирует тот же адрес в clipboard. В рабочем продукте обе команды должны использовать настоящий source_url публикации, не URL reader/material API. Оригиналы примера — явно помеченные синтетические страницы, внешних сетевых запросов нет.

## Решение

Вариант и семантика Above/Below ещё не утверждены. Пользователь запросил прототип; production-реализация, ПР и мерж в этот объём не входят. Прототип сохраняется в отдельной ветке как первичный источник.

## Фактический просмотр

Playwright + Chrome, 1440×980, синтетические данные. A/B/C: вызов меню, подсветка и завершение диапазона без цели, выключенный Above у первой строки, single read, правильная цель Copy Link (проверен clipboard) и Open in Browser (проверена новая локальная вкладка). Отдельно проверены обратная сортировка и изоляция выбранного фида. Ошибок страницы нет. Сняты и просмотрены A/B/C screenshots в `.scratch/check-runs/news-menu-prototype/`.

Первый просмотр остановился в варианте B: счётчик входил в accessible name. Всем пунктам задан одинаковый aria-label, повтор прошёл. После корректировки высоты позиции B (чтобы меню не перекрывалось панелью вариантов) повторный просмотр также прошёл. Полный CI и production-тесты не запускались; рабочие данные/аккаунты не использовались.
