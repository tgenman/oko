# Доменные документы

Око использует один доменный контекст (single-context):
`GLOSSARY.md` в корне и решения в `docs/adr/`.

Перед исследованием кода прочитай `GLOSSARY.md` и ADR,
относящиеся к задаче. Документы `docs/architecture/` выбирай
по затронутому сценарию согласно `AGENTS.md`.

Если доменный документ отсутствует, продолжай без отдельного
предупреждения и предложения создать его. Скилл `domain-modeling`
создаёт документы по мере согласования терминов и решений.

В задачах, предложениях, гипотезах и названиях тестов используй
термины глоссария. Если нужного понятия нет, проверь необходимость
нового термина и отметь пробел для `domain-modeling`.

Если предложение противоречит ADR, явно укажи решение,
противоречие и причину его пересмотра.
