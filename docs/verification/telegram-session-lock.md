# Telegram: одновременная проверка профиля и сбор

2026-10-16. База: `b17337c0c99dcff91cceaff2852b18551b9f7622` (`main`, совпадает с `origin/main` при проверке).

## Причина и исправление

При известном user ID и ещё не созданном collection worker параллельные
`LocalTelegram.identity(account)` и `info(account, peer)` открывали два собственных
процесса для одной Telegram-сессии. Временная проверка профиля и сбор конкурировали
за настоящий POSIX `SessionLock`; проигравший получал
«Telegram-сессия занята другим клиентом».

Блокировка аккаунта согласует проверку личности и регистрацию collection worker.
Сначала заканчивается временная проверка и закрывается её процесс либо проверка
использует уже зарегистрированный worker. Сетевой запрос сбора выполняется за
пределами этой блокировки. Разные аккаунты сохраняют отдельные блокировки и pipes;
защита сессии от другого приложения остаётся действующей.

блокировка сессии настоящая. До исправления команда

## Настоящие аккаунты

Использованы существующие настройки двух разных аккаунтов, без копирования
credentials. Проверки выполнялись последовательно, на отдельных временных данных.

- `session_race.py --baseline`: исходная реализация воспроизвела занятую сессию на **обоих** аккаунтах. По две одновременные операции на аккаунт: проверка личности и получение информации публичного канала.
- `session_race.py`: та же проверка с исправлением прошла на обоих аккаунтах; обе операции успешны, busy session отсутствует.
- `http_candidate.py`: production HTTP interface подтвердил оба профиля, отклонил один аккаунт в двух ролях и повторное подключение одного источника. Публичный пост `@telegram` с изображением полностью сохранён. Три последовательных цикла перепроверки обоих профилей и запроса сбора завершились без текущей проблемы занятой сессии.
- `browser.cjs`: перезапуск обычного HTTP-сервера, повторная проверка обоих профилей, запрос сбора, получение материала и локального JPEG (215572 байта), открытие материала и декодирование изображения настоящим Chrome через Playwright — успешно. Desktop screenshot просмотрен. В текущих проблемах остался только намеренно вызванный `duplicate_source` из отрицательной проверки.

Приватные сценарии, receipts и screenshots находятся в игнорируемой
`.scratch/check-runs/live-telegram/` worktree исправления. Они не публикуются.
