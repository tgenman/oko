# Повторная подготовка тестов: измерения и ускорение

Дата: 21 октября 2026. База: `6e4843efc8025a048fff182f3d3abcc6a7ba9069`.
Ветка: `codex/test-fixture-cost`. Рабочая установка и настройки Око не менялись.

## Сделано

- `scripts/run-browser-tests.cts` владеет одним экземпляром Chromium на команду
  node --test. Файлы подключаются независимо, сценарии сохраняют отдельные contexts,
  HTTP-приложения и временные хранилища. Performance остаётся отдельной командой.
- Владелец очищает свою process group и Chromium при любом исходе. SIGINT/SIGTERM
  передаются группе; оставшиеся потомки получают SIGTERM, затем при необходимости
  SIGKILL. Живые члены группы проверяются через ps (PGID/stat), без zombie processes.
  Ошибка доступа к живой группе остаётся ошибкой. Прямой запуск файла без wrapper
  сохраняет прежний собственный Chromium.
- Записанный Telegram-альбом через HTTP загружается отдельно от 18 посторонних
  публикаций. Все 19 публикаций исходной страницы и отсутствие одиночных карточек
  для девяти частей проверяются parser. HTTP сохраняет проверки девяти members,
  девяти локальных видео, полноты материала и отсутствия отдельных частей.
- API YAML читается CSafeLoader при наличии, иначе SafeLoader. Проверка полного
  нормализованного контракта дала одинаковый SHA256 у обоих loaders:
  `bdb00ed76f4ca7fc4aad0410a2517f4c598826787415c305742c65cd65cec281`.
  Оба отвергли unsafe Python object tag. Отдельный paired probe: 0,700s → 0,099s;
  под нагрузкой другой probe дал 2,179s → 0,427s. Это цена парсинга, не полного набора.
- В YouTube future-live fixture reader presence создаётся до подключения, убрана
  смена importance после старта captions. Она могла отменить уже начавшийся worker
  и включить admission wait. Настоящий subprocess/SDK, диагностика, tombstone,
  отсутствие повторных загрузок и restart остаются проверенными.

Product runtime, HTTP handlers и defaults не менялись. Новые skips, увеличение
таймаутов, автоматические retries или кэширование исходов тестов не добавлены.

## Оставшийся крупный резерв

cProfile выборки 20 HTTP cases: 25 созданий приложения, 1575 регистраций маршрутов.
Регистрация API заняла 2,65s из 5,35s runtest-фазы; основной CPU внутри неё —
повторная компиляция Pydantic response fields. Профилирование само добавляет overhead:
эти числа нельзя напрямую умножать на размер полного набора.

Следующая архитектурная граница — компиляция неизменных HTTP validators один раз
при независимой привязке Runtime/Store каждого приложения. Здесь она не менялась:
это отдельный продуктовый рефакторинг, который должен сохранить runtime validation,
response serialization и изоляцию приложений. До прежних 90 секунд текущий набор
пока не ускорен.
