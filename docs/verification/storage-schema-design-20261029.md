## Что выполнено

Скрипт Python прочитал SQL-блоки пяти физических схем и сверил декларации
CREATE TABLE, колонки, имена индексов и ссылки REFERENCES. Он не отправлял SQL
в PostgreSQL и не является SQL-парсером.

| Структурная проверка | Результат |
| --- | --- |
| Число уникальных CREATE TABLE | 20 |
| Суммарное число описанных колонок | 150 |
| Имена колонок внутри каждой таблицы | Без повторов |
| Явно объявленные индексы | 22, имена не повторяются |
| REFERENCES на описанные таблицы/колонки | Проверены 15 ссылок, неизвестных целей нет |
| Сопоставление с картой прежних 44 таблиц | Совпадает: 14 убираются, 10 объединяются, 20 остаются с заменой items → publications |
| CREATE TRIGGER/FUNCTION в целевых DDL-блоках | Отсутствуют |
| Локальные Markdown-ссылки и парность fences | Проверены |
| Пробельные ошибки и diff задачи | Проверены |

UNIQUE/PRIMARY KEY создают дополнительные индексы автоматически; 22 — только
явно записанные CREATE INDEX, не обещание общего размера каталога PostgreSQL.
REFERENCES проверены на наличие имени, не на работоспособность реального FK.

Синтаксис Mermaid и DDL просмотрен вручную. Локальный pglast/Mermaid-парсер
недоступен. NULLS NOT DISTINCT сверён с документацией PostgreSQL; кумулятивный
max_id — с документацией Telegram. Ссылки на первичные источники стоят рядом
с соответствующими решениями в проектах.

Изменения отделялись от прежнего dirty checkout снимками `scripts/task_changes.py`.
В последнем проходе добавлены два проекта (Telegram/history и служебные таблицы),
этот отчёт и уточнены общий проект и ссылки фидов. Код приложения, SQL-миграции,
настоящий индекс Git и рабочая установка не изменялись.

## Что ещё не проверено

- Исполнение целевого DDL, ограничения и PostgreSQL-планы запросов.
- Перенос конкретных данных, неизвестных дат, конфликтов идентичности и старых run.
- Полнота перевода всех писателей/читателей кода и удаление прежних функций/views.
- Поведение HTTP/Playwright, конкурентные захваты и гонки удаления.
- Сбои файлового сохранения, восстановление и внешняя отметка Telegram.
- Цена вычисления ETag/counts без таблиц версий и время графовых транзакций.

План этих проверок находится в проекте. Структурная сверка не заменяет их и не
делает проект ready-for-agent автоматически. Перед реализацией нужна сверка
актуального main и завершённого HTTP-перехода, затем конкретный план изменений
кода и миграции. Действующие миграции нельзя переписывать.
