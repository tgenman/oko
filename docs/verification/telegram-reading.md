## Поведение через API

Граница согласована ранее: API Око с настоящими временными SQLite и файлами, синтетическим внешним Telegram. Персональные сообщения и секреты не используются в fixtures.

`tests/test_telegram.py` проверяет подключение публичного канала и приватной обычной группы, явные ошибки доступа/forum, повтор подключения, исходную ссылку, объединение альбома, изображение/видео/кружочек, неполную загрузку и повтор после перезапуска, сохранение ID частей, удаление всех файлов, поздний ответ после просмотра, независимость ошибок фидов, несколько страниц и возобновление позиции, прерывание фиксации страницы и файлов, сохранение импортированного фида, отдельный курсор Telegram после RSS. Настройки прочитанного включаются в тесте, но внешняя граница не предоставляет ack-операций: они не вызываются.

Дополнительный API-тест запускает настоящий процесс `telegram_worker.py` через `LocalTelegram`, подменяя только внешний SDK и runtime существующего клиента в отдельном синтетическом проекте. Проверены расширение альбома у границы страницы, канал pipe и принудительное завершение во время записи вложения: временный файл и контент просмотренной карточки исчезают. Это проверка моста, не Telegram-аккаунта.

Три воспроизводящих цикла red → green: отсутствующее подключение API; отдельные карточки вместо альбома; создание второго фида вместо подключения импортированного. Отдельный red → green воспроизвёл смешение позиции RSS и Telegram. Другие сценарии расширяют уже работающий путь; полный TDD для всех изменений не заявляется.

Полный набор после ревью: 48 тестов прошли за 16.71 с. Первый запуск внутри ограниченного sandbox: 40 прошли, 6 процессных проверок не смогли открыть loopback. Повтор с разрешённым loopback прошёл; после исправлений альбома прогон повторён. Mypy: 9 модулей без ошибок; синтаксис JavaScript и `git diff --check` чистые. Есть прежнее предупреждение Starlette о будущем переходе TestClient на httpx2.

Ревью выявило изменение идентичности альбома при появлении/удалении его частей. Исправлены устойчивый ID по `grouped_id`, сохранение обнаруженного при fetch состава и повтор загрузки при расширении альбома. Два дополнительных API-теста сначала воспроизвели ошибку, затем прошли: новый элемент обновляет одну карточку; смена первого доступного URL не обходит tombstone просмотренного альбома. Повтор Spec-ревью подтвердил исправление. Открытый UI обновляет медиа при изменении состава.

Обнаруженная во время проверки гонка: новый job мог стартовать во время завершения отмены и очистки старого spool. `Runtime.cancelling` теперь блокирует такой старт и новый запрос моста до завершения отмены; процессный тест снова проходит.

## Браузер

Временный экземпляр со внешней синтетической Telegram-границей и настоящими локальными PNG/MP4. Через UI выполнены выбор аккаунта, username, папки и подключение. В читателе A появилась одна карточка альбома и прогресс 1/1. Изображение загружено через локальный API, у видео и кружочка `readyState=4`, размеры 320×320, длительность 2 секунды, ошибок декодирования нет. Видео запущено штатной кнопкой: `paused=false`, время воспроизведения двигалось. Воспроизведение кружочка отдельно не подтверждено; его декодирование и контролы подтверждены.

«Просмотрено» очищает все media-элементы DOM; карточка и счётчик папки исчезают. Обновление источника не возвращает просмотренный альбом. Экземпляр остановлен, созданная вкладка закрыта, временный viewport сброшен. [Скриншот читателя](telegram-reader.jpg) содержит только синтетические материалы.

## Существующее подключение: проверено и не проверено

Использовано окружение `/Users/dabondarev/repo_personal/telegram-mcp/.venv`, его клиент runtime и собственная `.env`; секреты не читались в вывод и не переносились. В установленном Telethon 1.45.0 проверены фактические сигнатуры `get_messages(... offset_date, offset_id, reverse, ids ...)` и `download_media(... file, progress_callback ...)`.

Настроены аккаунты `assistant` и `personal`. Ограниченные попытки разрешить один публичный канал через каждый аккаунт остановились до подключения: существующий `SessionLock` сообщил «Telegram-сессия занята другим клиентом». Это реальная проверка отказа занятого подключения, но не успешная проверка чтения или загрузки в Telegram. Другие процессы не останавливались, блокировка не обходилась, read acknowledgements не отправлялись. После каждой попытки процесс и spool удалены. Массового импорта аккаунта не было.

**Остаётся отдельная интеграционная приёмка:** когда одна существующая сессия свободна, проверить выбранные пользователем публичный/приватный источники и обычную группу, реальный альбом и загрузку видео/кружочка. Подмены и браузерный fixture не доказывают эти операции на личном аккаунте.

## Реализованные ограничения

Forum topics не подключаются. Один файл ограничен 200 МБ и 180 секундами; сбой явно оставляет неполный материал. Нестандартное вложение остаётся неполным. Альбомы расширяются по соседней истории, при очень свежем альбоме полнота откладывается до повтора. Исторические удаления между сохранёнными границами нельзя восстановить из Telegram. Обнаружение всех правок относится к тикету 13. Отметки прочитанного — тикет 05.

Документированные операции сверены с [Telethon](https://docs.telethon.dev/en/stable/modules/client.html) и [Telegram: загрузка файлов и группы медиа](https://core.telegram.org/api/files). Telegram документирует максимум десять элементов в группе медиа; выборка соседей использует историю, а не предположение о последовательных числовых ID.
