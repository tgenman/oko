Пакет передаёт ID/версии выбранных сущностей; его метаданные растут с выбранным
списком. Это не постоянный размер ответа и не постоянная работа на любом списке.
У неизменившегося пакета один Python JSON decode тела запроса, без чтения
материалов и производных файлов. Полные тезисы и фильтр не передаются ради списка.

Старый прямой `/status` при повторе открывает 0 файлов, но проверяет stat текущих
непросмотренных материалов (104/400). Это явно остающаяся стоимость совместимого
старого представления. Новый неизменившийся цикл вообще его не строит.

stat — 3 для затронутого материала. Ранее измеренные 171 SQL относятся к просмотру
до регистрации списка, поэтому эти числа не смешиваются.

На 20000 служебных записях измерены реальные планы и работа, а не только имена индексов:

| Обращение | Результат | VM | План |

На 3000 записей ошибочных команд (1500 предметов, по два исхода) выбор последнего
исхода потребовал ≈87000 VM с индексом и ≈18081000 без него. После удаления индекса
EXPLAIN получен заново, без повторного использования подготовленного плана.
Существующий HTTP-тест дополнительно проверяет 3000 предметов / 6000 исходов,
правильный последний результат и его сохранение после restart.

Повторно пройдены ограничения: HTTP viewed с историей/заданиями 20000 — <5000 VM;
статус с 20000 завершёнными заданиями — <10000 VM; dispatch — <3000 VM;
архивные индексы после удаления и повторного старта создаются снова. Цена пары
изменений viewed в архиве после reopen — 1188 VM в #56, допустимая граница <1500.

Новая сквозная миграционная проверка удаляет только новые служебные метаданные
версий и выбранные индексы в остановленной временной базе существующего формата.
После двух запусков HTTP сохраняются исходные байты текста, текущая и предыдущая
ревизии, переопределённая настройка originals, служебная отметка и незавершённая
задача. Running восстанавливается в pending. `secure_delete=1`, journal_mode=delete.
Существующие проверки дополняют это прерванной фиксацией фильтра и наследуемой
сигнатурой с сохранением результата/происхождения, Telegram legacy state и удалением.

## Время открытия в настоящем браузере

Граница: capture click по строке → MutationObserver видит текст выбранного ID.
Не включаются ожидание Playwright actionability и прокрутка до клика. На каждой
библиотеке — 40 разных первых открытий в этой вкладке, затем их 40 повторов.
Это не холодный дисковый кэш ОС: начальная загрузка списка уже выполнялась.
Сохранённый текст — примерно 2.1 KB на публикацию, без медиа. Фон — реальная
очередь Runtime и синтетическая локальная модель с задержкой 150 мс; наличие
обработки проверяется после обеих серий. Внешняя сеть сбора в этом стенде отключена.

Для сравнения использован `3b59c72` (серверные #53–55, до #56) и тот же тестовый
seeder/HTTP host/измеритель. Продуктовый код baseline не менялся.
