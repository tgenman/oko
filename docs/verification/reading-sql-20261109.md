# Проверка чтения фидов и повреждённой истории

Сравнение выполнено с `0a26a18c` на отдельной синтетической PostgreSQL.
Личные подписки и реальные источники не использовались.

В библиотеке из двух фидов и трёх публикаций request-scoped trace показывает:

| Запрос | До | После |
| --- | ---: | ---: |
| Навигация, 200 и 304 | 10 | 8 |
| Статус, 200 | 34 | 32 |
| Статус, 304 | 5 | 5 |
| Публикация, 200 и 304 | 14 | 11 |
| Отметка прочитанного без записи истории | 53 | 54 |
| Отметка прочитанного с записью истории | 53 | 57 |

Числа включают события транзакций и показывают только запросы, попавшие в
данный trace. Они не измеряют задержку и не описывают все обращения сервера к
PostgreSQL. Карточки в актуальном main уже используют новую модель публикаций;
замеры от старого checkout для неё неприменимы.

Базовое чтение фидов больше не загружает начальную историю. Полные сведения
получают только вызывающие места, которым они нужны. Повреждённая история
показывается отдельно от отсутствующей, исходные строки не сбрасываются;
обнаружение новых публикаций повреждённого фида ждёт восстановления, другие
фиды продолжают работу. Допущенные сохранения и отметки чтения удерживают
отложенные переходы до безопасного применения к тому же запуску истории.

Это не упрощение всей системы: сохранение прогресса при повреждении и работа
уже известных публикаций потребовали отдельного журнала, идентификатора
запуска и ограниченного восстановления. При неразрешимом конфликте проблема
остаётся видимой. Изменение не предоставляет автоматического сброса или
интерфейса ручного ремонта повреждённой базы. Внешние изменения состояния
истории фоновый сбор замечает не позднее следующей проверки раз в пять секунд;
при выключенной работе повтор ожидающего восстановления производится при
опросе статуса, с пятисекундным ограничением.

## Выполненные проверки до полного прогона

- 34 теста базового чтения, истории и восстановления просмотренных материалов.
- 41 тест совместной обработки повреждения, отложенных событий, гонок и сбора.
- 2 сценария Playwright через настоящий HTTP; скриншоты проверены. Первый
  запуск после переноса выявил устаревший синтетический fixture и завершился
  двумя ошибками; после его исправления оба сценария прошли.
- Миграция 126 → 127 на сохранённых корректных, отсутствующих и повреждённых
  историях: исходные значения и записи истории сохранены.
- Проверки Python и TypeScript и сборка интерфейса прошли до финальной
  интеграции; результаты общего прогона следует указывать отдельно.

Первый полный прогон актуальной ветки остановился на проверке типов после
объединения изменений; сборка, контракт, линт и HTTP на том снимке прошли.
Ошибки типов исправлены; итог повторного полного прогона фиксируется отдельно.

Повторный полный прогон на снимке до последнего сокращения чтения публикации:
1062 Python-теста и 187 браузерных сценариев прошли; по два Python- и
latency-сценария завершились ошибкой. Python-сценарии использовали fixture
без истории и прошли после его исправления. Latency-повтор и результаты для
последнего изменения чтения публикации фиксируются отдельно.

Изолированный последовательный Playwright-повтор на базовом `0a26a18c` и
изменённой ветке: все 4 сценария прошли на каждой версии. Для первого / повторного
открытия p95 в миллисекундах составил:

| Библиотека и обработка | Базовая версия | Изменённая версия |
| --- | --- | --- |
| 104, idle | 161 / 23 | 126 / 24 |
| 104, активная | 128 / 98 | 175 / 103 |
| 400, idle | 163 / 173 | 146 / 170 |
| 400, активная | 168 / 164 | 189 / 175 |

Каждая серия содержит 40 открытий; текущий тест требует p95 меньше 300 мс.
Это однократное сравнение, а не доказательство ускорения. Во время общего
параллельного прогона два из четырёх сценариев превышали порог; причина этих
выбросов не установлена. Повтор после завершения параллельных тестов прошёл.
HTTP-тест исправленного fixture и проверка публикации без загрузки истории
прошли вместе с повтором YouTube-сценария: 3 теста.

Повторный общий прогон на дереве `79287cdd5ccf4a7f0113c1eb9332e27d92f4f785`
прошёл предварительные проверки, но дал тайм-ауты трёх браузерных,
трёх медиа- и одного инструментального сценария при параллельной работе.
Он был остановлен до завершения; его нельзя считать успешным полным прогоном.
После остановки весь файл медиа прошёл (9 тестов), весь файл браузерного
чтения прошёл (6 тестов, скриншоты просмотрены), инструментальный сценарий
остановки тестовых процессов прошёл отдельно (1 тест). Эти повторы не доказывают
причину тайм-аутов и не заменяют полный прогон и CI.
