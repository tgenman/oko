## Результат и покрытие

Настоящие HTTP Runtime/Store, перенесённая синтетическая SQLite, временные файлы,
синтетические Telegram Web/Telegraph/llama.cpp/Codex. Личные источники не использовались.

В `tests/reviews/test_publication_processing.py` проверены: атомарные JSON и
метаданные результата; смена файла без пересчёта текста; `filter_out` с пустыми
блоками, причиной и доступным исходником; запрет Restore; no_input без модели,
его рестарт и появление текста; недоступный вход до получения; поздний ответ
прежних правил; отзыв public_ai во время проверки обработчика; готовые тезисы
при задержанном медиа; отклонение удаления чужой цитаты и неизвестного источника;
служебная ошибка статьи вне входа модели; фактическая модель повторной попытки;
неудачная регенерация и рестарт с сохранением текущего результата, очистка при
новом тексте; выключение/включение прежних правил и пропуск отдельных этапов;
будущие параметры Codex, невыбранный обработчик и явная регенерация.

Офлайн-перенос сохраняет доказанные результаты неизменившегося текста.
Изменившееся представление входа не получает новую подпись прежнего результата:
отчёт помечает пересчёт, старая копия остаётся в backup. Проверены отмена файла,
source-wait и обычный ручной retry через рестарт без сброса backoff.

Playwright через настоящий HTTP проверил непустые тезисы до/после ошибки
регенерации, скрытие/причину/исходник, отсутствие Restore, отключение фильтра
через Settings и актуальную видимость после перезагрузки. Скриншоты просмотрены:
