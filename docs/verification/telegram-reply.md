# Ответы Telegram — реализация варианта A

Дата: 21 октября 2026. Задача: https://github.com/tgenman/oko/issues/70.
База проверки: `37e4d9c8d950a62bc7c16ddd62671bc3e9db3b75`.
Спецификация: [telegram-reply/spec.md](../../.scratch/telegram-reply/spec.md).

## Реализованное поведение

Telegram web сохраняет автора, доступный фрагмент и безопасный адрес ответа отдельно от собственного текста. Заголовок выводится из собственного текста; предпросмотр не становится большой Markdown-ссылкой. При отсутствии собственного текста заголовок — «Ответ на сообщение». Пустой или частичный предпросмотр не создаёт фиктивное вложение.

Карточка A находится после даты перед содержимым; две строки раскрываются отдельной кнопкой без сети. Смена материала или принятие новой ревизии сбрасывает раскрытие, фоновое обновление той же ревизии сохраняет его. Предыдущие версии показывают собственный контекст. Текст предпросмотра выводится React как текст; допустимый адрес открывается отдельно с noopener/noreferrer.

Обе операции ИИ получают собственный текст и отдельный `reply_preview` внутри InputSource. Инструкции обработки различают авторов, фильтр удаляет фрагменты только собственного текста. Полный сохранённый фрагмент участвует во входе независимо от визуального усечения. Изменение контекста меняет ревизию и актуальность; идентичная повторная загрузка сохраняет результаты. При отсутствии обоих текстов имя/URL не запускают ИИ. Старый объединённый текст допускается без обязательного сетевого переполучения.

Формат старых файлов совместим; обновление приложения не мигрирует библиотеку. Первое штатное переполучение может сохранить исправленное представление как новую локальную версию. Это не доказательство авторской правки.

## Фактические проверки

В процессе TDD первая HTTP-проверка упала на заголовке `> Reply author`; проверка модельного входа — на отсутствующем контексте; браузерная — на отсутствующей карточке. Браузерная проверка переключения затем обнаружила коллизию sibling React keys с Media; ключ предпросмотра получил собственный префикс, проверка прошла.

Промежуточный HTTP-прогон после изменения проекции упал из-за неверного имени переменной `item` вместо `identity`; это исправлено. Промежуточная проверка reply-only ожидала два модельных вызова до окончания загрузки: фильтрация teaser могла успеть до окончательной версии. Проверка теперь включает обработку после завершения сбора, чтобы измерять согласованный вход. Эти промежуточные прогоны не считаются итоговым успехом.

Итоговые результаты будут записаны после полного прогона и независимого ревью. Автоматические проверки используют временные хранилища, синтетические HTTP/AI adapters и Playwright. Личные подписки, Telegram-аккаунты и настоящий ИИ не используются. Мобильная компоновка всего читателя не входит в изменение; узкая область чтения проверяется в существующем desktop layout.
