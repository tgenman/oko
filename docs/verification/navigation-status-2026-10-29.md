## Изменение

Навигация и компактный статус используют независимые предметные GET с ETag.
Подробности имеют собственный запрос; зависший запрос подробностей не задерживает
основной опрос. Закрытая панель и закрытые настройки не запрашивают подробности.
Допуск команд принадлежит только компактному статусу. Смена библиотеки очищает
снимок проблем и локальные исходы прежних команд. Универсальный reading/check,
его схемы и старый reading/materials удалены. Публикация остаётся единым ответом.

ETag статуса сравнивается до построения ответа. Пакетные факты публикации
используются одним синхронным чтением, включая связанные публикации и сведения
фида. Удалены повторное чтение фида/истории и запрос на каждую связанную публикацию.
Сохранён исходный SQL-бюджет открытия, а не увеличен порог теста.

`completed`/`total` активной непрерывной работы неизвестны и возвращаются как
null; размер оставшейся очереди не выдаётся за завершённую долю. Idle — 0/0.

## Уточнение SQL-проверки в CI

Первый CI исправленного выпуска завершил Python-группу с 495 PASS и одним
падением старой проверки линейности пустого диспетчера: фактические сканы
`[0, 402]` для 26/400 корневых публикаций сравнивались как `402 <= 0 * 25`.
Нулевой скан небольшого входа не является базой для отношения роста: PostgreSQL
может доказать пустоту без чтения строк, а для другого размера выбрать один
линейный проход. Сохранён множитель 25 и проверка против квадратичных join;
минимальная база теперь один просмотр строки на корневую публикацию.
Production-диспетчер этим исправлением не менялся.


## Уточнения следующего CI

Обнаружена и локально воспроизведена гонка Retry: фоновое применение подробностей
повторно читало неудачно загруженные настройки и убирало кнопку перед кликом.
После ошибки автоматическое повторное чтение прекращено; 304 не применяет
подробности повторно без изменения локальной ревизии. Усиленный браузерный тест
сначала получил два запроса вместо одного; после исправления весь затронутый
набор настроек/статуса/жизненного цикла — 21 PASS.

Проверка возобновления загрузки сравнивала заголовок старой карточки с готовностью
из более позднего ответа публикации. При завершении между двумя GET это давало
ложное падение. Теперь готовность, заголовок и содержимое проверяются из одного
ответа `GET /publication/{id}`; запрет принятия отменённого результата сохранён.


Дополнительные сценарии ревью и диагностики: открытие панели после того, как
настройки уже закэшировали подробности, воспроизвело пропуск отображения при 304.
Панель теперь всегда принимает доступный кэш; применение настроек учитывает,
какой объект ответа уже получил именно этот владелец.

Периодическая блокировка сохранения модели воспроизведена управляемой задержкой:
поздний callback `settings-open` отменял каталог новой страницы. Callback теперь
допускается только при неизменной ревизии навигации. Тайм-ауты не увеличивались.

Повторный объединённый набор после обоих исправлений: 33 Playwright PASS.
