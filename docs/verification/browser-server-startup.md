# Ускорение запуска HTTP-серверов браузерных тестов

2026-10-13. База задачи: `c2929ed`; исходный checkout содержал незакоммиченные изменения других задач. Они сохранены и исключены из коммита через `scripts/task_changes.py` и снимок `/tmp/oko-server-speed-start`.

## Изменение

`productionReader()` переиспользует один Python-процесс на тестовый файл Node. Импорты выполняются один раз; приложение и сервер создаются заново для каждого сценария. Существующая сборка синтетических adapters вынесена в `build_app`, её параметры не менялись.

Каждый сценарий сохраняет собственные browser context, токен, loopback-порт, временный каталог, SQLite, Runtime, Journal и adapters. Сервер работает в отдельном потоке со своим asyncio loop: production lifespan устанавливает обработчик ошибок на loop, поэтому общий loop мог бы смешивать журналы. Ответ о готовности отправляется после `server.started`, включая завершение startup/lifespan. Продуктовые HTTP routes, lifespan и хранилище настоящие; сброс общей базы и подмена серверных правил не используются.

Закрытие сначала закрывает browser context, затем завершает lifespan сервера и удаляет каталог. Отмена сценария не останавливает соседний. EOF/SIGTERM закрывает живые серверы; ошибка старта завершает host, чтобы следующие сценарии не продолжали работать после повреждённого lifecycle. Ожидания протокола и завершения ограничены; ненулевой exit host проваливает проверку.
