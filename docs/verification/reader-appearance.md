# Шапка и оформление карточек Око — фактическая проверка

Дата: 2026-10-14. Ветка реализации: `codex/reader-appearance`.

Основание: [спецификация](../../.scratch/header-ios-preview/spec.md), тикеты [02](../../.scratch/header-ios-preview/issues/02-header-ios.md) и [03](../../.scratch/header-ios-preview/issues/03-card-appearance.md).

## Изменение и границы

Действия шапки сгруппированы на одной линии с брендом, динамический ход работы расположен ниже. Сохранены действующие кнопки, обработчики, панель состояния и журнал диагностики. Клавиатурный фокус прокручивает верхний ряд к выбранной кнопке на узком экране.

Оформление карточек меняет только цвета фона, текста, разделителей и фокуса. DOM, размеры, плотность, типографика и порядок сведений остаются у действующего списка: превью 76×76 px, padding 16 px, gap 12 px, минимальная высота строки 112 px, список по умолчанию 440 px. Сохранены две строки заголовка/фрагмента, метаданные, группировка по датам и реальные превью.

Первоначальная база ревью: `8ea2ace189d9ce20351a62a4e0d7602824179423`. Итоговое дерево кода: `839e92ba013e1b0bc0febaf9b460f9f42a48df05`. В нём шесть файлов: сборка шапки, обработчик клавиатурного фокуса, отдельный stylesheet, два SVG состояния и браузерные проверки. Прежние dirty-изменения других задач не включены. Полные проверки запускались в независимых копиях подготовленного дерева; оригинальный checkout не сбрасывался.

Все данные синтетические, используются временные HTTP-серверы и хранилища. Computer Use в реализации и проверках не применялся. Скриншоты сняты Playwright и просмотрены как файлы.

| TDD: новая проверка карточек до оформления | Геометрия прошла; ожидаемое падение цвета выбранной строки | [До изменения цветов карточек](reader-appearance/before-cards.png) |

Первый полный прогон упал в двух существующих сценариях: ожидание «Тезисы готовы» в Codex HTTP и `NotSupportedError` при воспроизведении видео. На исходном коммите отдельный повтор обоих файлов прошёл; итоговый полный повтор тоже прошёл. Точная причина непостоянных сбоев не установлена; отдельный повтор не считается доказательством успеха первого прогона. Специальные исправления этих сценариев в данную задачу не включались.

Команда ограниченного набора:

```sh
./scripts/check ui --files tests/browser/test_reader_appearance.cjs tests/browser/test_material_list.cjs tests/browser/test_status_panel.cjs tests/browser/test_separate_menus.cjs tests/browser/test_reader_http.cjs
```

Отдельная проверка исходной базы:

```sh
./scripts/check browser --files tests/browser/test_codex_settings_http.cjs tests/browser/test_opened_material.cjs
```

Новые два сценария проверяют центры всех шести действий и бренда, длинный статус ниже ряда, положение панели под шапкой, возврат фокуса, Tab-доступность всех кнопок на 390 px без переполнения страницы, геометрию и содержимое строк, дату и источник, состояния загрузки, сохранение изображения и цвет выбранной строки.

Существующий полный набор дополнительно проверяет меню добавления и настройки, обновление, остановку, разные состояния кнопки проблем, журнал, адаптивность панели, состав чтения, выбор/просмотр, ширину списка, прокрутку, задержанные ответы и повторное использование превью.
