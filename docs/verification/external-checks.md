## Сохранённые расхождения и ограничения

- Поздний ответ после выключения/включения сейчас переводится в HTTP 400
  `source_connection_invalid` для RSS и 503 для остальных проверенных путей,
  с их предметными кодами ошибок. Это подтверждено на исходном Runtime.
- Codex check и сохранение конфигурации в этом сценарии возвращают 503
  `processor_unavailable`, тогда как закрытая схема этого ответа ожидает
  `storage_unavailable`. Новые тесты явно проверяют фактические статус/код обычным
  HTTP-клиентом; исправление контракта оставлено для отдельной задачи.
- Различия передачи настоящей отмены вызывающего запроса сохранены: RSS и
  клиентский Telegram передают её, llama.cpp/Codex переводят в ошибки действий,
  Telegram web preview передаёт без перевода.
- UI не менялся; браузерный набор в этой задаче не запускался. Широкий серверный
  прогон не является полным `check all`. Инструменты разработки не менялись,
  отдельный набор их тестов не запускался. Настоящие источники, аккаунты и
  обработчики не использовались; пользовательский экземпляр не перезапускался.
