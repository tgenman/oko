## Исправления при завершении

Независимое ревью backend истории и UI выявило четыре дефекта, которых не находил прежний полный набор:

1. Восстановление одного/обоих RSS-окон обходило границу истории по дате. Полный отказ теперь не сохраняет пустой успешный cursor; известная дата проверяется и для восстановившегося окна. HTTP regression параметризована полным/частичным отказом.
2. Повторный меньший N после появления нового видео создавал одинаковые ранги у выбранных и ранее сохранённых материалов. Store объединяет сохранённый префикс нового подбора с прежним порядком оставшихся материалов. Проверены «Новые сверху» и «Старые сверху»; избыточное поле порядка в Publication убрано, порядок сохраняется в Store.
3. После запуска первой истории и переоткрытия того же фида до ответа POST статус не мог создать отсутствовавшие элементы прогресса и продолжения. Теперь они подготовлены скрытыми и обновляются текущим status без пересоздания формы/потери черновиков.
4. Сохранённое N выше точного диапазона JavaScript округлялось при открытии формы. Форма читает `count_text`; browser regression проверяет точное отображение и отправку `9007199254740993` строкой.

Повторное ревью всех четырёх исправлений — без замечаний. Отдельные review субтитров/тезисов/defaults и отчётов runner/cleanup — без actionable замечаний.
