# Совместная работа чтения, обработки и Telegram

2026-10-11. Исходная база: `d4bba3f78e852348db64951492f20fa1a2460a3e`.

После завершения 13 задач первой версии следующий шаг — общая приёмка по
`.scratch/oko-product/spec.md`. Этот отчёт закрывает два сочетания поведения,
не объявляет всю V1 принятой и не добавляет новые продуктовые функции.

## Проверенные сценарии

Основная граница — согласованный API читателя с настоящим временным хранилищем
SQLite/файлов и заменяемыми внешними Telegram/AI. Проверки находятся в
`tests/lifecycle/test_integrated_reading.py`.

1. Три Telegram-публикации: скрытая реклама и два сообщения об открытии
   библиотеки. Фильтрация и событие работают вместе; обзор сохраняет точный
   набор из трёх оригиналов, включая скрытый. Завершение папки считает одну
   карточку и три оригинала, удаляет оригиналы, событие и обзор. Telegram
   подтверждается до ID 42. Сбой после внешнего подтверждения моделирует
   потерянный ответ; после перезапуска граница восстанавливается без повторного
   подтверждения и без текстов. API не выдаёт удалённое; каталоги результатов
   пусты; контрольные фрагменты отсутствуют во всех оставшихся файлах.
2. Два Telegram-фида одной папки: один разрешает публичный AI, другой запрещает.
   Локальная модель готовит смешанный обзор. После переключения на Codex прежний
   обзор перестаёт выдаваться, запрет виден в статусе. Разрешённый оригинал
   получает новые тезисы; запрещённый оригинал и прежняя производная сводка
   не передаются внешнему Codex adapter. Запрет одного задания не мешает
   допустимой обработке другого фида.

Это характеристические проверки уже реализованного поведения. Исправления
production-кода не потребовались. Первый прогон второго теста ожидал ошибку в
ответе материала обзора; API выдаёт только готовые обзоры, а ошибку показывает
в общем статусе. Исправлена проверка интерфейса; это не дефект продукта.

## Граница доказательств

Свежая проверка настоящих Telegram, Codex и llama.cpp в этой работе не
выполнялась. Личный read state не изменялся, модели и серверы не запускались,
Telegram MCP не использовался. Синтетический Codex adapter проверяет отсутствие
передачи на границе Око, но не аттестует CLI sandbox и его действующую квоту.

Полная приёмка V1 остаётся открытой: нужны свежие проверки внешних подключений,
сквозной путь в браузере и сверка всех A01–A32 с доказательствами. Качество
смысловой обработки локальной моделью эти тесты не оценивают.
