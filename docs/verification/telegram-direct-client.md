# Собственный клиент Telegram

2026-10-08. Указание пользователя: перенести клиент в Око, убрать зависимость от MCP-проекта. База изменения: `1bed56c3750c8a3908537041f8c9344fcd78d489`.

До изменения worker уже вызывал Telethon напрямую, но импортировал runtime и singleton из проекта telegram-mcp и запускался в его venv. Теперь Око содержит `telegram_client.py`, устанавливает Telethon 1.45.0 в собственное окружение и запускает свой модуль worker. MCP, внешний Python-код и чужой venv не используются. Отдельный процесс сохраняет принудительную отмену скачивания.

Настройки читаются из явно указанной `.env`. Нет экспорта сессий, нового логина, копирования секретов или создания отсутствующей файловой сессии. Список аккаунтов определяется до создания SDK-клиентов. Именованные и одиночные StringSession/существующие `.session`, device identity и SOCKS/HTTP/MTProxy поддержаны. Пулы сессий пока явно отклоняются. FloodWait возвращается вызывающему слою без скрытого сна SDK. Сетевые обновления SDK отключены, read acknowledgements не вызываются.

Блокировка адаптирована из `telegram_mcp/singleton.py` под POSIX и использует тот же путь и хэш идентичности сессии; лицензия сохранена в `docs/licenses/telegram-mcp-Apache-2.0.txt`. Рабочие процессы других клиентов не останавливаются.

API-тест отсутствующей зависимости от внешнего проекта сначала падал на поиске чужого venv; после изменения проходит с одной синтетической `.env`. Проверка реального процесса worker теперь подменяет только внешний Telethon SDK: в fixture вообще нет telegram-mcp или venv. Проверены альбом у границы страницы, отмена скачивания и удаление временных файлов. Отдельная проверка неавторизованной сессии подтверждает отказ без логина, создания фида или копии авторизации. Остальные проверки Telegram сохранены.

Ограниченная проверка на существующей конфигурации: собственное окружение Око прочитало названия `assistant`, `personal`; попытка доступа через `personal` остановлена совместимой SessionLock до сетевого соединения. Spool удалён. Секреты и пользовательские сообщения в вывод не попали. Успешное чтение реального аккаунта остаётся непроверенным, статус тикета `integration-pending` сохраняется.

Настройка SDK сверена с [официальной документацией Telethon](https://docs.telethon.dev/en/stable/basic/signing-in.html). Ранее выполненная [браузерная проверка](telegram-reading.md#браузер) остаётся проверкой неизменённого UI с синтетическим источником; она не выдаётся за новую живую проверку Telegram.
