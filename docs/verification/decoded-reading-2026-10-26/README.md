# Синтетический замер чтения PostgreSQL

Замер 2026-10-27 сравнивает исходный checkout `6e64879` с деревом изменений PostgreSQL-only на одинаковом одноразовом PostgreSQL 18. Использованы 1600 карточек с длинным синтетическим текстом и 100 общих связанных публикаций; личные данные и внешние источники не использовались. Каждый сценарий запущен пять раз последовательно, без других тестов. PostgreSQL имел лимит четыре CPU. Сценарий и отдельные измерения сохранены рядом; окружение не представляет production.

| HTTP-сценарий | Медиана до | Медиана после | Разборов содержимого до → после |
| --- | ---: | ---: | ---: |
| Полный список | 2593 мс | 2137 мс | 17 600 → 1 700 |
| Фид с двумя карточками | 97 мс | 85 мс | 22 → 3 |
| Открытие материала | 7,4 мс | 7,4 мс | 11 → 2 |

Для полного списка и фида совпали число карточек, размер ответа и SHA-256 нормализованного состава карточек. Размер ответа открытого материала также совпал. Неизменённая проверка составила 45 и 46 мс соответственно, без разбора содержимого. Это измерение серверного HTTP-интерфейса, не Safari и не production; ускорение реальной отрисовки не доказано. Оптимизация ограничена сроком одного снимка чтения и может увеличить его пиковую память.

## Проверки

В повторном полном прогоне `check all --compact --in-place --browser-workers 2` прошли 988 серверных тестов (2 пропущены), 321 инструментальный и 113 Node-тестов. Браузерный набор в полном прогоне завершился с одной ошибкой из 224 выполненных сценариев: экран модели не дождался каталога. Пять отдельных повторов файла настроек прошли (10 сценариев). Следующий отдельный прогон всех браузерных тестов дал 223 успешных сценария и две ошибки подготовки библиотеки; после увеличения только таймаута подготовки PostgreSQL и ожидания восстановления фоновой очереди все четыре performance-сценария прошли. Исходный полный прогон при лимите PostgreSQL в одно CPU также содержал таймауты; пять его серверных ошибок прошли при повторе. Следовательно, эти ограниченные повторы не являются единым полностью успешным `check all`.

Для четырёх performance-сценариев p95 первого/повторного открытия составил: 104 материала без обработки 30,5/33,1 мс, с обработкой 42,0/42,1 мс; 400 материалов без обработки 44,0/52,9 мс, с обработкой 53,9/60,4 мс. Порог p95 <200 мс не менялся. Отдельный браузерный сценарий с собственной схемой PostgreSQL прошёл вход, сбор, отображение, перезапуск и «Просмотрено». Два ранее отключённых браузерных сценария остаются пропущенными; третий пропуск общего набора соответствует указанному отдельно проверенному сценарию PostgreSQL.
