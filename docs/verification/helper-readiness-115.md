# Готовность helper при перезапуске #115

База f0e4c094ec1ebca583c9f92f628c2f0b464bc310. Ветка codex/115-helper-readiness.

После первого успешного рабочего запуска новый reader прошёл HTTP, выдачу файла
и браузер. Обычный restart выявил старую гонку: reader healthy наступил раньше
listener helper; единичный inside-Docker health вернул URLError, команда штатно
остановила новый reader. Данные сохранены, возврата на прежнюю библиотеку не было.

Проверены гипотезы позднего listener, Docker-маршрута и идентичности helper.
На Mac helper стал ready через 1.58 s после 14 ранних транспортных отказов.
С предварительно готовым helper тот же обычный start прошёл, включая проверку
из контейнера. Это подтверждает гонку готовности, а не неправильный секрет/SHA.
Подробные рабочие артефакты хранятся отдельно, без пользовательских данных в Git.

Минимальный red-loop: test_start_waits_for_helper_listener_after_reader_is_ready
через настоящий start и probe; первая транспортная ошибка задаётся на OS-границе,
далее используется принадлежащий тесту HTTPServer. До исправления 1 failed,
0.55 s: URLError Synthetic helper is not listening yet. Первая черновая фикстура
также упала в cleanup на неподдерживаемом Mac socket option; она исправлена,
принадлежащий ей зависший pytest завершён; этот прогон не считался успешным.

Исправление: ограниченный retry только OSError с deadline 15 s, запросом 2 s и
шагом .25 s. HTTPError немедленно завершается; protocol/release проверяются вне
retry. Старое правило остановки нового reader при неуспехе сохранено. Новых
параметров и изменений HTTP-контракта нет. Независимое ревью — без замечаний.

Сценарии: listener готов после раннего отказа; неверные SHA/protocol; 401;
недоступный helper и истечение deadline. Последний тест использует локальные
импортируемые часы только для probe, не меняя глобальное время процесса.
`./scripts/check python --compact --files tests/development/test_docker_release.py`
— **28 passed**, 17.43 s, contracts PASS.
[Отчёт](helper-readiness-115/targeted-report.json). Успех относится к затронутому
набору; слияние требует полного CI нового SHA. Рабочий restart после выпуска
будет записан отдельно по факту.
