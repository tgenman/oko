# Согласование актуальности обработки: проверка

2026-10-11. План: [processing-coordination](../architecture/processing-coordination.md). База: `a86ec7a6f0386361ee1f219805bc75ccc557165e`.

## Изменение

`oko/reviews/coordination.py` содержит ProcessingCoordination и PreparedWork. Module владеет порядком согласования Filters → Digests → Events → тезисы и связывает запрос конкретного задания с проверкой актуальности, принятием результата и освобождением временного плана обзора. Runtime не строит таблицу операций, не выбирает тип результата, не знает пустой этап и освобождение Digests.

`oko/reviews/theses.py` содержит PublicationTheses: определение актуальности, очередь, подготовку, чтение, повторную попытку и принятие тезисов публикации. Эти правила перенесены из Store. Store сохраняет SQLite, файлы, транзакции, атомарный writer и восстановление; его чтение материала достраивается доступными результатами.

После принятия фильтра или этапа обзора зависимые результаты согласует PreparedWork. Filters.save и Digests.save больше не вызывают пересчёт других видов результатов. Принятие версии, настройки, просмотр, восстановление скрытого материала и периодический проход используют ProcessingCoordination.sync. В выключенной обработке уже отменённое задание без входных данных и файла не получает новое поколение при каждом неизменившемся проходе.

Сохраняются прежние форматы и порядок заданий. Runtime владеет допуском и отменой; внешние проверки и генерация остаются вне блокировки действий. Перед передачей после проверки обработчика и при принятии ответа проверяется актуальность подготовленной работы. Освобождение плана работает также при ошибке подготовки и отмене.

## Test surface

Основные проверки используют interface читателя, временные настоящие SQLite/файлы и внешние source/AI adapters. Внутренние классы согласования не подменяются; тесты не читают SQL для доказательства поведения.

Новый `tests/reviews/test_processing_coordination.py` проверяет:

- Готовые фильтр, тезисы, событие и обзор не вызывают повторных внешних запросов на неизменившихся проходах и после перезапуска.
- Отзыв разрешения публичного AI во время задержанной проверки обработчика предотвращает передачу публикации; поздняя проверка не открывает допуск.
- Ручной возврат скрытого оригинала пересобирает обзор с прежним набором ID и включает возвращённый текст в новые тезисы и обзор.

Первые две проверки выполнены также на отдельной временной копии исходного `a86ec7a`: **2 passed**. Это characterization для рефакторинга, а не искусственный red. В первых запусках нового fixture отсутствовал role=assistant, а ответ события представлял одиночные группы; это ошибки тестового adapter, исправленные без изменения продуктовых требований.

Сохранены проверки правки версии во время генерации, запрета старого ответа, отмены при просмотре, смены настроек, неполных исходников, повреждения прогресса и возобновления после аварии в существующих тестах.
