# Telegram: подключение и темы форумов

Дата: 12 октября 2026. Требования: [.scratch/telegram-topics/spec.md](../../.scratch/telegram-topics/spec.md). Согласованная база ревью: `6979747`.

## Изменение

Форма подключения вынесена в `web/telegram-connection.js`. Аккаунты загружаются при открытии настроек, единственный аккаунт выбирается автоматически; несколько требуют выбора. Кнопка недоступна без корректного источника, папки, аккаунта и выбранной темы (когда загружен список тем), а также во время запроса. Ошибка сохраняет введённые данные. Подключение импортированного фида использует ту же форму и передаёт существующий feed_id.

Тема сохраняется в nullable `feeds.telegram_topic`. Старые фиды сохраняют NULL и прежнюю идентичность. Для новых тем идентичность включает account/peer/topic; подмена темы существующего подключённого фида запрещена. Runtime сохраняет владение admission/отменой; внешний клиент выполняет ожидания вне mutation lock. ReadSync сохраняет отдельную очередь каждого фида.

Собственный worker использует установленные SDK-запросы `messages.GetForumTopicsRequest`, `GetForumTopicsByIDRequest`, `ReadDiscussionRequest`. Темы, включая «Общее», не подтверждаются через отметку всего диалога. Страницы, прямое получение сообщений, расширение альбомов и медиа фильтруются по теме. «Общее» фильтруется из общей истории, а cursor учитывает просмотренную внешнюю страницу, даже если она не содержит сообщений выбранной темы. Форум без темы отклоняется. Подключённый обычный фид, превратившийся во внешний форум, не может отправить отметку всего форума.

## Реальный Telegram и браузер

Настроены 2 аккаунта. Проверка доступных диалогов нашла 28 форумов в одном аккаунте. Содержимое, названия приватных групп, идентификаторы и секреты не выводились.

Настоящий worker получил 11 тем доступного форума, проверил info/page/read_state для General и обычной темы; за последние сутки General вернул 4 сообщения, обычная выбранная тема — 0. Дополнительная read-only проверка SDK получила 5 сообщений обычной темы без ограничения сутками. Повтор существующей ненулевой серверной границы чтения прошёл, граница осталась прежней. Новые личные непрочитанные сообщения не подтверждались; такой переход проверен на fixture, а не на личном аккаунте.

В запущенном Око настоящий Chrome через настоящий API получил 2 аккаунта; выбор, блокировка пустой формы и включение после заполнения проверены без подключения новых источников. Предыдущий процесс штатно остановлен, новая версия запущена через Око.app.

Источники протокола: [форумы](https://core.telegram.org/api/forum), [readDiscussion](https://core.telegram.org/method/messages.readDiscussion). Локальная модель и Ollama не запускались для этой доработки.
