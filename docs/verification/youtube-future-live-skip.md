# Пропуск анонсов будущих трансляций

По указанию пользователя будущие трансляции не ожидаются и не проверяются по расписанию. Когда captions worker получает `VideoUnplayable` с причиной `This live event will begin ...`, он возвращает штатный сигнал пропуска. Адаптер передаёт `SourceSkipped`, Runtime проверяет актуальность задания и использует существующее завершение материала в Store: карточка исчезает, задания отменяются, контент удаляется, идентичность остаётся обработанной. Повторный сбор и перезапуск не возвращают этот анонс и не запрашивают его субтитры снова. После начала трансляции этот же ID тоже не возвращается.

Этот результат не записывается как исключение. Другие причины VideoUnplayable сохраняют прежнюю обработку и диагностику. Распознавание происходит только при запросе субтитров по существующим настройкам; дополнительных запросов для проверки анонсов нет. При выключенных тезисах и обычной важности анонс не распознаётся таким способом.

Проверки использовали временные хранилища и настоящий captions worker с синтетическим SDK:

- tests/collection/test_youtube.py: 12 passed. Новые сценарии проверяют исчезновение анонса, отсутствие диагностики, повторный сбор и перезапуск без повторного captions request; региональная недоступность по-прежнему записывается как VideoUnplayable.
- ./scripts/check all: 269 Python tests, 42 browser scenarios, mypy 36 modules, синтаксис, diff и CLI — PASS (152.38 секунды).
- Независимое ревью: 0 замечаний.

Работающий пользовательский экземпляр не перезапускался, реальные источники не вызывались. Прежние записи диагностики не удаляются этой правкой; их можно очистить существующей кнопкой панели.
