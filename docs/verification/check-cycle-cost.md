## Реализация

- Pre-commit всегда проверяет whitespace индекса. Документационные коммиты не
  сканируют Python-тесты. Контракты тестов проверяются при изменении их входов.
- Успешные проверки индекса кэшируются по всему index inventory/blob IDs, HEAD,
  фактическому коду checker, установленным инструментам и окружению. Ошибки не
  кэшируются; после выполнения ключ сверяется снова. Index отличается от worktree:
  исправление только worktree не скрывает staged ошибку.
- TypeScript экспортирует staged файлы одним Git вызовом и проверяет затронутые
  проекты по графу импортов; JSON/конфиги/удаления проверяются консервативно.
  Межпроектный импорт и extends покрыты отдельными сценариями. Финальный export
  использует raw `git cat-file --batch`: checkout-index smudge/EOL filters не могут
  изменить проверяемые bytes. Regression сначала показал ложный PASS со smudge,
  после исправления hook отвергает staged неопределённое имя; рабочая копия остаётся исправленной.
- Runner и frontend builder используют общий receipt типизации по исходникам,
  конфигам и инструментам. Изменение extends/source инвалидирует success.
- API cache игнорирует PYTEST_CURRENT_TEST и PYTEST_VERSION: это маркеры процесса
  pytest, не входы генерации. Версии Python-пакетов остаются в toolchain fingerprint.
- Python и tools выполняются каждый в двух непустых процессах с отдельными логами
  и artifacts. Файлы распределяются детерминированно по размеру, повторные аргументы
  удаляются до разбиения. Один файл не разбивается. Guards checkout и cleanup
  процессов/потомков сохранены; failure любого worker делает группу неуспешной.
- CI определяет необходимость tools до setup. Ошибка команды или неожиданный ответ
  приводит к ошибке job, а не пропуску. Browser types выполняются в browser job.
  Fresh API check и последующие build checks идут в одном шаге с одинаковым OKO_PYTHON;
  прямой Node вызов не добавляет npm-only PATH, который иначе менял бы ключ кэша.

## Условия измерений

Все full runs: `PYTEST_ADDOPTS='--durations=20' ./scripts/check all tools
--candidate api/openapi.yaml --report-dir ...`, с явным `--browser-workers 2/4`
после изменений. Tools включены принудительно в before/after; состав продуктовых
проверок не сокращался. Каждый full run создаёт новую candidate-копию с холодными
локальными receipts; тяжёлые проверки не запускались одновременно друг с другом.
Это замеры wall-clock runner на одной машине, не статистический benchmark:
фоновая нагрузка и прогрев зависимостей могли отличаться.

Pre-commit: синтетический комментарий к существующему TypeScript-тесту либо текст
в README, внесённый только во временный GIT_INDEX_FILE поверх того же HEAD.
Каждый индекс проверялся дважды через настоящий `git hook run pre-commit`.
Рабочие файлы и настоящий индекс не менялись. Исходная версия запускалась в
`/tmp/oko-hook-before-tree` на7c435f3 с теми же зависимостями. Неуспешная первая
попытка в candidate без context исключена из таблиц: она не выполняла hook checks.
