## Настоящая сборка и Docker Desktop

Команда `scripts/oko-release --home /tmp/oko-release-final prepare --ref 2aea94c`
успешно создала выпуск из `git archive`, отдельное native окружение Python 3.13.11
и Linux ARM64 образ с Python 3.13.9. Generated API и сборка frontend проверены внутри
builder. `install` проверен только в выбранном временном каталоге с отдельным
временным путём LaunchAgents; он не запускает процессы. Импорт production-модулей
из отдельного native окружения прошёл.

Manifest выпуска указывает образ:
`sha256:ca4f2d2cde97bcc79d4c197fba5273e3c12584c001e3e1848a4fafa1825a70e4`.

`tests/fixtures/docker_smoke.py` прошёл именно с этим образом на портах 8765/8767:

- HTTP/UI контейнера доступны, новый Store первоначально выключен.
- Чистый клиент получает 403; обычные bearer-пробы не создают cookie; явный вход
  создаёт отдельную HttpOnly cookie. Посторонние Host/Origin отклоняются.
- Каталог, настройка и проверка Codex через HTTP читателя доходят до синтетического
  helper на Mac, слушающего `127.0.0.1`, через `host.docker.internal`.
- `RemoteCodex.complete` внутри Linux получил результат от собственного supervisor
  синтетического обработчика на Mac.
- После stop/remove/recreate контейнера сохранились настройки, выключенное
  состояние и браузерная cookie; bearer процесса изменился.

Machine-readable результат:
`/private/tmp/oko-release-prepared-smoke/report.json`. Более ранние образы проверены
отдельно; их успех не подменяет эту проверку подготовленного выпуска. Временные
контейнеры и тестовые данные очищены; постоянный пользовательский экземпляр не создан.

## Ограничения рабочего запуска

Настоящий установленный Codex обновился до `0.163.0-alpha.10.2`; его SHA-256 отличается
от действующего допуска Око. Существующий allowlist не расширялся, и этот CLI пока
не допускается к обработке. Выполнены только проверки без создания thread/turn:
запуск под sandbox, флаги, каталог, лимиты и отрицательные проверки OS-правил.
Подробности и оставшийся gate — [отдельная проверка CLI](codex-0.163-preflight.md).
Настоящий запрос модели и проверка его файлов/очередей/журналов не выполнялись.

LaunchAgent в пользовательский сеанс не загружался, личный каталог данных не
переносился и рабочий экземпляр не переключался. Telegram-авторизация, внешние
сессии, сетевые ограничения LAN и живые личные источники не проверялись.
До рабочего переноса необходимы отдельная проверка нового Codex, согласованный
перенос данных и проверка путей Telegram/llama.cpp по
[инструкции установки](../development/docker.md). Проверки синтетического adapter
не доказывают готовность установленного настоящего CLI.
