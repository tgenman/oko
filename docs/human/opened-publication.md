# Открытая публикация: один запрос

Согласовано 28 октября 2026. Реализация — задача #174; рабочий выпуск проверяется отдельно.
[Точный контракт и полный пример ответа](../architecture/publication-http-design.md).

```http
GET /publication/{id}
```

Одним ответом получаем:

- ID, заголовок, фид, дату публикации и ссылку на оригинал;
- `text` — полный исходный текст;
- `filter` — состояние фильтрации и результат: скрыто ли, причина, текст после фильтрации;
- `theses` — состояние подготовки тезисов и массив строк `points`;
- `media` — сведения о вложениях и ссылки. Сами файлы скачиваются отдельно.

У фильтрации и тезисов одинаковая структура:

```json
{
  "state": "processing",
  "result": null,
  "error": null
}
```

| Состояние | Что означает |
| --- | --- |
| `disabled` | Выключено |
| `pending` | Ожидает обработки |
| `processing` | Обрабатывается |
| `ready` | Результат готов |
| `error` | Ошибка, пояснение в `error` |

Без результата — `result: null`, без ошибки — `error: null`.
Без вложений — `media: []`. Неизвестная дата — `published_at: null`.

Ответ содержит ETag. Повторяем тот же GET с `If-None-Match`: `304` без тела,
если ничего не изменилось, или `200` со всей обновлённой публикацией.

Если появились тезисы, текст тоже передастся повторно. Принимаем этот компромисс
ради простоты: один запрос вместо четырёх, без универсального check.
Состояния загрузки публикации и файлов ещё предстоит согласовать отдельно;
этот документ описывает состояния именно фильтрации и тезисов.
