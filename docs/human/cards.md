# Карточки: загрузка и просмотр

Согласовано 27 октября 2026. Реализация находится в ветке задачи #168;
состояние рабочего экземпляра этот документ не подтверждает.
Это актуальное решение по списку карточек; прежние варианты с универсальным
check и загрузкой полного состава ID ему не соответствуют.
[Точный HTTP-контракт и поля карточки](../architecture/cards-http-design.md).

## Один запрос списка

```http
GET /cards?folder=product-id&sort=newest&limit=40&cursor=card-123
```

- Можно выбрать папку или фид. Без фильтра — All Items.
- Сортировка только по времени: сначала новые или сначала старые.
- Скрытые материалы по умолчанию не показываются (`show_hidden=false`).
- Ответ: `items` — порция карточек, `total` — всего в выбранном списке,
  `next_cursor` — ID первой карточки следующей порции.
- Карточка курсора включается в порцию: получили A, B → курсор C → получаем C, D.
- `next_cursor: null` — конец. Курсор потерялся → `409 cursor_expired` →
  начинаем список заново. Смена фильтра или сортировки тоже начинает его заново.

В карточке — заголовок, фид, дата, ссылка на оригинал, превью и существующие
отметки: Loading, Updated, скрыто, ограничение Telegram, внешние вложения.
Название фида берём из навигации. Дата и превью могут отсутствовать (`null`).
Текста, сниппета, тезисов и полного перечня медиа в списке нет.

## Обновляется только то, что видно

Тот же GET с курсором первой карточки видимого участка и небольшим запасом.
При прокрутке меняется запрашиваемый участок. Тысячу ранее загруженных карточек
каждый раз не перечитываем.

ETag относится к конкретному запросу. С `If-None-Match` сервер отвечает `304`
без тела, если ничего не изменилось, или `200` с обновлённым участком.
Начало списка проверяем отдельно тем же GET без курсора. Если пользователь
внизу, показываем «Есть новые», не сбивая его место. Если выбрано «сначала
старые», нажатие переключит порядок на «сначала новые» и покажет начало.

При повреждённых сохранённых данных карточка показывается с заголовком
«Публикация недоступна», без превью и значков, и включается в счётчик.
Если ссылка повреждена, `source_url` равен `null`, действия со ссылкой недоступны.
Остальные карточки остаются доступны; фид и папка учитывают её при завершении.

## Просмотрено — только выбранные ID

```http
POST /cards/read
```

```json
{"ids": ["card-1", "card-2", "card-3"]}
```

Above/Below берёт ID карточек, уже показанных пользователю, выше или ниже
выбранной, исключая её саму. Незагруженные карточки и новые поступления
не затрагиваются. Серверные диапазоны и токены подтверждения не нужны.

Уже просмотренные или удалённые ID пропускаем. Сохраняем всё одной транзакцией.
Успех — `204` без тела, карточки убираются из списка. Ошибка сохранения — `5xx`,
без частичного успеха. Если ответ потерян, интерфейс сообщает, что исход
не подтверждён и повторить тот же запрос безопасно; сам он запрос не повторяет.
«Просмотрено» по-прежнему означает удаление собранного содержимого, а не открытие.

## Что становится проще

У списка нет `check`, `kind`, `storage_id`, `known_cards`, отдельных версий
карточек и полного массива ID библиотеки в HTTP-ответе. Загрузка и обновление —
один GET, отметка просмотра — один POST. Навигация и открытый материал остаются
отдельными предметами проектирования.
