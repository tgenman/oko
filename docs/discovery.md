# Око: продуктовое интервью

Обновлено: 2026-10-08. Интервью продолжается. Подтверждённые пожелания отделены от предложений; технические решения ещё не приняты.

## Результат проектирования

Пользователь согласился с предложенным результатом: описание первой версии, CJM, сценарии чтения, правила обработки, границы MVP и простой интерактивный макет для проверки сценариев. Подход — wayfinder: [карта открытых решений](../.scratch/oko-product/map.md) и последовательное обсуждение.

## Главный желаемый результат

Меньше мелких отвлечений и разрозненных мест, требующих внимания. Пользователь хочет убрать их из других приложений, чтобы там всё было прочитано, а решение «хочу / не хочу читать» принимать в Око.

Слова пользователя: «Самое главное для меня, что у меня станет меньше вообще отвлекающих маленьких вещей».

Для каждого Telegram-канала или приватной группы пользователь хочет настройку: автоматически отмечать полученное прочитанным либо делать это только после явной отметки соответствующей новости или summary просмотренными в Око. Связь сводки с исходными сообщениями согласована в решении [«Сжатие истории и отметка просмотра»](../.scratch/oko-product/issues/01-history.md); технические ограничения ещё требуют проверки. Реальных изменений в источниках не выполнялось.

Проверка 2026-10-08 выявила накопительную семантику отметки Telegram: она затрагивает все сообщения до выбранного ID, поэтому отдельная отметка более позднего сообщения без раннего не поддерживается обычным вызовом истории. [Исследование и границы проверки](research/telegram-read-state.md). Согласованы [отложенная синхронизация и отдельная настройка старой истории при подключении](../.scratch/oko-product/issues/11-read-sync-policy.md#answer).

## Текущий опыт: подтверждено пользователем

- Публичные Telegram-каналы читаются в News Explorer через RSSHub: https://github.com/diygod/rsshub.
- Приватные Telegram-каналы читаются в Telegram.
- У пользователя есть авторизованный клиент Telegram на Python и установленный MCP. Возможности и состояние доступа в этой сессии не проверялись.
- Подписки разделены на тематические папки. Их структура приложена на скриншоте и в OPML.
- В некоторых приватных каналах очень много публикаций. Пользователю интересен обзор встречающихся тем, а не чтение всех сообщений.

## Заявленные пожелания

- Единый UI для публичных и приватных Telegram-каналов, YouTube-каналов и RSS других сайтов.
- Telegram: доступны текст, картинки, кружочки, видео — весь материал публикаций.
- YouTube: видеть обновления, заголовки и краткое summary.
- Загрузка Telegram-медиа заранее, отсутствие скачивания YouTube-видео, получение полного текста RSS и показ неполного материала согласованы в решении [«Полнота материалов и поведение при недоступности»](../.scratch/oko-product/issues/05-media.md#answer). Там же подтверждены поведение без субтитров, обнаруженные правки и удаления источников.
- «Просмотрено» удаляет контент из Око — уточнение пользователя, заменяющее предложенное бессрочное хранение просмотренного. Точный состав удаления и сохраняемых служебных данных закреплён в том же решении. Сжатие истории и автопрочитывание Telegram сами по себе контент не удаляют.
- Хранение короткого описания события или смыслового отпечатка после просмотра отклонено для первой версии. Последствия для поздних повторов и обновлений закреплены в решении [«Повторы новости после удаления просмотренного»](../.scratch/oko-product/issues/12-dedup-after-view.md).
- Удалять из представления рекламные публикации и рекламные части материалов, в том числе на YouTube. Сохранение исходников, доступ к скрытому и исправление ошибок согласованы в решении [«Фильтрация рекламы и объединение новостей»](../.scratch/oko-product/issues/03-filtering.md). Работа с рекламными фрагментами видео ещё требует уточнения.
- Фильтровать по темам; исходный пример — исключать уголовную хронику из политических источников, включая «Медузу». Уточнённый фильтр с исключениями закреплён в том же решении.
- Повторы одной новости из нескольких источников объединять, суммаризировать и сопровождать ссылками. Область объединения, окно по умолчанию и обработка новых сведений и противоречий закреплены в том же решении.
- Первоначально упоминалась важность каналов и папок; пользователь уточнил: важность принадлежит фиду, цифры в названиях папок задают только порядок. Правила закреплены в решении [«Чтение по папкам и приоритеты»](../.scratch/oko-product/issues/04-reading.md).
- Для важных YouTube-каналов автоматически получать субтитры и делать тезисное summary, помогающее решить, интересен ли материал.
- Для выбранных приватных Telegram-каналов делать тезисные обзоры тем по множеству публикаций. Настраиваемые режимы, промпты и запуск согласованы в решении [«Правила фидов и промпты сводок»](../.scratch/oko-product/issues/02-prompts.md); конкретные значения для источников пока не выбраны.
- Основная навигация — тематические папки, как в News Explorer: группировки фидов по темам. Общий обзор всех тем не выбран основным экраном.
- Для чтения выбран вариант A: папки → список карточек → выбранный материал. Шкала важности, сортировка по времени публикации в обе стороны и по важности, массовая отметка папки и наследование обработчика согласованы в [решении по макету](../.scratch/oko-product/issues/07-prototype.md#answer).
- Принадлежность фида одной папке, счётчики карточек и кнопка копирования ссылки на оригинал согласованы в решении [«Чтение по папкам и приоритеты»](../.scratch/oko-product/issues/04-reading.md). «Сохранить на потом» исключено пользователем.
- Для отдельных фидов нужны настраиваемые правила представления: например, всегда получать summary по выбранному источнику. Состав и сочетания режимов, наследование настроек закреплены в решении [«Правила фидов и промпты сводок»](../.scratch/oko-product/issues/02-prompts.md).
- Паттерны сводок настраиваются через промпт. Режимы, расписание и ручное обновление закреплены в том же решении; готовые промпты и конкретные периоды для подписок ещё не заданы.
- После перерыва нужна явная кнопка «Сжать историю», в том числе для выбранных папок. Поведение исходников, повторного сжатия и отметок просмотра согласовано в решении [«Сжатие истории и отметка просмотра»](../.scratch/oko-product/issues/01-history.md). Автоматическое исчезновение старого непрочитанного не согласовано.
- Для каждого Telegram-канала или приватной группы отдельно настраивается автопрочитывание: при включении — после получения материалов Око; при выключении — после явной отметки новости или summary просмотренными пользователем. Открытие карточки само по себе не согласовано как отметка просмотра. Режим по умолчанию не выбран.
- Подкасты: обновления и summary тезисов — вторая очередь, вне первой версии.
- Удобное чтение сначала в браузере компьютера; расширение на другие устройства позже.
- Простой локальный запуск. Markdown для новостей и отдельное хранение промежуточного состояния / идентификаторов последних прочитанных постов допустимы как стартовый вариант, а не обязательный окончательный стек. Граница между последним полученным и последним прочитанным требует обсуждения.
- Предпочтительный обработчик — Codex; дополнительно нужны кастомные модели, включая локальные через Ollama. Галка фида «Разрешить обработку публичным AI» не запрещает свою локальную обработку. Условия запуска, индикатора и первоначального импорта записаны в решении [«Границы первой версии и ограничения обработки»](../.scratch/oko-product/issues/06-mvp.md#answer). Выполнимость подключений исследуется отдельно; платный API не выбран.
- Око работает только когда включено пользователем: открыть, оставить на обработку, затем читать. Постоянный сбор после закрытия Око отклонён. Это ограничивает ранее выбранное расписание сводок временем работы приложения.
