# Вход в общее Око

Постоянный Docker-читатель при открытии показывает только логин и пароль.
У всех логинов одинаковые права, общие настройки и материалы. «Просмотрено»
удаляет материал для всех. Регистрации и восстановления через почту нет.
Без настроенных логинов вход закрыт; старые ссылки с токеном и cookie прежнего
launcher не заменяют пароль. Разработка без `--persistent` сохраняет локальный
служебный сценарий с токеном; не публикуйте его в сеть.

## Локальные доступы

Команды выполняются из checkout с установленной `.venv`. Для рабочего экземпляра
по умолчанию используется `~/Library/Application Support/Oko/data`. Для отдельной
установки передавайте `--data /полный/путь/data`. Команды не запускают источники
и не перезапускают читатель. Изменения логинов начинают действовать сразу.

```sh
.venv/bin/python scripts/oko-access set dmitry
.venv/bin/python scripts/oko-access list
.venv/bin/python scripts/oko-access disable dmitry
```

`set` запрашивает пароль дважды без отображения. Допускаются 12–256 символов;
новый логин создаётся, существующий получает новый пароль. Обе операции смены
пароля и отключение немедленно отзывают все сессии этого логина.

Для случайного пароля можно создать **новый** приватный файл:

```sh
.venv/bin/python scripts/oko-access set dmitry --generate-to /приватный/путь/oko-password.txt
```

Пароль не печатается в stdout. Файл создаётся с правами `0600`, существующий файл
не перезаписывается. Сохраните пароль в своём менеджере паролей, затем удалите
файл. В `data/access.json` остаются только scrypt-хэши (N=131072, r=8, p=1,
случайная соль 16 bytes), хэши credentials, сроки сессий и короткое окно попыток
входа. Файл записывается атомарно под межпроцессным lock с правами `0600` и входит
в штатный backup данных. Резервные копии и приватный файл пароля не публикуйте.
Повреждённый access.json блокирует вход и административную перезапись до
разбора/восстановления из согласованной копии.

Сессия фиксированная на 30 дней. «Выйти» отзывает текущую сессию; выход
распространяется на вкладки того же браузера. Для каждого логина допустимо до
16 одновременных сессий, для установки до 128. При достижении лимита завершите
сессии либо смените пароль. За минуту допускается 5 попыток на логин и 30 всего;
перезапуск не обнуляет окно. Возобновление работы читателя не требует браузерного
входа: служебные воркеры и состояние питания независимы.

## HTTPS через Caddy

Это процедура будущей публикации. Пока внешний адрес не настроен, используйте
`http://localhost:8765` и не открывайте порт 8765 в интернет.

1. Выберите домен, настройте DNS на сервер с Caddy и доступ к нему по 80/443.
   Если сервер — этот Mac за роутером, нужен подходящий внешний IP и проброс
   только 80/443. Спящий Mac и остановленный Docker недоступны.
2. Создайте хотя бы один логин до публикации. Сохраните один внешний origin:

   ```sh
   .venv/bin/python scripts/oko-access origin https://oko.example.org
   ```

3. На **том же хосте**, что и reader, запустите Caddy с таким Caddyfile:

   ```caddyfile
   oko.example.org {
       reverse_proxy 127.0.0.1:8765
   }
   ```

   Caddy сохраняет исходный Host и управляет сертификатом и продлением.
   Используйте [официальную установку](https://caddyserver.com/docs/install)
   с запуском как службы. [Автоматический HTTPS](https://caddyserver.com/docs/automatic-https)
   требует доступного домена и портов. Не включайте журналы тел запросов входа.
   Туннель или отдельный VPS требуют собственного решения по приватному upstream;
   этот Caddyfile рассчитан на reader на том же хосте.
4. Остановите рабочее Око через `scripts/oko-release stop`, затем выполните
   `scripts/oko-release start` для применения
   origin. Сохранённая настройка переживает обновления. Порт reader остаётся
   опубликованным только на `127.0.0.1`, helper остаётся на `127.0.0.1:8767`.
   Не меняйте bind на `0.0.0.0` снаружи Docker и не публикуйте служебный bearer.
5. Из новой внешней браузерной сессии проверьте редирект HTTP→HTTPS, сертификат,
   форму, запрет прямого API/медиа без входа, успешный вход, выход и повторный
   запрет старой сессии. Проверьте недоступность 8765/8767 извне. Эта проверка
   относится к реальной публикации, синтетический TLS-тест её не заменяет.

Схема и Host внешнего origin берутся из конфигурации, не из X-Forwarded-*.
Uvicorn не доверяет proxy headers. Запросы изменения состояния и отправка формы
требуют точного Origin, посторонний CORS не разрешён. HTTPS-cookie — Secure;
локальный HTTP-вход сохраняет HttpOnly и SameSite=strict. Выход или отзыв
прекращают выдачу новых данных и дальнейших фрагментов защищённых потоков.
Потеря доступа очищает открытую вкладку при следующем запросе/проверке сессии
(до 5 секунд для активной вкладки; при возврате к вкладке выполняется проверка).
Уже увиденное и сохранённое пользователем содержимое удалённо отозвать нельзя.
