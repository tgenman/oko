# Python-окружение

Око использует Python `>=3.11,<3.15`, Poetry 2.5.1 и poetry-core 2.5.0. Верхняя граница соответствует закреплённому `youtube-transcript-api==1.2.4`. Версии runtime- и dev-библиотек задаёт `pyproject.toml`; принятый набор прямых и транзитивных зависимостей для разработки и CI фиксируется в единственном `poetry.lock`.

## Новый checkout

Установите CLI отдельно от окружения приложения, например через установленный pipx:

```sh
pipx install 'poetry==2.5.1'
poetry --version
```

Если Poetry уже установлен другим способом, обновите именно ту установку до 2.5.1. Конфигурация проекта проверяет требуемую версию CLI; Poetry не включается в runtime-зависимости Око.

Из корня checkout:

```sh
poetry env use python3.11
poetry check --lock --strict
poetry sync
poetry run python -m oko --demo
```

Проектный `poetry.toml` задаёт `.venv` внутри checkout. Стандартный `poetry sync` устанавливает также группу `dev`: тесты, генераторы API, типизацию и backend упаковки. Из активированного постороннего virtualenv сначала выйдите: Poetry может использовать уже активное окружение.

`poetry sync` устанавливает принятый lock, а не обновляет версии. Для намеренного изменения зависимостей обновите pyproject/lock отдельной задачей и проверьте diff. Не пересоздавайте lock при обычной установке или в CI. До сборки wheel нужны npm-зависимости и готовый фронтенд: [поставка](package.md). Runner и генераторы по-прежнему принимают `OKO_PYTHON`; обычно они используют `.venv/bin/python`.

## Переход существующего checkout

Сначала проверьте установку по lock в отдельном checkout. Когда потребуется переключить локальное окружение, штатно остановите свой экземпляр Око и выйдите из активированной `.venv`. Сохраните прежнее окружение под другим именем, затем выполните команды настройки выше. Не запускайте `poetry sync` поверх используемого процессом окружения: синхронизация может удалять пакеты, отсутствующие в lock.

Для отката восстановите согласованный прежний набор конфигурации, `uv.lock`, упаковщика и инструкций. Верните сохранённое окружение на исходный путь `.venv` либо создайте его заново по прежним инструкциям. Virtualenv не следует запускать из переименованного каталога: его scripts содержат абсолютные пути.

## CI и пользовательская установка

Ubuntu job использует Python 3.11, отдельную установку Poetry 2.5.1, проверку согласованности lock и `poetry sync`. Полный набор запускается через `poetry run ./scripts/check all`. Расширение Python/platform matrix — отдельная задача; проверки macOS выполняются на временных данных.

Wheel содержит готовый читатель, Swagger и API-контракт. Пользователь устанавливает его обычным installer; Poetry и Node для запуска не нужны. Обычный `pip install` разрешает зависимости по metadata wheel и не использует `poetry.lock`: гарантия lock относится к разработке и CI.
