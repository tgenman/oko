# Инструменты агента

## Чтение исходников

Начинайте с поиска нужного символа или раздела и ограничивайте длинные строки:

```sh
rg -n --max-columns 220 --max-columns-preview 'ExternalAttachments|originalText' frontend/src/reading
sed -n '30,65p' frontend/src/reading/external-attachments.tsx
```

Вывод с многоточием/усечением — указатель на место, а не полный источник для
правки. Выбранный фрагмент дочитайте адресно. Для длинного JSX выбирайте совпадение
или короткий участок, вместо вывода всего файла. Несколько независимых чтений
можно запускать вместе; общий лимит вывода должен вмещать выбранные выдержки.

## Снимок прототипа

Сначала запустите существующую команду прототипа. Затем:

```sh
npm run browser:snapshot -- --url 'http://127.0.0.1:5190/?variant=A' \
  --output /tmp/oko-prototype-A.png --ready '.tr-material'
```

Команда открывает только loopback HTTP(S), ждёт загрузку страницы/шрифтов и,
если указан, видимый `--ready` selector. Печатает путь, viewport и JS-ошибки;
при JS-ошибке сохраняет снимок и завершает работу с ненулевым кодом. Снимок нужно
просмотреть. `--width`/`--height` задают viewport; по умолчанию 1440×1000.

Выбор браузера общий с browser-тестами: `OKO_BROWSER_EXECUTABLE`, установленный
Google Chrome на macOS, затем стандартный Chromium Playwright. Отсутствующий
браузер не скачивается автоматически. Команда не запускает Runtime или подписки.

## Компактное ожидание CI

Подключённый GitHub-плагин остаётся основным способом работы с PR. Для ограниченного
ожидания без повторной выдачи полных списков steps доступна команда:

```sh
./scripts/ci-status --repo tgenman/oko --sha <полный-SHA-PR> --wait 60
```

Принимается только полный SHA; выбран последний запуск workflow `Checks` для
этого коммита. Вывод — JSON со статусом запуска и краткими jobs, только при изменении.
Коды: 0 — success, 1 — завершённый неуспех, 2 — ошибка доступа/ввода, 3 — ещё pending.
Отсутствие запусков остаётся pending. Без `--wait` команда делает один снимок;
ожидание ограничено 60 секундами с интервалом 30 секунд. Ошибка GitHub не выдаётся
за успех. `--workflow` выбирает другое имя workflow.

Для публичного репозитория токен не требуется, но действует лимит публичного API.
Для закрытого репозитория или большего лимита используйте уже настроенный `GH_TOKEN`
или `GITHUB_TOKEN` через окружение; команда не печатает токен. Если CLI-доступа нет,
используйте плагин: сравнивайте краткие name/status/conclusion, steps читайте лишь
при изменении или ошибке. Данные источника и изменившийся SHA проверяйте отдельно
перед merge: команда наблюдает CI, но ничего не публикует и не сливает.
