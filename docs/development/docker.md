# Docker и PostgreSQL

Рабочий экземпляр Око использует PostgreSQL. Выпуск обновляется по
[cloud deploy](cloud-deploy.md), резервное копирование и восстановление — по
[cloud backup](cloud-backup.md). Согласованный backup содержит дамп PostgreSQL,
медиа и конфигурацию. Копии одного каталога `data` недостаточно.

## Локальная разработка

Сначала подготовьте отдельную PostgreSQL-базу или схему и приватный файл DSN
по [инструкции PostgreSQL](postgresql.md). Примените миграции отдельной командой;
reader проверяет установленную схему и не создаёт таблицы при запуске.

Образ ожидает `/run/secrets/database-url`. Корневой `compose.yaml` монтирует
`$OKO_HOME/secrets/database-url` вместе с приватным ключом локального helper.
DSN должен быть доступен из контейнера: `localhost` в нём обозначает сам
контейнер, а не PostgreSQL на хосте. Данные публикаций принадлежат указанной
схеме, файлы медиа — каталогу `$OKO_HOME/data`.

В новой PostgreSQL-библиотеке сбор выключен. Start/Stop меняет сохранённое
состояние работы; `--persistent` продолжает работу при закрытии вкладки.
Перезапуск сохраняет ранее выбранное состояние.

## Старый локальный контроллер

`scripts/oko-release` сохраняет prepare/install/start/stop/open/status для
явно подготовленной локальной PostgreSQL-установки. File-only операции
update/rollback/backup/restore/migrate сняты: они завершаются до остановки
экземпляра или изменения данных. `scripts/update-working-oko` также отказывает
до fetch/build. Эти команды не должны объявлять успешным неполный backup БД.

Установленные каталоги и старые резервные копии автоматически не удаляются и
не импортируются. Для рабочего выпуска используйте проверенные процедуры
cloud deploy/backup, указанные выше. Исторические результаты старого локального
контроллера остаются в отчётах соответствующих версий.
