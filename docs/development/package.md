# Запуск читателя из checkout

Сборка wheel и проверки установленного пакета временно удалены. Поддерживаемый способ запуска — из репозитория с установленными зависимостями.

```sh
npm run build
uv run --locked python -m oko --demo
```

Для обновления чистого checkout и подготовки интерфейса используйте
`./scripts/update-checkout`: ошибка Git останавливает сборку, ошибка сборки —
валидацию. Команда не перезапускает Око. Подробности:
[обновление и проверки](check-workflow.md).

В работающем Око `/docs` показывает Swagger, `/openapi.json` — canonical contract. Кнопка Authorize принимает token локальной сессии; после неё Try it out → Execute отправляет запрос. Авторизация находится в памяти страницы и пропадает после загрузки нового документа. Swagger не получает token автоматически и не создаёт reader lease. Поэтому прежняя остановка Око без живой вкладки читателя действует и при открытой документации.

Когда читатель остановлен, используйте самостоятельный просмотр:

```sh
npm run api:docs
```

Его адрес — `http://127.0.0.1:8766/docs`; там нет API-вызовов и авторизации. Оба варианта используют локальные assets и не ослабляют CSP.

## Самостоятельный API v3

```sh
uv run --locked python -m oko --api-only --demo
```

Explicit-профиль работает до `POST /api/v3/stop`, без веб-сборки, Node и heartbeat. Обычный запуск читателя использует нейтральные client sessions; параметры lease/grace/renew приходят из status. Remote auth и мобильное приложение не поставляются. Проверка копии кода без assets/PATH находится в `tests/lifecycle/test_independent_lifetime.py`; она не означает наличие wheel/install workflow, который сейчас удалён.

## Откат перехода API

Остановите текущий процесс его v3 stop, дождитесь завершения workers и сделайте копию всего каталога данных (SQLite вместе с оставшимися WAL/SHM, настройками и content). Затем используйте предыдущий checkout и его согласованную сборку assets/DTO; клиент также должен поддерживать major этого checkout. Один digest нельзя смешивать между сборками. Переход HTTP v3 сам не удаляет материалы, настройки или source identity и не переписывает служебные записи; старые проблемы/receipts адаптируются при чтении. Восстановление резервной копии выполняют только при необходимости отката предметных изменений данных; замена API сама по себе не требует сброса или повторного подключения источников. Не запускайте две версии одновременно на одном каталоге данных.
