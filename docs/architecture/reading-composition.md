# Состав чтения

2026-10-09. Кандидат 1 архитектурного обзора. Пользователь согласовал ограниченный рефакторинг и проверки через interface читателя. Исходная база: `dc8e2f6`.

## Согласованный объём

Сосредоточить правила состава чтения в одном deep module: какие карточки представляют оригиналы, к какой тематической папке они относятся и какие исходные публикации охватывает «Просмотрено». Список карточек, подсчёт папки и разворачивание отметки используют одну implementation этих правил.

Сохранить согласованные продуктовые решения, формат SQLite/Markdown, маршруты читателя, сортировку и UI. Не добавлять сохраняемый снимок состава, миграцию, новый storage adapter или общий framework обработки.

Сохранить [управление работой](reader-work.md), [прогресс обзора](digest-progress.md) и [структуру пакетов](package-layout.md). Runtime владеет действиями, блокировкой, отменой и сетевыми ожиданиями. Store владеет транзакциями, файлами, заданиями удаления и восстановлением. Events и Digests создают и проверяют свои представления; этапы обзора не пересматриваются.

## Текущее трение

- `oko/storage/store.py`: `cards` исключает представленные оригиналы; `folder_contents` снова определяет их принадлежность через карточки и текущие папки фидов; `viewed` отдельно разворачивает событие или обзор в оригиналы.
- `oko/reader/app.py`: `reader_cards` дополняет принадлежность папке и важность; обработчики списка и счётчиков используют этот дополнительный набор правил.
- `oko/reviews/events.py`: `candidates` исключает публикации, уже представленные готовыми обзорами за период.

Простой перенос этих функций в отдельный файл не даёт depth: вызывающий код всё ещё должен согласовывать покрытие и принадлежность.

## Направление устройства

Разместить module состава чтения в `oko/reader`, с прямыми импортами по структуре пакетов. Его interface скрывает согласование карточек, папок и оригиналов; точные типы и имена методов выбрать при реализации. Не выставлять наружу набор промежуточных helpers, порядок вызовов которых должен знать caller.

Разделить сбор исходных данных и согласование состава так, чтобы не возник цикл: состав → Events → состав. Events и Digests остаются владельцами результатов и доступных оригиналов своих представлений. Правило исключения уже представленных обзором публикаций должно иметь одного владельца, а не копироваться в новом module.

Состав вычисляется для текущего действия или чтения; долговременный cache не нужен. Не сохранять контент в служебных данных подтверждения завершения папки. Существующие token, сравнение набора и повторное подтверждение после изменения остаются в Runtime.

## Сохраняемые правила

- Готовые карточки событий и обзоров представляют исходные публикации; эти оригиналы не дублируются самостоятельными карточками.
- Фильтр скрытых материалов влияет на отображение, но не исключает их из завершения папки.
- Незагруженные и нечитаемые оригиналы входят в завершение своей папки, если их не представляет доступный обзор другой папки.
- Готовый замороженный обзор папки сохраняет её принадлежность после перемещения фида. Завершение новой папки не удаляет оригиналы, которые продолжает представлять этот обзор.
- Оригиналы в наборе завершения учитываются один раз; количество карточек и количество оригиналов остаются разными величинами.
- «Просмотрено» для групповой карточки охватывает её исходные публикации. Фиксация и физическое удаление выполняются прежним путём Store/Runtime.
- Изменение состава между preview и подтверждением требует прежнего повторного подтверждения. Поздний ответ обработки не восстанавливает просмотренный контент.
- Сохраняются действующие правила пересечения обзоров, приоритет представления и важность фида. Новую политику разрешения пересечений не вводить.

## Проверка

Основной test surface — существующий interface читателя с временными SQLite/файлами и заменяемыми внешними adapters. Сохранить сценарии `tests/reader/test_folder_completion.py`, `tests/reviews/test_events.py`, `tests/reviews/test_digests.py`, удаления и восстановления.

Проверить согласованность списка карточек, счётчиков папок, preview завершения и результата удаления для:

1. Обычных публикаций, события и готового обзора за период.
2. Скрытых, ещё загружаемых и нечитаемых оригиналов.
3. Перемещения фида после замораживания обзора.
4. Пересекающихся представлений и уникального подсчёта оригиналов.
5. Изменения состава после preview и позднего ответа после «Просмотрено».

Добавлять проверки только для отсутствующих сценариев; существующие утверждения не ослаблять. Выполнить затронутые наборы, полный pytest и строгий mypy. Приёмку и ревью записать отдельно после реализации; в этой сессии тесты не запускались.

Locality: правила принадлежности и покрытия находятся в одном module. Leverage: список, счётчики и действия используют согласованный состав. Seam проходит между доступными исходниками/представлениями и их составом для читателя; существующие внешние adapters не меняются. Deletion test: удаление module снова распределит эти правила между его callers.

## Реализация

Дерево чтения расширяет `ReadingComposition` выбором фида и расчётом навигации. Счётчики папок, фидов и всех материалов считают уникальные непросмотренные исходные публикации, включая незагруженные, но исключая скрытые фильтром. Число карточек остаётся отдельной величиной. Фид выбирает также целиком события и обзоры с его исходниками; принадлежность закреплённого обзора папке сохраняется после перемещения фида. Поэтому счётчик папки может отличаться от суммы её фидов. Расчёт не хранится долговременно; HTTP навигация и прежний маршрут папок используют один источник правил. Полное поведение: [спецификация дерева чтения](../../.scratch/feed-sidebar/spec.md).

`oko/reader/composition.py` содержит `ReadingComposition` и `FolderContents`. Общий расчёт `represented_originals` разворачивает карточки в уникальные ID исходных публикаций; его используют список, набор завершения, одиночное «Просмотрено» и исключение уже представленных обзором исходников Events.

`ReadingComposition` собирает представления Events/Digests, дополняет карточки принадлежностью папке и важностью, определяет набор завершения и разрешает идентичность открываемого материала. Читатель больше не достраивает принадлежность папке. Существующий interface Store сохраняется для Runtime, а фиксация просмотра остаётся в `viewed_set`.

Events использует общий расчёт ID с готовыми результатами Digests напрямую, без обратного вызова `ReadingComposition`. Сбор представлений не замыкается на собственную сборку состава. Новый снимок в памяти между действиями не хранится; данные подтверждения по-прежнему состоят только из служебных ID.
