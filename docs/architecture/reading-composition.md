# Состав чтения

`oko/reader/composition.py` сосредоточивает правила выбора публикаций, принадлежности папке, навигационных счётчиков и охвата «Просмотрено». Список, счётчик и завершение чтения используют одно определение состава.

Каждая карточка представляет одну публикацию. Фид принадлежит одной текущей папке; принадлежность публикации и её важность определяются фидом. Фильтрация может скрывать материал, сохраняя исходник и возможность ручного восстановления. Тезисы принадлежат той же публикации.

Счётчики папок, фидов и всех материалов считают уникальные непросмотренные исходные публикации, включая незагруженные, но исключая скрытые фильтром. Число доступных карточек остаётся отдельной величиной. Расчёт не сохраняется долговременно; HTTP-навигация и выбор папки используют один источник правил.

«Всё просмотрено» охватывает непросмотренные публикации выбранной папки, включая скрытые, незагруженные и нечитаемые материалы. Подтверждение хранит служебные ID; изменения состава после подготовки подтверждения не должны незаметно расширять удаление. Завершение одной папки не затрагивает другую. Просмотр одной карточки относится только к её публикации.

Runtime владеет действиями, блокировкой, отменой и внешними ожиданиями; Store — транзакциями, файлами, заданиями удаления и восстановлением. Фиксация просмотра остаётся в `viewed_set`. См. [управление работой](reader-work.md) и [структуру пакетов](package-layout.md).

Проверять список, навигацию, скрытые и незагруженные материалы, перенос фида, изоляцию папок, подтверждение завершения и поздние ответы через существующий HTTP interface с временным хранилищем; действия читателя — через Playwright. [Порядок разработки](../agents/development.md) определяет команды.

## Показ прочитанных фидов

`NavigationFeed.has_unviewed` определяется в том же проходе по непросмотренным
публикациям до исключения скрытых фильтром. Скрытая, незагруженная или недоступная
публикация удерживает этот признак; видимые счётчики сохраняют прежний смысл.
Внешнее прочитанное Telegram его не меняет.

В дереве читателя по умолчанию скрыты фиды без непросмотренных публикаций и папки,
у которых не осталось показанных фидов. Кнопка варианта A из #31 возвращает их
на прежние места. Текущий фид/папка остаётся до смены выбора, включая просмотр
последнего материала и перемещение фида. Переключение меняет только локальное
представление; выбор, открытый материал, подписки и очередь сбора не меняются.
Предпочтение хранится в браузере для текущего origin, как ширина и раскрытие дерева.

## Действия фида

Контекстное меню варианта A из #33 открывается правым кликом либо ContextMenu /
Shift+F10; обычный клик по-прежнему выбирает фид. `feed-actions.tsx` владеет меню,
подменю папок, подтверждениями и актуальностью их ответов. Четыре английских действия:
Mark All as Read, Settings…, Move to Folder, Delete….

Завершение фида использует тот же Runtime/viewed_set, что завершение папки, с составом
`feed_contents` и токеном, привязанным к паре scope/identity. Охват включает скрытые,
незагруженные и нечитаемые публикации. При изменении состава требуется новое
подтверждение; использованный токен не завершает будущие поступления. Telegram
синхронизируется по существующей безопасной границе. Удаление фида остаётся локальным
и не создаёт оснований для внешней отметки прочитанного.

Поздний ответ завершения и межвкладочное feed-viewed только инвалидируют снимок:
открытый материал согласуется с актуальными карточками. Очистка целого текущего фида
по старому ответу недопустима, поскольку после captured token могла прийти новая
публикация. Settings использует существующего владельца настроек, перенос — текущий
feed patch; успешное удаление согласуется с существующим журналом очистки MenusOwner.

## Действия отдельной карточки

`news-actions.tsx` владеет контекстным меню варианта A из #35, подсветкой,
подтверждением диапазона и его последовательным выполнением. `list.tsx` передаёт
снимок текущего порядка карточек и ключ области/сортировки/показа скрытых. Above/Below
исключают цель; подтверждение фиксирует точные ID и не расширяется новыми поступлениями.
При смене области неотправленные команды прекращаются; принятые просмотры не откатываются.
Частичный сбой останавливает диапазон, автоматического повтора нет. Используются
существующие per-material viewed и receipts, без нового серверного batch API.

Поздний результат согласуется по ID публикации, не по фиду или всему текущему списку.
Закрытие уже закрытого меню не обновляет список: это сохраняет порядок native и React
событий controlled селекторов. Освобождение выполняемого запроса уведомляет актуальный
store без замены нового target/generation. Ссылки открытия/копирования берутся из
source_url карточки, а не из адресов API или reader.
