# Состав чтения

Для каналов Telegram, RSS, статей и YouTube действует
[единый пайплайн](latest-publication.md). Постоянной истории версий, Restore и
выбора истории по дате в UI/API нет; группы Telegram не поддерживаются.
Вкладка может удержать старое открытое содержимое только в памяти.

`oko/storage/composition.py` сосредоточивает правила выбора публикаций, принадлежности папке, навигационных счётчиков и охвата «Просмотрено». Список, счётчик и завершение чтения используют одно определение состава.

Каждая карточка представляет одну публикацию. Фид принадлежит одной текущей папке; принадлежность публикации и её важность определяются фидом. Фильтрация может скрывать материал, сохраняя исходник и возможность ручного восстановления. Тезисы принадлежат той же публикации.

Счётчики папок, фидов и всех материалов считают уникальные непросмотренные исходные публикации, включая незагруженные, но исключая скрытые фильтром. Число доступных карточек остаётся отдельной величиной. Проекции счётчиков хранятся в PostgreSQL и обновляются вместе с изменениями состава; HTTP-навигация и выбор папки используют один источник правил.

«Всё просмотрено» охватывает непросмотренные публикации выбранной папки, включая скрытые, незагруженные и нечитаемые материалы. Подтверждение хранит служебные ID; изменения состава после подготовки подтверждения не должны незаметно расширять удаление. Завершение папки охватывает её публикации; общая Publication завершает чтение во всех своих принадлежностях. Несвязанные публикации другой папки не затрагиваются. Просмотр одной карточки относится только к её публикации.

ReaderApplication владеет действиями, Execution — общим допуском и внешними ожиданиями; JobControl — отменой и заданиями удаления, Store — транзакциями, файлами и восстановлением. Фиксация просмотра остаётся в `viewed_set`. См. [управление работой](reader-work.md) и [структуру пакетов](package-layout.md).

Проверять список, навигацию, скрытые и незагруженные материалы, перенос фида, изоляцию папок, подтверждение завершения и поздние ответы через существующий HTTP interface с временным хранилищем; действия читателя — через Playwright. [Порядок разработки](../agents/development.md) определяет команды.

## Показ прочитанных фидов

`NavigationFeed.has_unviewed` определяется в том же проходе по непросмотренным
публикациям до исключения скрытых фильтром. Скрытая, незагруженная или недоступная
публикация удерживает этот признак; видимые счётчики сохраняют прежний смысл.
Внешнее прочитанное Telegram его не меняет.

В дереве читателя по умолчанию скрыты фиды без непросмотренных публикаций и папки,
у которых не осталось показанных фидов. Кнопка варианта A из #31 возвращает их
на прежние места. Текущий фид/папка остаётся до смены выбора, включая просмотр
последнего материала и перемещение фида. Переключение меняет только локальное
представление; выбор, открытый материал, подписки и очередь сбора не меняются.
Предпочтение хранится в браузере для текущего origin, как ширина и раскрытие дерева.

## Действия фида

Контекстное меню варианта A из #33 открывается правым кликом либо ContextMenu /
Shift+F10; обычный клик по-прежнему выбирает фид. `feed-actions.tsx` владеет меню,
подменю папок и отдельным представлением подтверждения; общие правила завершения
фида и папки принадлежат `completion.ts`. Четыре английских действия:
Mark All as Read, Settings…, Move to Folder, Delete….

Завершение фида использует те же ReaderApplication/viewed_set, что завершение папки, с составом
`feed_contents` и токеном, привязанным к паре scope/identity. Охват включает скрытые,
незагруженные и нечитаемые публикации. При изменении состава требуется новое
подтверждение; использованный токен не завершает будущие поступления. Telegram
синхронизируется по существующей безопасной границе. Удаление фида остаётся локальным
и не создаёт оснований для внешней отметки прочитанного.

Поздний ответ завершения и межвкладочное feed-viewed только инвалидируют снимок:
открытый материал согласуется с актуальными карточками. Очистка целого текущего фида
по старому ответу недопустима, поскольку после captured token могла прийти новая
публикация. Settings использует существующего владельца настроек, перенос — текущий
feed patch; успешное удаление согласуется с существующим журналом очистки MenusOwner.

## Действия отдельной карточки

`news-actions.tsx` владеет меню и подтверждением; `list.tsx` передаёт
уже показанные карточки в текущем порядке. Above/Below исключают цель и
фиксируют точные ID, не охватывая незагруженные карточки или новые поступления.
`POST /cards/read` сохраняет просмотр всего набора одной транзакцией; отсутствующие
ID пропускаются, повтор безопасен. Закрытие подтверждения не отменяет уже
отправленную команду. [Контракт карточек](cards-http-design.md).

Принятый просмотр из контекстного меню очищает открытый материал, только если его ID совпадает с просмотренной карточкой. Поздний результат согласуется по ID публикации, не по фиду или всему текущему списку.
Закрытие уже закрытого меню не обновляет список: это сохраняет порядок native и React
событий controlled селекторов. Освобождение выполняемого запроса уведомляет актуальный
store без замены нового target/generation. Ссылки открытия/копирования берутся из
source_url карточки, а не из адресов API или reader.

## Подтверждение завершения фида и папки (#38)

`frontend/src/reading/completion.ts` скрывает получение состава и токена,
подтверждение, конфликт состава, блокировку повторной отправки по scope/ID и допуск
поздних ответов. Его interface — open/confirm/close и наблюдаемое состояние.
Отдельные представления фида и папки не управляют поколениями завершения.
Существующий reader command adapter сохраняет учёт исходов и receipts.

Закрытие лишает старый запрос права менять диалог, но отправленная команда продолжает
выполняться. Блокировка живёт до завершения запроса независимо от показа; другие
объекты не блокируются. При composition_changed показывается новый токен/количество,
нужно повторное явное подтверждение. При неизвестном исходе старое подтверждение
теряет токен, автоматического replay нет; Status проверяет исход. Новое открытие
получает актуальный состав и требует явного действия пользователя.

Результат любого отправленного завершения и межвкладочные folder-viewed/feed-viewed
инвалидируют снимок и запускают авторитетное согласование карточек. Это относится
и к ошибке после уже принятого просмотра. Список/открытый материал не очищаются
целиком по принадлежности папке или фиду; новые и посторонние публикации сохраняются.
ReaderApplication, Store, серверные токены и правила Telegram не меняются. Above/Below
остаётся отдельной последовательностью captured ID.

## Действия тематической папки

Контекстное меню папки использует выбранный вариант A: Mark All as Read, Settings…,
Rename…, разделитель и Delete…. Правый клик и ContextMenu / Shift+F10 фиксируют
папку по внутреннему ID без смены области чтения и раскрытия дерева.
`folder-menu.tsx` владеет меню, диалогами переименования/удаления и временем их жизни;
`folder-actions.tsx` выполняет существующее завершение папки по явной цели.
Поздние ответы и folder-viewed инвалидируют снимок; новый материал той же папки
согласуется по актуальным карточкам и не очищается по старому подтверждению.

ID папки независим от названия: новые папки получают случайный непрозрачный ID,
существующие сохраняют ID и все связи. RSS/YouTube и Telegram разрешают название
создаваемой/выбираемой папки в ID в одной транзакции; имя не является ключом связей.
Rename меняет только title, сохраняя фиды, настройки, материалы и локальный выбор.
Удаление допускается только при отсутствии всех фидов, включая недоступные и ещё
удаляемые. Store проверяет это атомарно с удалением папки и её настроек; ReaderApplication
сериализует команду с переносом и добавлением фидов. Непустая папка показывает
Folder Is Not Empty. Пустые папки доступны через Show Read.

Проверять через HTTP с временным хранилищем и Playwright: сохранение старых ID,
повторное использование названия, сохранение настроек, пустоту по наличию фидов,
поздние ответы и смену цели. Прототип сохранён в архивной ветке по
[указателю](../agents/prototype-archive.md).

## Стоимость чтения (#53)

HTTP-навигация, карточки и открытый материал используют один синхронный снимок
чтения. Повторно используются настройки по уровням наследования, сведения о фиде,
текущая/предыдущие версии, подписи обработки, принятые тезисы и файлы результатов.
Снимок ограничен одним построением ответа и освобождается до возврата из endpoint;
внутри него нет await или записей. Между запросами данные читаются заново.
Он не обещает атомарности нескольких HTTP-запросов.

Состав ограничивается фидом/папкой в SQL до чтения файлов. Карточка строится из
общих сохранённых фактов и одного текста для превью, без создания полного
производного display_text. Навигации достаточно состояния фильтра; открытие
материала получает только свой фид. Частичный индекс непросмотренных публикаций
поддерживает порядок published DESC, не включая просмотренный архив.

Общие принадлежности, глобальная карточка, повторная история и удержание зависимостей
описаны в [общих публикациях](shared-publications.md).


## Пакетное чтение PostgreSQL (#158)

ReadingQueries/ReaderFacts собирают сведения запрошенных фидов и материалов
пакетами до 400 идентичностей. История, привязки и аватары фидов, прямые
связанные публикации и принадлежности для разрешения публичного AI читаются
для выбранных ресурсов. Факты материалов используются только внутри
синхронного снимка; согласование проблем, которое пишет в БД, остаётся снаружи.
Неизменившиеся версии не требуют повторной сборки ресурсов.

Preview завершения читает точные идентичности и Telegram members. Доступность
карточки проверяется по тем же сохранённым входам, что при чтении; полный
читательский ответ и сниппеты для подсчёта не строятся. Массовое завершение
сохраняет факты принадлежности для read-sync, удаляет выбранные принадлежности,
затем один раз вычисляет достижимость от оставшихся корней. Сохранение просмотра
и заданий очистки остаётся транзакционным; файловая очистка выполняется после
commit существующим владельцем работы.

Состояние сбора использует общую классификацию, но отдельные объёмы данных:
сводка выбирает необходимые скалярные поля диагностики, подробности читают
только выбранный фид. Старый пересчёт версий полного списка удалён; чтение карточек использует cursor и ETag.
