# Независимая загрузка медиа (#92)

Telegram Web на перенесённом хранилище сохраняет текст и описания медиа до
скачивания файлов. Готовое содержимое discover не вызывает лишний fetch.
Старое хранилище и другие источники продолжают прежний путь.

`MediaReference.resource_identity` — необязательное непрозрачное подтверждение
версии ресурса от адаптера. Store не разбирает locator: подтверждённый тот же
ресурс сохраняет MediaFile.id при смене подписи URL; новый или неподтверждённый
ресурс получает новый ID. `name` содержит исходное имя или пустую строку,
а не локальный путь. Имена временной проекции читателя генерируются из ID.

Текущий HTTP-путь media принимает MediaFile.id для нового пайплайна. Замена
ресурса меняет URL; старый URL не выдаёт новые байты. Локальные имена прежних
источников сохраняются. `media_ids` и блоки content следуют порядку источника.

`Runtime` выполняет download_media в отдельной lane существующего цикла.
Сбор метаданных не ожидает файлов. `Store.media` владеет staging, конечными
путями и фиксацией. Удалённая или заменённая работа теряет поколение; зависшая
старая операция отсоединяется, её поздний результат не публикуется.

Порядок сохранения: поток во временный файл → проверка размера → fsync →
перемещение → fsync каталогов → короткая принимающая транзакция. Она проверяет
поколение и владельца, сохраняет ready и завершает Job. Падение до коммита
не делает файл доступным. После коммита проекция восстанавливается из SQLite.
Настоящий пустой файл имеет size_bytes=0 и может быть ready; неизвестный размер
остаётся NULL. Пустое изображение/видеопоток не принимается как корректное медиа.

До выделения связанных публикаций в #94 Telegram Web на новом пути запрашивает
у Telegraph текст и описания ресурсов без скачивания этих ресурсов. Они проходят
те же MediaFile/Job. При ошибке статьи сохраняется её последняя доступная копия
вместе с новым текстом поста. Прежние источники используют прежний enrich; общий
разбор статьи один. Это переходный режим, не рекурсивный обход ссылок.

Job хранит retry_delay, UTC retry_at и wait_scope. Временные ошибки повторяются
без предела с удвоением задержки. После рестарта UTC-срок переводится в часы
текущего процесса. failed ждёт ручного повтора, unavailable хранит ограничение.
Повтор вручную сохраняет backoff и вынужденные сроки источника. Успех сбрасывает
задержку. Ошибка одного файла сохраняет доступный текст и остальные файлы.

Глобальные настройки: GET `/api/v3/settings/retries`; PATCH
`/api/v3/settings/oko/global` принимает retry_initial_seconds/retry_max_seconds.
Значения по умолчанию 60/3600 секунд; NULL сбрасывает значение. Максимум должен
быть не меньше начального значения. Эти настройки не меняют правила ИИ-обработки.

Очистка раз в час работает вне транзакции. Удаляются файлы без записей MediaFile
и остатки незавершённых загрузок. Активные временный и конечный пути защищены
с момента допуска до завершения принятия, включая промежуток move → commit.

Общая политика повторов fetch/download_media находится в
`storage/collection_jobs.py`; вызывающий код владеет транзакцией. Частичный текст
и срок повторного fetch принимаются вместе. Ошибки отдельных медиа и notice
не останавливают загрузку статьи; временные ошибки других статей продолжают
повторяться при постоянной ошибке одной из них.

Фактическая проверка и ограничения: [отчёт #92](../verification/independent-media-92.md).
