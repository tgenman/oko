# HTTP-контракт списка карточек

Согласовано 27 октября 2026. Контракт реализуется в ветке задачи #168;
это не подтверждение выпуска на рабочем экземпляре. Пользователь подтвердил,
что совместимость со старым v3-контрактом не требуется. Он заменяет прежний
универсальный протокол карточек и промежуточный вариант PR #167. [Кратко для человека](../human/cards.md).

## GET /cards

Ниже пути записаны без общего префикса `/api/v3`.
Один endpoint обслуживает All Items, тематическую папку и фид.
Тела запроса нет; параметры передаются в query string.

| Параметр | Правило |
| --- | --- |
| `folder` | ID тематической папки; необязательный |
| `feed` | ID фида; необязательный; одновременно с `folder` не допускается |
| `sort` | `newest` или `oldest`; по умолчанию `newest` |
| `show_hidden` | Показывать скрытые; по умолчанию `false` |
| `limit` | Размер порции; по умолчанию 40 |
| `cursor` | ID первой карточки запрашиваемой порции, включительно; в первом запросе отсутствует |

Без `folder` и `feed` выбираются All Items. Порядок — по времени публикации
в выбранном направлении, при одинаковом времени — по ID для однозначности.
Сортировка по важности в целевой контракт не входит.

```http
GET /cards?folder=product-id&sort=newest&limit=40
```

Ответ `200 OK`, заголовок `ETag` и JSON:

```json
{
  "items": [{
    "id": "card-123",
    "title": "Заголовок публикации",
    "feed_id": "feed-7",
    "published_at": "2026-10-27T12:00:00Z",
    "source_url": "https://example.org/article",
    "preview_url": null,
    "loading": false,
    "changed": false,
    "hidden": false,
    "post_web_unavailable": false,
    "external_attachment_kinds": []
  }],
  "total": 1250,
  "next_cursor": "card-124"
}
```

`total` — число карточек всей выбранной области с учётом фильтров, а не размер
порции. `next_cursor` — ID первой карточки следующей порции; `null` означает
конец. Пустая выборка: `items: []`, `total: 0`, `next_cursor: null`.

### Поля карточки

| Поле | Назначение |
| --- | --- |
| `id` | Идентичность карточки, выбор и отметка просмотра |
| `title` | Заголовок строки списка |
| `feed_id` | Источник; название фида берётся из навигации |
| `published_at` | Дата публикации; `null`, если неизвестна |
| `source_url` | Открытие оригинала и копирование ссылки в меню |
| `preview_url` | Превью; `null`, если отсутствует |
| `loading` | Надпись Loading |
| `changed` | Надпись Updated |
| `hidden` | Отметка скрытого материала |
| `post_web_unavailable` | Значок ограничения веб-доступа Telegram рядом с превью |
| `external_attachment_kinds` | Значки внешних вложений рядом с превью; пустой массив, если их нет |

Полный текст, сниппет, тезисы, результаты фильтрации и полный перечень медиа
не входят в карточку. Открытый материал загружается отдельно.

### Продолжение и потеря курсора

```text
Список: A B C D E
Первая порция: A B; next_cursor=C
Запрос cursor=C: C D; next_cursor=E
Запрос cursor=E: E; next_cursor=null
```

Сервер определяет позицию по карточке курсора. Удаление уже показанных A или B
не мешает запросу от C. Новые карточки до курсора появляются при проверке
начала списка, после курсора — при продолжении. Замороженного снимка порядка,
хранения позиций удалённых карточек и специального межвкладочного протокола нет.
Базовый сценарий проектирования — одна вкладка.

Если карточки курсора больше нет в выбранном списке:

```http
409 Conflict
```

```json
{"code": "cursor_expired"}
```

Клиент очищает показанный список и начинает без курсора, сохраняя фильтры и
сортировку. Смена фильтра или сортировки тоже начинает список заново.

### Видимая часть и новые карточки

Периодически повторяется тот же GET: `cursor` указывает на начало видимого
участка с небольшим запасом, `limit` ограничивает этот участок. Накопленные
при прокрутке сотни карточек целиком не запрашиваются. При смене видимого
участка меняются параметры запроса.

Клиент передаёт `If-None-Match` с ETag именно соответствующего запроса:

- `304 Not Modified`, без тела — участок не изменился;
- `200 OK` — актуальные `items`, `total`, `next_cursor` и новый ETag;
  клиент обновляет этот участок, не перезапрашивая остальной список;
- `409 cursor_expired` — перезапуск списка по правилу выше.

Начало выбранного списка проверяется отдельно тем же GET без курсора.
Если появились новые карточки, пока пользователь внизу, показывается
«Есть новые» без автоматического сброса прокрутки. При сортировке oldest
новые поступления дополнительно обнаруживаются тем же GET с sort=newest и
первой порцией. По нажатию «Есть новые» сортировка переключается на newest.
Проверка видимого участка
не заменяется периодическим запросом всего загруженного префикса.
Второго режима GET со списком `ids` нет.

При повреждённых сохранённых данных карточка показывается с заголовком
«Публикация недоступна», без превью и значков, и включается в счётчик.
Если ссылка повреждена, `source_url` равен `null`, действия со ссылкой недоступны.
Остальные карточки остаются доступны; фид и папка учитывают её при завершении.

## POST /cards/read

```http
POST /cards/read
Content-Type: application/json
```

```json
{"ids": ["card-1", "card-2", "card-3"]}
```

Команда отмечает просмотренными ровно перечисленные ID. В терминах Око
«Просмотрено» сохраняет своё значение из [глоссария](../../GLOSSARY.md):
это завершение разбора с удалением собранного содержимого и результатов,
а не просто открытие карточки.

Above/Below формирует список ID на стороне браузера из карточек, уже показанных
пользователю, в текущем порядке, исключая выбранную карточку. Незагруженные
карточки и последующие новые поступления не расширяют отправленный набор.
Охват больше не определяется сервером по всей папке или всему списку.

- Уже просмотренные или удалённые ID пропускаются.
- Сохранение выполняется одной транзакцией; частичного успеха нет.
- Успех: `204 No Content`, без тела. Браузер убирает перечисленные карточки.
- Ошибка сохранения: `5xx`, без частичного успеха. Потерянный ответ может
  означать уже выполненную команду: интерфейс сообщает, что исход не подтверждён
  и явный повтор безопасен. Автоматического повтора нет; отдельных результатов
  по ID и receipt у этой идемпотентной команды нет.

Команда идемпотентна. Атомарность относится к сохранению просмотра в БД.

## Что заменяется в архитектуре

| Прежний путь списка | Целевое решение |
| --- | --- |
| `POST /reading/check`, `kind: list/card` | Предметный `GET /cards` |
| `storage_id`, `known_version`, `known_cards` в запросе карточек | Query-параметры и HTTP ETag / If-None-Match |
| Полный массив ID состава в ответе | Только порция `items`, число `total`, `next_cursor` |
| `card_limit` и растущий префикс на клиенте | Cursor/limit для порции и видимого участка |
| Подготовка всех заголовков незагруженного диапазона | Явные ID уже показанных карточек |
| Серверный preview/token диапазона (обсуждённый и отклонённый вариант) | Не вводится |
| Последовательные per-card команды Above/Below | Один транзакционный `POST /cards/read` |

Путь и пересчёт версий старых списков удаляются без слоя совместимости.
Таблица старых списков не удаляется миграцией; остальные сохранённые версии
и весь `reading/check` сохраняются: статус, навигация и открытый материал
разбираются отдельно. Новый контракт не содержит универсального пакета ресурсов.
Охват отдельного действия завершения всей папки/фида этим решением не меняется.

## Границы согласования

Зафиксирован HTTP interface и поведение списка. Не согласованы детали
реализации: вычисление ETag, ограничения размера запросов, положение неизвестных
дат, точная частота опроса и согласование границ обновляемого участка при
изменении его состава. Здесь они не выдаются за принятые решения.
В реализации limit ограничен диапазоном 1–200; неизвестные даты идут после
известных, одинаковые даты упорядочены по ID. Интервал проверки — примерно
одна секунда после завершения предыдущей; видимый участок включает запас 150 px.
ETag связывает параметры, состав страницы, общее количество и версии её карточек.
Выпуск и перезапуск рабочего экземпляра выполняются отдельно.
