# Общая публикация и чтение

Publication определяется внешним ключом адаптера `(platform, external_id)`.
FeedPublication задаёт все её принадлежности. Повторное обнаружение существующего
ключа добавляет принадлежность; сравнение текста не объединяет публикации.

Карточка остаётся глобальной: её подпись, важность и основной фид одинаковы
в полном и селективном HTTP. Область списка выбирает принадлежности, не создаёт
варианты карточки или результата обработки. Основной фид — первый владелец;
при его удалении выбирается оставшийся. Один проход обработки сохраняет один
набор правил. Действующие запреты публичного AI всех используемых исходников
проверяются независимо от выбора правил; изменение разрешений отклоняет поздний
результат.

Основной фид отмечается на одной из строк `feed_publications`; публикация не
хранит вторую копию принадлежности. При удалении основной связи выбирается
оставшаяся. Чтение получает владельца через `items_read`, а выбор по фиду —
через прямые запросы к `feed_publications` и `publications`; для незавершённой
очистки владелец берётся из задания удаления. `is_unviewed` в связи — индексируемая проекция `items.viewed`, обновляемая
операцией Python в той же транзакции, а не отдельная отметка пользователя. Если последняя связь
уже удалена, владелец незавершённой очистки хранится в `delete`-задании до её
завершения; это не возвращает публикацию в состав чтения.

Списки, счётчики и подтверждение завершения используют `feed_publications` —
сохранённые принадлежности FeedPublication.
Общий материал считается один раз в папке и во всей библиотеке, один раз в каждом
своём фиде. Скрытые/ожидающие публикации входят в состав завершения чтения.
Изменение принадлежности пересчитывает только затронутые фиды/папки/списки перед
commit. Изменение медиа или metadata не запускает пересчёт всей библиотеки.

Просмотр убирает все принадлежности чтению. Данные, ещё нужные другому корню,
сохраняются как зависимость. Удаление фида убирает его принадлежности и меняет
владельца общих публикаций; выполняемые задания получают новое поколение.
Файловое задание возвращается в pending у оставшегося владельца, а старый ответ
не проходит допуск. Просмотр не создаёт подтверждение чтения для удалённого фида.

Store определяет нужные публикации рекурсивным SQL от оставшихся корней.
Недостижимые зависимости, включая циклы, отменяют задания и получают обычную
очистку. Self-link не создаётся. Физическое удаление ждёт активное сохранение.
Для канонических публикаций после очистки не остаётся viewed/tombstone записи,
которая запрещала бы повторное обнаружение. Группы Telegram не поддерживаются.

Регулярный курсор не меняется от просмотра. Новый явный count-проход Telegram
получает новую фиксированную границу; отмена завершает его сохранённое окно,
следующие сообщения доступны обычному сбору. Сам формат cursor принадлежит адаптеру.

Исторический офлайн-перенос выпуском 9ae1b50 объединял старые копии только по уже вычисленному внешнему ключу,
при совместимых текущих текстах и файлах. Карта old_id → new_id сохраняется в отчёте.
Альтернативные результаты остаются в backup и отмечаются в unportable; несовместимые
снимки или противоречивая идентичность блокируют публикацию перенесённого хранилища.
