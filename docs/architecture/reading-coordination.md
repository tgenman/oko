## Модуль и interface

`frontend/src/reading/coordination.ts` скрывает полный цикл загрузки состояния,
навигации и карточек, допуск ответов и последствия действий. Его вызывающий код
может запустить чтение, запросить обновление, сообщить об изменении данных,
открыть материал из панели состояния, получить имя объекта и остановить Око.
Для этого не нужны поколения, порядок обновления владельцев или ID текущей области.

Внутри module создаются существующие владельцы списка, дерева, открытого материала
и действий. Их implementation и владение ресурсами сохраняются. Начальная
загрузка и дальнейшее обновление проходят через один цикл. Каждая попытка
проверяет и изменение содержания, и порядковый номер запроса после внешних
ожиданий; устаревший ответ не обновляет актуальный показ. Несколько запросов
не объявляются единым транзакционным снимком сервера.

## Сохраняемое поведение

- Просмотр одной публикации из открытого материала, контекстного меню и другой
  вкладки использует одно локальное согласование: диагностика, открытый материал
  и строка списка очищаются только по ID публикации. Сообщение другой вкладки
  не отправляется обратно. Диапазон сохраняет последовательное выполнение.
- Завершение фида инвалидирует чтение и согласуется с актуальными карточками;
  новый материал после captured token не очищается по одному лишь ID фида.
- Завершение папки сохраняет существующее согласование по папке. Подтверждения,
  токены и правила конфликтов остаются у владельцев действий.
- Смена области, порядка и показа скрытых материалов лишает старые запросы права
  менять текущий список. Выбор области читается у дерева, без второй копии ID.
- Список владеет строками, фокусом и прокруткой; открытый материал — своей сессией,
  версиями и медиа; настройки — черновиками и навигацией.
- `reader-session.ts` владеет опросом, heartbeat, BroadcastChannel и событиями
  страницы. Модуль согласования подключает эти события, не дублируя ресурсы.
- Остановка, закрытие страницы и потеря связи сохраняют текущие правила очистки
  и допуска. Успешная серверная запись не откатывается закрытием формы.

## Проверка

Seam проверки — существующий настоящий браузер с управляемым HTTP adapter.
Проверки наблюдают список, открытый материал, подтверждения и действия, а не
внутренние счётчики module. Сохраняются существующие сценарии поздних ответов,
просмотра в другой вкладке, обновления при прокрутке, сортировки, скрытых
материалов, переноса/удаления фида и новых поступлений после завершения фида.
Новые внутренние тестовые seams не вводятся; перенос сам по себе не требует
переписывать тесты. Личные источники и настоящий обработчик не запускаются.

Фактические запуски записываются отдельно:
[отчёт проверки](../verification/reading-coordination.md).
