# Обработка последнего состояния Publication (#93, в работе)

Целевой путь использует существующие Filters/PublicationTheses и jobs.
Runtime запускает отдельные периодические проходы фильтра и тезисов; предыдущий
этап меняет Publication.status. Общий лимит выполнения модели остаётся прежним.
Прежние источники используют старое согласование до их миграции.

Подписи целевого пути учитывают текст/цитаты, название, правила этапа,
обработчик, адрес локального обработчика и разрешения. Смена файла или его
временного URL сама по себе не инвалидирует текст. filtered_content обновляет
ссылки на новые MediaFile без повторного обращения к модели.

Результаты читаются из JSON Publication; файлы являются совместимой проекцией.
processing_metadata хранит подписи входа/правил, фактический обработчик, модель,
параметры и время завершения; _pass фиксирует выбранный фид и настройки.
Проверенные точные удаления получают publication_id/block_index/text,
блоки — source_publication_id. filter_out сохраняет пустой blocks и причину.
Restore для целевого пути отклоняется; can_restore=false скрывает кнопку.

Подтверждённый пустой вход завершается без модели с reason=no_input.
Обработка доступного текста не зависит от готовности медиа. Общие сохраняемые
повторы fetch/filter/theses/download_media используют collection_jobs.
Проверенные результаты прежней схемы переводят подписи при офлайн-миграции.

Это промежуточная реализация. Ещё нужны проверки неудачной регенерации,
поздних ответов, отзыва разрешений, недоступного входа, настроек всего прохода,
браузерная приёмка, полное ревью и итоговый прогон. Документ не означает готовность #93.
