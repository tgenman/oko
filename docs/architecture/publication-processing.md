# Обработка последнего состояния Publication (#93)

Целевой путь использует существующие Filters/PublicationTheses и jobs.
Runtime запускает отдельные периодические проходы фильтра и тезисов; предыдущий
этап меняет Publication.status. Общий лимит выполнения модели остаётся прежним.
Группы Telegram не поддерживаются; каналы используют этот же путь.

Подписи целевого пути учитывают текст/цитаты, название, правила этапа,
обработчик, адрес локального обработчика и разрешения. Смена файла или его
временного URL сама по себе не инвалидирует текст. filtered_content обновляет
ссылки на новые MediaFile без повторного обращения к модели.

Результаты читаются из JSON Publication; постоянных файлов результатов на целевом пути нет.
processing_metadata хранит подписи входа/правил, фактический обработчик, модель,
параметры и время завершения; _pass фиксирует выбранный фид и настройки.
Проверенные точные удаления получают publication_id/block_index/text,
блоки — source_publication_id. filter_out сохраняет пустой blocks и причину.
Restore и поле can_restore удалены из HTTP и UI.

Подтверждённый пустой вход завершается без модели с reason=no_input.
Обработка доступного текста не зависит от готовности медиа. Общие сохраняемые
повторы fetch/filter/theses/download_media используют collection_jobs.
Одноразовый перенос прежних результатов выполнен выпуском 9ae1b50; в текущем коде переводчика старых подписей нет.

При выключении и повторном включении прежних правил отменённая Job снова
выполняет нужный этап. Изменение фильтра согласует reader_visibility в той же
транзакции: список и счётчики, включая новую загрузку страницы, видят актуальное скрытие.

Настройки запроса и версия берутся из _pass; актуальность проверяется отдельно
по действующим правилам. Выбор будущих параметров Codex не инвалидирует готовое;
локальная повторная попытка записывает модель и параметры, фактически отправленные
этому обработчику. Конфигурация невыбранного обработчика не меняет подпись.

Текст Telegraph сохраняется из собственных текстов поста и статьи. Служебная ошибка
загрузки не является авторским текстом; она остаётся в полноте и linked_content.
Если при офлайн-переносе такое представление изменило вход прежней обработки,
результат не получает новую подпись: он остаётся в backup, отчёт требует пересчёта.

Обычный ручной повтор очищает монотонный и UTC-срок, сохраняя backoff; обязательные
source-wait сохраняются. MediaOutput отвергает запись после отзыва допуска загрузки.

Фактическая проверка: [отчёт #93](../verification/publication-processing-93.md).
Связанные Publication и общий выбор фида действуют через publication_links и feed_publications. Итоговый перенос описан в [последнем состоянии](latest-publication.md).
