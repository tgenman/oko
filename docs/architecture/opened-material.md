# Открытый материал в браузере

2026-10-12. Кандидат 1 архитектурного обзора, база `80e9a7e`. Пользователь подтвердил очистку прежнего материала при переключении карточки и единое владение загрузкой, версиями, медиа и очисткой. Итоговый объём подтверждён пользователем перед реализацией.

## Решения

При выборе другой карточки прежний материал сразу очищается; область чтения показывает загрузку новой карточки. Поздний ответ или ошибка прежнего открытия не меняют текущий экран. Переключение не означает «Просмотрено».

Deep module открытого материала владеет загрузкой выбранной карточки, раскрываемыми исходниками сводки, предыдущими версиями, текстом, медиа и прекращением их показа. Список карточек, тематические папки, настройки и подтверждение завершения папки остаются самостоятельными сценариями.

## Трение и направление

В `oko/web/app.js` функции открытия, раскрытия версий, загрузки медиа, обновления списка и обработки сообщений других вкладок согласуют `generation`, `contentEpoch`, `ids`, `selected` и общий набор blob URL. Interface фактически включает этот совместный протокол; перенос функций по файлам его не скрывает.

Разместить module в `oko/web`, без нового UI framework. Interface выражает выбор карточки, согласование её актуальности и прекращение показа; implementation скрывает поколения загрузки, владение DOM и освобождение медиа. Точные имена и типы выбрать при реализации. Seam к внешней загрузке позволяет задерживать и завершать ответы в проверках: реальный fetch adapter и управляемый adapter используют тот же путь показа.

Locality: правила актуальности и очистки меняются в одном module. Leverage: одиночная публикация, исходники сводки и предыдущие версии используют одну implementation этих правил. Deletion test: удаление module снова разнесёт знания о поздних ответах и освобождении медиа между callers.

## Сохраняемые условия

- UI варианта A, маршруты читателя, сортировки, настройки и состав чтения сохраняются.
- Фильтры, тезисы, сводки, исходники и предыдущие версии сохраняют доступные действия и содержание.
- Переключение карточки, прекращение показа и отметка «Просмотрено» остаются разными действиями.
- После просмотра, остановки или потери связи ранее открытое содержимое не возвращается из незавершённых запросов.
- Медиа прекращают воспроизведение; созданные module blob URL освобождаются при очистке. Отмена загрузки не заменяет проверку актуальности позднего результата.
- Просмотр исходника групповой карточки в другой вкладке учитывается при согласовании текущего показа. Завершение другой папки не очищает открытый материал незатронутой папки.
- Runtime сохраняет владение действиями, отменой внешней работы и допуском результатов; Store — транзакциями, файлами и восстановлением. Формат хранения и processing modules не меняются.

## Проверки

Interface — test surface: взаимодействие читателя с настоящим браузерным module. Управляемые задержанные внешние ответы не должны подменять implementation показа.

1. Открытие A → выбор B: A сразу очищен, видна загрузка B; поздний успех и поздняя ошибка A не меняют B.
2. Загрузка текущего медиа или предыдущей версии → переключение карточки: старый текст и медиа не добавляются к новой карточке.
3. Просмотр во время загрузки → поздний ответ: содержимое не возвращается; уже созданные blob URL освобождены и воспроизведение прекращено.
4. Просмотр во второй вкладке: открытая исходная публикация или затронутая сводка прекращает показывать удалённое содержимое; другая папка сохраняет свой открытый материал.
5. Остановка или потеря связи при незавершённой загрузке: поздний результат не возвращает материал.
6. Раскрытие предыдущей версии и исходников сводки остаётся рабочим, включая изображения, видео и кружочки.

Существующие проверки читателя, удаления и версий на Python сохранить. Для этой работы нужны воспроизводимые браузерные проверки асинхронных сценариев, а не только проверка синтаксиса JavaScript или ручной снимок. Использовать временное хранилище и синтетическое содержимое; реальные личные источники и AI для этого рефакторинга не нужны.

## Завершение
