# Telegram client в общем пайплайне

Подтверждённые каналы используют TelegramClientAdapter: внешний ключ фида — marked
peer ID, публикации — каноническая ссылка сообщения, альбом — одна публикация с
участниками в extra.telegram. Группы продолжают использовать прежний путь.

Адаптер не получает UUID, SQLite, enabled и задания. Он возвращает метаданные,
содержимое, внешние ссылки и описания отдельных файлов. Owned worker передаёт
один файл в поток, проверяет native identity ресурса перед скачиванием и удаляет
свой временный файл. Photo/document ID позволяют сохранять ID неизменного файла.
Изменившийся ресурс требует обновления описания; повтор сохраняет backoff.

Native peer и сохранённые ID сообщений позволяют перечитать известную публикацию
после переименования. Ключ и URL уточняются в принимающей транзакции. Неполный ответ
по известному альбому сохраняет локальную копию; рост альбома обновляет ту же запись.
Молодой альбом требует повторной проверки метаданных. Полные публикации перечитываются
по явной перезагрузке, новые приходят следующим окном с фиксированной границей.

## Явная смена доступа

`telegram/connect` принимает необязательный feed_id. Для существующего канала сервер
проверяет тот же peer и подтверждённые aliases, актуальность профиля и отсутствие
конфликта владельцев. Переход client → web также проверяет текущий публичный адрес
через прежний профиль. Автоматического fallback нет.

Привязка, сброс несовместимого курсора, отмена старых file jobs и постановка обновления
описаний фиксируются вместе. Готовый локальный контент сохраняется. Старые операции
отменяются; поздний ответ не проходит проверку поколения. Новый адаптер получает
свежие описания перед скачиванием. Настройки, фид и Publication сохраняют свои IDs.
Граница подтверждения чтения прежнего аккаунта не переносится другому аккаунту.

FloodWait использует существующий допуск аккаунта и сохраняется после перезапуска;
ручной retry его не обходит. Web-статьи и их файлы допускаются общими workers по
собственным зависимостям, независимо от готовности native аккаунта. Auto-read ждёт
готовности собственных и связанных файлов; ручной режим ждёт просмотра.

## Офлайн-перенос

Мигратор работает с новой копией и сохраняет побайтную резервную копию источника.
Он переносит каналы с сохранённым подтверждением типа, текущие файлы и доказанно
актуальные результаты. Старые inline-статьи и их файлы становятся отдельными
Publication. Неодинаковые сохранённые снимки одной статьи дают конфликт, а не
произвольный выбор. Неизвестный locator старого готового файла уточняется при
последующем обновлении описания; cached bytes доступны без сети.

Если структура входа изменилась при разделении статьи, прежний результат остаётся
в backup, а новый ожидает обработки. Каноническая ссылка может уточниться без
повторного запроса модели. Неподтверждённый тип существующего client-источника не
угадывается; финальная проверка переноса рассматривает его отдельно.
