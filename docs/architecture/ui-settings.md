# Меню и редактор настроек в браузере

Спецификация: [ускорение разработки](../../.scratch/development-flow/spec.md).

## Владельцы

- `menus.js` создаёт три меню и связывает завершённые действия форм с переходами. Владеет активным диалогом, временем жизни открытия, возвратом фокуса и адаптивным переходом списка/деталей. При закрытии и повторном открытии даже того же меню прежняя операция теряет право навигации. Переключение способа добавления также меняет контекст.
- `settings-editor.js` владеет выбранным фидом/папкой, текущим уровнем Око/папка/фид, эффективными значениями и черновиками по объектам. Загружает список подписок, показывает дерево и редактор, сохраняет поля и параметры фида, сбрасывает наследование. `open` принимает сценарий и необязательный объект; `deactivate` завершает показ без удаления черновиков. `refresh` согласует каталог после серверных изменений без смены текущего объекта. `status` принимает сведения о ходе начальной истории; `stop` прекращает работу.
- `model-settings.js` хранит черновик подключения модели, загружает сохранённую конфигурацию и выполняет проверки обработчиков. Время жизни показа независимо от запросов редактора полей.
- `feed-connection.js` и `telegram-connection.js` сохраняют валидацию, ввод, проверки источника и очистку успешно отправленной формы. Переподключение Telegram принадлежит редактору выбранного фида; форма нового подключения — меню добавления.
- `opml-import.js` владеет файлом, предварительным планом, выбором конфликтов и подтверждением импорта. Новый файл лишает старый предварительный ответ права изменять форму. Успешная серверная запись обновляет подписки даже после закрытия меню; переход допускается только в контексте исходного действия.
- `app.js` собирает интерфейс и связывает меню с обновлением чтения. Черновики, выбранный объект настроек и счётчики меню ему не передаются. Открытый материал сохраняет отдельное владение по [действующему решению](opened-material.md).

## Допуск результатов

`ui-operations.js` — общий механизм времени жизни UI-операций. Отдельный экземпляр принадлежит отдельному владельцу. `begin` начинает именованную операцию и заменяет прежнюю с тем же назначением, `capture` фиксирует контекст без замены соседних операций, `invalidate` завершает текущий контекст. `commit` выполняет эффект только пока операция актуальна. Читающие запросы могут получать `signal`; отсутствие поддержки отмены транспортом не ослабляет проверку актуальности.

Операции разных владельцев и разные назначения одного владельца не отменяют друг друга. Например, сохранение поля и проверка модели независимы. Загрузка редактора и сохранение поля также имеют разные назначения: обновление значений после записи не отменяет сообщение об этой записи.

Отмена браузерного ожидания не откатывает серверную запись. Поэтому успешная мутация сначала выполняет относящуюся к ней очистку черновика/формы и согласование данных, а сообщения и навигация проходят через `commit`. Ошибки поступают в диагностику независимо от допуска их показа в текущем меню.

При сохранении поля или параметров фида удаляются только черновики, равные отправленным значениям. Ввод, сделанный во время запроса, остаётся. Загрузка сохранённых значений накладывает существующие черновики и не переносит их на другой объект.

Механизм намеренно не заменяет управление открытым материалом, сбором, Runtime или Store. `controls.js` содержит только общие конструкторы DOM без собственного состояния.

## Проверка

Сохраняется настоящий браузерный interface с управляемым HTTP adapter: меню, фокус, чтение, черновики, наследование, смена объектов, запоздалые ответы и записи после закрытия. Проверки не знают карты черновиков или внутренних счётчиков. Отдельный HTTP сценарий обходит импортируемый граф JavaScript от главной страницы через production routes и проверяет, что данные читателя по-прежнему требуют авторизации.
