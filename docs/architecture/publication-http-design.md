# HTTP-контракт открытой публикации

Согласовано 28 октября 2026. Реализация — задача #174;
это не подтверждение выпуска на рабочем экземпляре.
[Кратко для человека](../human/opened-publication.md).
[Контракт списка карточек](cards-http-design.md) согласован отдельно.

## GET /publication/{id}

Путь указан без общего префикса `/api/v3`. Один запрос возвращает текст,
фильтрацию, тезисы и сведения о медиа выбранной публикации.
Ответ: `200 OK`, заголовок `ETag` и JSON. Пример ниже сокращён: полный
состав обязательных полей указан в `api/openapi.yaml`.

```json
{
  "id": "publication-123",
  "title": "Заголовок",
  "feed_id": "feed-7",
  "published_at": "2026-10-27T12:00:00Z",
  "source_url": "https://example.org/article",
  "text": "Полный исходный текст",
  "filter": {
    "state": "ready",
    "result": {
      "hidden": false,
      "reason": "",
      "text": "Текст после фильтрации"
    },
    "error": null
  },
  "theses": {
    "state": "ready",
    "result": {
      "points": ["Первый тезис", "Второй тезис"]
    },
    "error": null
  },
  "media": [
    {
      "id": "media-1",
      "kind": "image",
      "url": "/media/media-1"
    }
  ]
}
```

- `id`, `title`, `feed_id`, `published_at`, `source_url` — идентичность,
  заголовок, фид, дата публикации и ссылка на оригинал. Неизвестная дата — `null`.
- `text` — полный исходный текст; `filter.result.text` — текст после фильтрации.
- `filter.result.hidden` — скрыта ли публикация; `reason` — пояснение фильтрации.
- `theses.result.points` — массив строк тезисов.
- `media` — массив сведений и ссылок, не байты файлов. Без медиа — `[]`.
  Файлы загружаются отдельно по `url`; показанный адрес — пример.
- Для сохранения текущего показа ответ дополнительно содержит сведения об
  источнике, доступности и ревизии, полноте и загрузке, связанных публикациях,
  предпросмотре ответа и внешних вложениях. Результаты содержат происхождение,
  удалённые фильтром фрагменты и ссылки тезисов. Полная схема — в OpenAPI.

## Состояния фильтрации и тезисов

`filter` и `theses` всегда имеют одинаковую оболочку: `state`, `result`, `error`.
Состояние не кодируется отсутствием объекта.

| `state` | Значение |
| --- | --- |
| `disabled` | Обработка выключена |
| `pending` | Ожидает обработки |
| `processing` | Обрабатывается |
| `ready` | Результат готов |
| `error` | Попытка завершилась ошибкой; пояснение в `error` |

Без результата — `result: null`. Без ошибки — `error: null`; при ошибке
`error` содержит строку пояснения. Примеры:

```json
{"state": "processing", "result": null, "error": null}
```

```json
{"state": "disabled", "result": null, "error": null}
```

```json
{"state": "error", "result": null, "error": "Не удалось связаться с обработчиком"}
```

## Смена библиотеки

Читатель может передать необязательный заголовок `X-Oko-Storage-Id` с уже
подтверждённой идентичностью хранилища. Если она не совпадает с текущей,
сервер возвращает `409` с кодом `storage_changed` до чтения публикации.
Читатель сверяет идентичность и при получении ответа, чтобы поздний ответ
прежней библиотеки не смешался с данными после восстановления. Независимый
клиент может не передавать заголовок. ETag включает идентичность хранилища.

## Обновление через ETag

ETag относится ко всему ответу публикации. Повторный GET с `If-None-Match`:

- `304 Not Modified` без тела — ответ не изменился;
- `200 OK` — всю актуальную публикацию и новый ETag, если изменилась любая часть.

Таким образом, готовность тезисов или изменение медиа может привести к повторной
передаче текста. Сейчас сервер собирает полный ответ и для проверки ETag:
`304` экономит передачу, но не сборку. Этот компромисс принят ради одного запроса и одной схемы
загрузки и обработки ошибок. Раздельные GET текста, фильтра, тезисов и медиа,
как и универсальные material/filter/theses/media checks, не нужны в целевом
пути открытой публикации. Загрузка файлов по ссылкам остаётся отдельной.

## Границы решения

Согласованы состав ответа и состояния обработки `filter`/`theses`. Состояния
загрузки самой публикации и отдельных файлов, полный перечень видов медиа,
ошибки отсутствующей публикации и удержание прежнего результата при повторной
обработке отдельно не согласованы этим документом. Они не должны молча исчезнуть
из поведения при будущей реализации.

Это HTTP-представление, не решение о замене формата хранения публикации.
Прежнее поведение браузера описано в [историческом описании открытой публикации](opened-material.md).
Навигация и статус остаются отдельными предметами проектирования. Состояние выпуска и фактические проверки указываются отдельно.
