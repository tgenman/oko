# Фронтенд и бэкенд Око

Око состоит из браузерного фронтенда в `frontend/` и серверного Python-пакета `oko/` в одном репозитории. Существующий запуск `python -m oko` обслуживает оба на одном локальном origin. Пользовательскому запуску не требуются Node, сборка или отдельный frontend-процесс.

Спецификация и критерии приёмки: [явное разделение](../../.scratch/frontend-backend-separation/spec.md). Фактические проверки: [отчёт](../verification/frontend-backend-separation.md).

## Владение

Фронтенд владеет DOM, фокусом, навигацией, черновиками, локальными предпочтениями и допуском позднего ответа к текущему показу. Runtime владеет исполнением, отменой и внешними ожиданиями; Store — фиксацией и восстановлением. Сервер формирует состав чтения и эффективные настройки. Браузер не вычисляет membership и не повторяет правила актуальности обработки.

Действуют решения [UI-состояния](ui-settings.md), [открытого материала](opened-material.md), [управления работой](reader-work.md), [состава чтения](reading-composition.md) и [согласования обработки](processing-coordination.md).

## HTTP interface

Seam между фронтендом и бэкендом — HTTP interface читателя. Существующие URL, локальная сессия, проверка host/origin и защитные заголовки сохраняются. Успешная серверная запись остаётся состоявшейся после закрытия формы; отмена браузерного ожидания не откатывает её. Несколько читающих запросов не обещают один транзакционный снимок.

`oko/reader/contracts.py` описывает карточки, навигацию, открытый материал, предыдущую версию и статус как строгие wire types без defaults. Настоящие ответы проверяются при выдаче; непереданные необязательные поля не появляются в сериализации. Поля, состояния, null и ссылки явно описаны. Внутренние types Store и Runtime не входят в interface.

Команда `python -m oko.reader.contracts` экспортирует JSON Schema для браузерных проверок без запуска Runtime или внешних источников. Схемы получаются из того же серверного описания; независимо поддерживаемых JavaScript-схем нет. Браузерная поддержка проверяет успешные снимки ответов, включая задержанные; HTTP-ошибки остаются ошибками своего маршрута. Остальные действия и настройки сохраняют существующие контракты.

## Транспорт и выдача файлов

`frontend/transport.js` скрывает общие правила авторизации и передачи JSON, медиа и закрытия вкладки. Interface принимает fetch adapter, токен и origin. Токен отправляется только на свой origin. JSON-ошибки сохраняют detail и диагностические заголовки; медиа возвращают Response для существующего поведения callers. Закрытие вкладки использует keepalive.

Транспорт не владеет DOM, отменой серверной работы или поколениями UI. `app.js` связывает UI и сообщает ошибки запросов; диагностика использует тот же транспорт, но сама владеет очередью, дедупликацией и повторной доставкой. Ошибка её передачи не сообщает саму себя рекурсивно.

`oko/reader/static.py` выдаёт выделенный каталог фронтенда после регистрации маршрутов данных. Вложенные ES modules доступны без перечисления их имён в Python. Путь определяется относительно checkout, а не рабочего каталога процесса. Неизвестные маршруты данных не превращаются в HTML; обход пути, скрытые файлы и symlink за пределы каталога отклоняются.

Runner и линтер обнаруживают браузерные JavaScript modules рекурсивно. Тесты сохраняют существующую организацию: HTTP interface с временными SQLite/файлами, настоящий браузер и заменяемые внешние adapters. Перенос production-файлов сам по себе не требует переноса сценариев.
