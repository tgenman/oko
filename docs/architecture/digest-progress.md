# Прогресс обзора за период

2026-10-09. Кандидат 3 архитектурного обзора; пользователь согласовал сохранение поведения и проверку переходов, затем поручил самостоятельно выбрать оставшиеся решения. Исходная база: `56cd7a4`.

## Решение

Углубить module обзора за период в `oko/digests.py`: сосредоточить определение следующего этапа, проверку прогресса и переход после ответа внутри одной implementation. Существующий interface `Digests` для Runtime и читателя сохраняется. Новый framework обработки, adapter хранения и журнал этапов не нужны.

Сохраняются замороженный набор ID/version, ограничения размера запросов, промпты, число раундов, правила допуска обработчика, атомарный writer Store, поведение «Просмотрено» и формат JSON-заголовка Markdown. Корректные уже начатые обзоры продолжаются с последнего сохранённого этапа. Новый формат хранения и миграция не требуются.

## Устройство implementation

- Работать с типизированным `Progress` до момента сериализации; не изменять словарь состояния независимо в подготовке и сохранении.
- Внутренний неизменяемый план определяет этап, точный запрос, выбранные источники и условия перехода. Разбиение исходников и группировка промежуточных тезисов имеют одного владельца внутри обзора.
- При подготовке связать план с идентичностью задания, generation, актуальностью исходников и отпечатком исходного Progress. При принятии ответа проверить этот же план и свежий Progress. Изменённый во время обработки файл не может переинтерпретировать ответ как результат другого этапа.
- План живёт только на время принадлежащего модулю задания. Он не является новым сохраняемым состоянием. После перезапуска план воспроизводится из manifest и Progress; отмена и завершение освобождают его.
- Переход принимает валидированный результат выбранного этапа и формирует новый Progress. Только после этого Store атомарно сохраняет файл и завершает либо возвращает задание в очередь.
- Не заменять планом существующие проверки живой вкладки, текущего Store, generation, актуальности исходников и разрешения публичного AI. Поздний ответ по-прежнему отбрасывается.

Стадии остаются прежними: обработка частей → ноль или несколько раундов сжатия → финальный обзор. Для единственной части отдельного финального обращения нет; при отсутствии допустимых для AI исходников завершение обходится без обращения к модели. Полный набор оригиналов сохраняется независимо от набора, переданного модели.

## Проверка прогресса и восстановление

Проверять не только форму полей, но и допустимость состояния относительно текущего набора:

- Счётчики неотрицательны; количество обработанных частей не превышает воспроизводимое число частей.
- Указатель группы соответствует текущему раунду; накопленные результаты и счётчики согласованы с этапом. Нельзя перейти к сжатию до обработки всех частей.
- Ссылки промежуточных и окончательных тезисов принадлежат замороженному набору и имеют точные исходные URL. При построении этапа ссылки должны также принадлежать допустимым источникам выбранной части или группы.
- Готовый результат допускается к чтению только при `jobs.status=done` и проверенном `Progress.complete=True`. Пустой готовый результат допустим для действительно пустого набора источников AI; он не доказывает готовность непустого набора.
- Лимит раундов сохраняет нынешнее поведение; его пересмотр не входит в рефакторинг.

Если файл повреждён по форме или содержит невозможное состояние, отменить актуальное поколение обработки и пересобрать обзор с начала из того же manifest. Не показывать повреждённый файл как готовый, не удалять оригиналы, не расширять набор новыми поступлениями. Использовать существующие запись и восстановление; повреждённое содержимое не архивировать. Изменение исходников или настроек продолжает обрабатываться существующими правилами актуальности, отдельно от повреждения Progress.

Если исходное состояние изменилось между подготовкой и принятием ответа, ответ не сохранять. Повторная подготовка использует актуальное проверенное состояние; это не повод пересобирать корректный прогресс.

## Test surface

Существующий interface читателя с временными SQLite/файлами и заменяемым внешним AI adapter остаётся основной test surface. Codex и llama.cpp уже обосновывают существующий seam; отдельный adapter арифметики прогресса не вводится.

Сохранить проверки больших исходников, глобального промпта, возобновления после остановки и 503, отмены, изменения разрешения и аварий после атомарного переноса. Добавить сценарии:

1. Остановка и перезапуск посреди раунда сжатия: принятые группы не отправляются повторно.
2. Отрицательные и выходящие за диапазон счётчики, несогласованные флаги и результаты: исходники доступны, обзор пересобирается в прежнем наборе.
3. Чужая ссылка в сохранённом прогрессе: содержимое не передаётся обработчику и не показывается как готовое.
4. Частичный файл при done-задании: ложная готовность не отображается.
5. Изменение файла прогресса во время задержанного ответа: ответ старого этапа не применяется к новому состоянию.
6. Совместимость корректного файла, созданного до рефакторинга, включая промежуточный раунд сжатия, единственную часть и пустой набор источников AI.

Depth выражается в том, что Runtime не знает правила переходов. Locality: подготовка, принятие и восстановление используют одну implementation. Leverage: один набор правил проверяет все этапы обзора. Deletion test: удаление этого module снова распределило бы знание о стадиях между подготовкой запроса, принятием ответа и чтением результата.
