# Свои модели через Ollama

Проверено 2026-10-07 по официальной документации. Исследование выполнимости; Ollama не устанавливался и не запускался, модели не скачивались, пользовательские настройки не читались.

## Вывод

Документированного HTTP API достаточно для будущего подключения своей модели: выбрать сервер и модель, передать текст, получить структурированные тезисы и показать завершение или ошибку. Это вывод о наличии интерфейсов, а не проверка качества, скорости или доступности модели на компьютере пользователя. Стек реализации не выбран.

## Подтверждённые интерфейсы

| Возможность | Что подтверждено |
|---|---|
| Адрес сервера | По умолчанию сервер слушает `127.0.0.1:11434`; стандартный адрес подключения — `http://localhost:11434`. Адрес привязки сервера меняется через `OLLAMA_HOST`. [FAQ](https://docs.ollama.com/faq#how-can-i-expose-ollama-on-my-network) |
| Список и выбор моделей | `GET /api/tags` возвращает доступные модели с именем и метаданными. Выбранное имя передаётся в поле `model` запроса. [List models](https://docs.ollama.com/api/tags), [Chat](https://docs.ollama.com/api/chat) |
| Обработка текста | `POST /api/chat` принимает `model` и массив `messages` с ролями и содержимым. [Chat](https://docs.ollama.com/api/chat) |
| Структурированный результат | `format` принимает `json` либо JSON Schema. Это позволяет описать поля тезисов и ссылок; соответствие смыслу источника всё равно требует отдельной проверки. [Chat](https://docs.ollama.com/api/chat) |
| Поток и завершение | `stream` по умолчанию включён; его можно отключить. Ответ содержит `done` и `done_reason`, а также длительности и счётчики токенов. Документированного достоверного процента готовности из этих полей не следует. [Chat](https://docs.ollama.com/api/chat) |
| Ошибки | Ошибка передаётся в JSON-поле `error`; возможны, например, HTTP 400, 404, 429, 500 и 502. При ошибке внутри потока приходит NDJSON-объект с `error`, а уже отправленный HTTP-статус не меняется: одного HTTP 200 для признания результата успешным недостаточно. [Errors](https://docs.ollama.com/api/errors) |

## Локальное выполнение и публичный AI

Ollama поддерживает и локальные, и облачные модели. Согласно FAQ, при локальном выполнении Ollama не получает промпты и данные; облачные модели обрабатывают запросы на стороне сервиса. Поэтому название провайдера «Ollama» само по себе не означает разрешённое локальное выполнение. [FAQ](https://docs.ollama.com/faq#does-ollama-send-my-prompts-and-answers-back-to-ollamacom)

Для режима только локальных моделей официально предусмотрены `OLLAMA_NO_CLOUD=1` либо `disable_ollama_cloud: true` в `~/.ollama/server.json`. После изменения нужен перезапуск. Настройка отключает облачные модели Ollama и веб-поиск; это не заявление о полном отсутствии любых сетевых соединений системы. [FAQ](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features)

Продуктовое следствие, предлагаемое для обсуждения: запрет публичного AI должен ограничивать место обработки, сохраняя возможность собственной модели. Запрет также должен распространяться на промежуточные тезисы и общие сводки, содержащие материал такого фида. При недоступности разрешённой модели нельзя незаметно переключаться на публичный сервис. Это рекомендации для будущего решения, не реализованные гарантии.

## Что проверить отдельным экспериментом

- Доступность конкретного сервера и выбранной локальной модели, включая фактическую границу локального/удалённого выполнения.
- Качество русскоязычной фильтрации и тезисов, соблюдение схемы ответа, время обработки и допустимый объём входа.
- Поведение при недоступном сервере, исчезнувшей модели, обрыве потока и остановке Око.
