# Начальная история YouTube через yt-dlp

2026-10-13. Исследование, без реализации. Дополнение к [исследованию RSS](feed-history-pagination.md).

Исторический срез до реализации истории YouTube. Последующая реализация и её проверки: [итог разбора](../verification/uncommitted-completion.md).

## Вывод по документации и исходному коду

Технически можно перечислить первые 60 элементов публичного списка загрузок без собственного API-ключа и скачивания видео. Для экономного режима нужны `--flat-playlist` и ограничение списка: один `--skip-download` запрещает видеофайл, но не извлечение метаданных каждого ролика. Flat-режим пропускает извлечение отдельных видео; `--dump-single-json` выводит JSON и подразумевает симуляцию. Источник: [официальный README, General Options и Verbosity and Simulation](https://github.com/yt-dlp/yt-dlp#usage-and-options).

Кандидат для проверки на указанном канале:

```sh
yt-dlp --ignore-config --flat-playlist \
  --playlist-items 1:60 --simulate --dump-single-json \
  --compat-options no-youtube-unavailable-videos \
  --no-cache-dir --extractor-retries 0 --retries 0 --socket-timeout 15 \
  'https://www.youtube.com/playlist?list=UUsXVk37bltHxD1rDPwtNM8Q'
```

Это ограниченный исследовательский запуск: автоматические повторы отключены, результат — один JSON. `--ignore-config` исключает неожиданное применение пользовательских настроек загрузки, cookies или дополнительных действий. Верхняя граница `1:60` ограничивает выбранные позиции. Проверять достижение 60 нужно по числу уникальных пригодных записей, а не по exit code. При исключениях/недоступных элементах их может оказаться меньше. `--lazy-playlist` нужен для обработки поступающих записей потоком, но для этого ограниченного результата не обязателен и в фактической проверке ниже не использовался. [Описание опций](https://github.com/yt-dlp/yt-dlp#usage-and-options).

## Какие запросы нужны

Из кода следует схема: страница плейлиста с первой порцией → continuation-запросы до выбранной границы. Flat-ветка возвращает URL-результат без перехода к извлечению каждого видео. Это чтение веб-интерфейса/Innertube YouTube, не Data API v3 и не RSS. [Обработка flat-результатов](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py), [обход списка, `_entries`](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py).

Две детали минимизации:

- По умолчанию экстрактор может перезагрузить плейлист, включая недоступные видео. `--compat-options no-youtube-unavailable-videos` отключает эту ветку и соответствующий дополнительный browse-запрос.
- `youtubetab:skip=webpage` не обязательно уменьшает число запросов: альтернативная ветка сначала выполняет `navigation/resolve_url`, затем `browse`/`next`. Успешная обычная HTML-страница уже содержит начальные данные. `skip=authcheck` отключает локальную проверку для авторизованных запросов без начальной конфигурации, а не отдельный сетевой запрос.

Источник: [`_reload_with_unavailable_videos`, `_extract_data`, `_extract_tab_endpoint`, `_report_playlist_authcheck`](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py). Число страниц и общий сетевой бюджет нельзя обещать по одному лимиту 60: они зависят от фактического ответа, ошибок и версии yt-dlp. Ниже отдельно должны быть записаны измерения.

## Что означает «последние 60»

Корневой URL канала может раскладываться на несколько вкладок; `/videos` выбирает только вкладку видео. Для единого списка сам yt-dlp предлагает плейлист Uploads `UU…`, полученный из `UC…` заменой префикса. Использовать корневой канал и считать `1:60` общим хронологическим ограничением всех вкладок нельзя. Источник: [логика `extra_tabs` и `uploads_url`](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py).

Предлагаемый смысл для Око — первые 60 публично перечисляемых элементов Uploads в порядке YouTube. Отдельно нужно проверить покрытие Shorts/завершённых трансляций и порядок на фактическом результате. Публичная запись списка не гарантирует доступность воспроизведения; проверять каждое видео отдельно только ради этого означало бы дополнительные запросы. Удалённые и закрытые записи нельзя обещать получить. Объявления будущих трансляций, если они попали в список, не должны запускать запрос субтитров.

## Цена экономного режима: неполные метаданные

Экстрактор извлекает из списка ID, название, URL, ссылки на превью и часть данных канала. Описание берётся из snippet и может отсутствовать или быть сокращённым. Точная дата публикации не гарантируется; `approximate_date` вычисляет приблизительное время из текста интерфейса. Расписание будущего эфира, если доступно, хранится отдельно как `release_timestamp`. Источник: [`_extract_video`, `_extract_lockup_view_model`](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py), [предупреждение `approximate_date`](https://github.com/yt-dlp/yt-dlp#extractor-arguments).

Для Око отсюда следует компромисс: дешёво получить 60 ссылок и названий возможно; обещать одновременно точные даты, полные описания и субтитры всех 60 без дополнительных запросов нельзя. Значения из текущего RSS можно сохранить для пересекающихся ID. Неизвестную дату не заменять приблизительной без явной отметки. Режим «до даты» требует отдельного решения, поскольку грубая дата может неверно отсечь границу.

## Предложение для будущей спецификации

Использовать yt-dlp только для явно запрошенной начальной истории/догрузки, а обычные обновления продолжать через RSS. Дедупликация по video ID; полученные субтитры не перезапрашивать. Для истории сохранять доступные метаданные сразу, а обогащение отдельного видео считать отдельной операцией с отдельной стоимостью запросов. При сетевом отказе прекращать ограниченный запуск и сообщать частичный результат; не запускать бесконечные повторы.

В текущем [`YouTubeSource.fetch`](../../oko/collection/youtube/source.py) перед обработкой каждого материала вызывается `read_entries()`. Простая замена этого метода на yt-dlp привела бы к повторному перечислению списка для каждого видео. Будущая интеграция должна отдельно перечислять историю и передавать/повторно использовать уже полученные метаданные в обработке материала. Это рекомендация по коду, а не реализованное изменение.

Веб-интерфейс YouTube может меняться; сам проект предупреждает о поломках старых версий экстракторов. Версию yt-dlp и результат проверки следует фиксировать. [Политика обновлений проекта](https://github.com/yt-dlp/yt-dlp#update).

## Фактическая проверка

Документационная часть: прочитаны официальный README и текущий исходный код master. Затем основной исполнитель выполнил ограниченный эксперимент с **yt-dlp 2026.08.19**, установленным во временный каталог `/tmp`.

Через Python API использованы `extract_flat=True`, `playlist_items='1:60'`, `simulate=True`, `skip_download=True`, `cachedir=False`, `retries=0`, `extractor_retries=0`, `socket_timeout=15`, `compat_opts=['no-youtube-unavailable-videos']`. Пользовательские CLI-конфиги и cookies не загружались. Команда выше — документированный CLI-кандидат; фактический запуск был через Python API.

`YoutubeDL.urlopen` инструментирован: разрешены только `/playlist` и `/youtubei/v1/browse`, жёсткий предел — шесть запросов. Запросы страниц отдельных видео, медиа и субтитров запрещены. Фактически выполнен **один GET** `https://www.youtube.com/playlist?list=UUsXVk37bltHxD1rDPwtNM8Q`, ответ **HTTP 200**, путь не изменился, время **0,60 с**. Из ответа выбраны **60 различных video ID**; первые 15 совпали с ранее проверенным официальным RSS. Список сообщал общее количество 393, но выбрано только 60. Первый заголовок — «We Finally Know More About Humanity’s First Civilization», последний — «Let’s Cook a Planet».

| Поле | Наличие в выбранных 60 |
| --- | --- |
| ID, название, URL, ссылки на превью, длительность | 60 из 60 |
| Описание, timestamp, upload_date, live_status | 0 из 60 |

**Один запрос относится только к перечислению.** Байты изображений не загружались: сохранение превью потребует отдельных GET. Полные описания, точные даты и субтитры также не получены. Для 45 элементов вне текущего RSS нельзя обещать эти данные без дополнительного обогащения. Совпадение первых 15 подтверждает начало порядка в этом ответе, но без дат не доказывает хронологическую корректность всех 60 и покрытие всех типов публикаций.

Это успешный результат одного публичного канала, одной версии и одного запуска; он не гарантирует один запрос для любых каналов. Больший список, другая разметка, continuation или отказ могут изменить число запросов. Око и его пользовательское хранилище не изменены; видео, картинки и субтитры не скачивались.
