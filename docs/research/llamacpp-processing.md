# llama.cpp: используемый контракт

Проверено по официальной документации 2026-10-09. Это исследование API, не проверка загруженной пользовательской модели.

[llama-server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md): `/v1/models` сообщает точный ID (путь или alias), владельца и метаданные весов; `/props` — путь GGUF и build info. `/v1/chat/completions` принимает `messages`, `stream=false` и `response_format={type:json_object,schema:…}`. Око не отправляет tools и не исполняет действий модели; проверяет собственную схему, завершение и допустимые ссылки.

Минимальная поддержка — один сервер с одной уже загруженной моделью, без автоматического запуска, загрузки весов, router API, авторизации API-ключами и поддержки произвольного OpenAI-совместимого провайдера. Удалённый адрес допустим только с разрешением публичного AI. Сервер без `/props` показывает ошибку несовместимого API.

Метаданные не доказывают отсутствие удалённого RPC или прокси. Для локального режима вместе с loopback и метаданными требуется явное подтверждение конфигурации владельцем сервера. Многомодельный список не считается подтверждённым локальным подключением.

HTTP-клиент отключает inherited proxy и redirects, ограничивает ответ 2 МБ и тайм-аут чтения 120 секунд (подключение 5 секунд). Запрос не сохраняется в Око. `cache_prompt=false` не даёт гарантии стирания памяти общего сервера. Не включать подробные логи, slot-save-path или сохранение prompt cache; `--log-disable` документирован для отключения логирования. Око не посылает серверу команды сохранения/стирания чужих slots и не останавливает его.

Дальнейшая проверка: зафиксировать версию llama-server, модель/квантование и параметры запуска; на синтетической публикации проверить факты и атрибуцию, отмену/stop, отсутствие сохранённых входов и удаление содержимого Око. Пользователь сообщил, что модель пока скачивается. [Текущий отчёт](../verification/llamacpp-theses.md).
