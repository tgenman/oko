# Codex как обработчик материалов Око

Проверено 2026-10-07. Исследование выполнимости, без запуска модели, изменения настроек или чтения учётных данных. Решение о реализации не принято.

## Вывод

Око может программно вызывать установленный Codex: документированы `codex exec` для отдельных заданий и `codex app-server` для приложения с событиями и отменой. Для первого ограниченного эксперимента достаточно `exec`; если нужна подтверждаемая отмена через протокол, рассмотреть app-server. Это рекомендация по результатам исследования, а не согласованный выбор архитектуры.

Локально установлен `/opt/homebrew/bin/codex`, версия `codex-cli 0.136.0`. Проверены только `--version`, `exec --help`, `app-server --help`. Последний помечен CLI как experimental. Команды завершились успешно, хотя окружение запретило вспомогательное обновление PATH.

## Подтверждено

### Запуск и результат

- Локальный `exec --help` подтверждает неинтерактивный запуск, ввод через stdin, `--json`, `--output-schema`, `--ephemeral`, `--skip-git-repo-check`, `--ignore-user-config`.
- `--json` даёт поток событий JSONL, включая завершение и ошибки; `--output-schema` задаёт JSON Schema финального ответа. Это позволяет показывать стадии задания и получать машиночитаемые тезисы. События не равны достоверному проценту готовности.
- `--ephemeral` отключает сохранение файлов сессии/rollout на диск. Без него обычные сессии могут сохраняться. Это не обещание отсутствия любых логов или облачного хранения.

Источники: локальная справка; [Non-interactive mode](https://developers.openai.com/codex/noninteractive) (при чтении перенаправляет на официальную документацию ChatGPT Learn).

### Подписка и авторизация

Codex поддерживает вход ChatGPT для доступа по подписке и API key для оплаты по использованию. `codex exec` по умолчанию переиспользует сохранённую CLI-авторизацию. Из этого следует техническая возможность локального запуска через существующий вход ChatGPT, если CLI действительно авторизован этим способом и у аккаунта есть доступ.

Документация отдельно рекомендует API key для программных сценариев вроде CI/CD. Поэтому не следует превращать техническую возможность локального personal workflow в обещание неограниченного сервиса на подписке. Текущий способ входа пользователя, доступные модели, квоты и достаточность подписки для 258 фидов здесь не проверялись. Повторная авторизация может потребоваться; учётные данные Око копировать не нужно.

Источники: [Authentication](https://developers.openai.com/codex/auth), [Authenticate in automation](https://developers.openai.com/codex/noninteractive#authenticate-in-automation).

### Прогресс и остановка

App-server запускается локальным процессом, поддерживает stdio, `turn/start`, поток уведомлений и `turn/interrupt`. Отмена завершается событием `turn/completed` со статусом `interrupted`; параметр `outputSchema` задаёт формат результата одного turn. Документация описывает ephemeral fork, но отсутствие сохранения для нового app-server thread в установленной версии отдельно не проверено.

Источник: [Codex App Server](https://developers.openai.com/codex/app-server).

Для Око это означает, что остановку можно встроить в жизненный цикл приложения. Но закрытие вкладки браузера само по себе не гарантирует остановку дочернего процесса: способ обнаружения закрытия/потери соединения и проверка завершения процесса ещё требуют проектирования и проверки. Уже отправленный запрос невозможно считать «не отправленным» после отмены.

## Граница удаления и разрешения AI

Продуктовое требование «Просмотрено удаляет контент» нужно применять ко всем локальным копиям Око: исходникам, сводкам, временным входам/ответам и логам, если они содержат текст. Рекомендуется не сохранять содержимое событий в диагностике и использовать ephemeral-задания. Это требования к будущей интеграции, ещё не реализованная гарантия.

Удаление из Око не подтверждает удаление уже отправленного содержимого у OpenAI. Документация связывает обработку данных с выбранным способом авторизации и настройками аккаунта/workspace; точные сроки хранения для данного аккаунта не установлены. Локальный запуск Codex с OpenAI-моделью остаётся облачной AI-обработкой. [Authentication](https://developers.openai.com/codex/auth).

Галка «Разрешить обработку публичным AI» должна проверяться до подготовки входа для Codex: запрещённый фид нельзя включать и в общий обзор папки. Нужно исключить также косвенный доступ обработчика к его файлам и источникам через инструменты. Один лишь промпт или режим read-only не обеспечивает запрет передачи: read-only ограничивает запись, а не сам факт чтения. Проверка этой изоляции — условие будущего технического эксперимента.

## Что остаётся неизвестным

- Реальная скорость, качество фильтрации/дедупликации и расход лимита на пользовательских материалах.
- Выдержит ли доступ пользователя желаемый объём; какую модель он разрешит использовать.
- Полный перечень локальных и внешних копий для выбранного режима, включая возможные пользовательские hooks, трассировку и инструменты; пользовательские настройки намеренно не читались.
- Корректная отмена при закрытии Око и повторный запуск без дубликатов: нужен ограниченный проверочный сценарий после выбора архитектуры.
