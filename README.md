# Око

Локальный читатель: папки → карточки → материал. Работают RSS/Atom со статьями и локальными изображениями, синтетический источник, импорт OPML, папки и наследуемые настройки. Telegram, YouTube и AI добавляются следующими тикетами.

## Запуск

Python 3.11+ и uv:

```sh
uv sync --extra dev
uv run python -m oko
# Демонстрация без настоящих источников:
uv run python -m oko --demo
```

Браузер открывается автоматически. Повтор той же команды открывает действующий экземпляр. `--data /путь` выбирает хранилище; по умолчанию это `data/` текущего каталога. `--no-browser` оставляет открытие браузера вызывающему коду. Без `--demo` подключаются импортированные RSS/Atom. При открытой вкладке сбор выполняется при запуске, для новых подписок, по кнопке «Обновить источники» и раз в пять минут.

Открытие и копирование сохраняют материал. «Просмотрено» удаляет его содержимое. Если требуется повторно пройти демонстрацию с тремя публикациями, используйте другой каталог `--data`.

Вкладка посылает heartbeat раз в 2 секунды. Через 6 секунд без связи задания приостанавливаются; процесс ждёт переподключения ещё 15 секунд и выходит; на завершение принадлежащих ему задач отведено дополнительно до 0,5 секунды (две границы по 250 мс), плюс завершение HTTP-сервера. «Остановить Око» завершает все вкладки сразу. Автозапуска нет. Замороженная вкладка может потерять связь; после сна сбор требует нового heartbeat. Таймауты настраиваются `--lease` и `--grace`; значения должны быть положительными.

## Подписки и настройки

«Подписки и настройки» → «Импорт OPML» → выбрать файл → разрешить конфликты папок → импортировать. Повторный импорт объединяет известные идентичности, сохраняет исходные URL и настроенные поля. Один фид находится в одной папке. Вложенные папки показываются путём «Родитель / Папка»; буквальный слеш имени отображается как `\/`, обратный — как `\\`, чтобы не смешивать разные структуры. Числовые префиксы задают порядок, остальные папки сохраняют порядок импорта. Для уже известного фида, пришедшего в другую папку, также требуется явный выбор.

Распознаются Telegram-адреса и RSSHub `/telegram/channel/<username>` с известными параметрами отображения `show…` в пути ([контракт RSSHub](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/telegram/channel.ts)). Фильтрующие и неизвестные параметры остаются неоднозначным подключением: RSS можно выбрать явно, с ограничениями. YouTube RSS с `channel_id` сопоставляется с каналом. Распознавание не проверяет доступность источника. Парсер импорта не обращается к сети; в работающем читателе очередь начинает сбор импортированных RSS. Счётчик непрочитанного News Explorer не переносится.

Настройки Око, папки и фида переопределяются по отдельным полям. «Сбросить» возвращает наследование. Режимы оригиналов, тезисов и обзоров сочетаются; промпты, период обзора, расписание (`off` либо местное `HH:MM`) и имя обработчика сохраняются, их выполнение добавляется последующими задачами. Важность, первоначальный период (сутки), разрешение публичного AI и настройки Telegram принадлежат самому фиду. AI и очистка начальной истории выключены, автопрочитывание не выбрано. Сохранение не отправляет отметки Telegram.

Контракт адаптеров: `Store.subscriptions.effective('feed', feed_id)` или `GET /api/settings/feed/<id>` возвращает `effective` с `value/scope/owner`, собственные `overrides` и `feed` с разрешениями, адресами, транспортом и периодом. `null` в PATCH настройки сбрасывает поле. `create_app(..., source_feed=feed_id)` связывает внедрённый источник с конфигурацией; позиции и идентичности публикаций разделены по фидам. Настройки подписок сохраняются в той же SQLite без контента публикаций. Импортированные фиды показывают необходимость подключения; одно поле `transport` выбирает способ сбора.

В читателе доступны выбор папки, «Новые сверху» (по умолчанию), «Старые сверху» и «Сначала важное» (при равной важности новые сверху). Счётчики отражают доступные непросмотренные карточки.

## Хранение и восстановление

SQLite хранит идентичности, состояние, позиции и очередь. Содержание находится в `content/<id>/1/original.md`: первая строка — JSON-заголовок, далее Markdown. Запись: staging → fsync → атомарное перемещение → транзакция полноты. При перезапуске сироты удаляются, незавершённые задания восстанавливаются. Удаления имеют приоритет; их ошибка блокирует новый сбор до успешного повтора.

Просмотр фиксируется транзакцией до физического удаления. Поздние результаты проверяют поколение задания и просмотр. Адаптеры должны поддерживать отмену и ограниченные сетевые таймауты. Если адаптер игнорирует отмену, его поколение инвалидируется, ожидание ограничено 250 мс; при завершении собственный цикл событий Око закрывается после ещё 250 мс. Это не останавливает чужие процессы. После удаления остаются ID, URL и служебное состояние; заголовок и текст в SQLite не записываются. Ошибки сохраняются в виде безопасных категорий. Повреждённая база сохраняется с видимой ошибкой, без пересоздания. Гарантии восстановления предполагают исправный диск. Стирание физических секторов и пользовательского буфера обмена не выполняется.

Сервер слушает IPv4 loopback. API требует случайный токен сессии из ссылки запуска; проверяет Host и Origin. UI не исполняет Markdown/HTML материалов, выводит текст через `textContent`. Ответы имеют `no-store`, CSP и запрет встраивания. Постоянные браузерные хранилища не используются. Просмотр сбрасывает открытый материал в других вкладках через BroadcastChannel и опрос API (500 мс); pagehide очищает DOM, возврат из bfcache перезагружает страницу.

## Проверки

```sh
uv run python -m pytest
uv run mypy oko
node --check oko/web/app.js
```

Основная граница — API с настоящими временными SQLite/файлами, управляемым временем и синтетическими источниками. Процессные тесты открывают loopback и аварийно завершают дочерний процесс в точках транзакции и записи. Тестовые fault hooks передаются только Python-кодом, через HTTP не доступны.

[Результаты браузерной проверки](docs/verification/first-reader.md), [тикет первого пути](.scratch/oko-implementation/issues/01-first-reader-path.md), [следующие задачи](.scratch/oko-implementation/README.md).

## RSS/Atom

Первый проход использует период фида (по умолчанию сутки). Сохранённая граница импорта применяется после перезапуска: доступное окно RSS перечитывается, известные ID/URL пропускаются, запоздавшие публикации не теряются из-за продвижения временного курсора. Ограниченное окно истории обозначается отдельно от полноты статьи. Записи, которые сервер убрал из RSS, восстановить нельзя. GUID используется в области фида; без него — нормализованный URL. Неоднозначный GUID с разными ссылками не скрывает второй материал и не подменяет анонс старого задания.

Анонс сохраняется до фиксации позиции вместе с заданиями. Затем выполняется попытка извлечь статью из HTML и сохранить PNG/JPEG/GIF/WebP. При неудаче доступны анонс, причина неполноты и «Повторить загрузку». Извлечение эвристическое, без JavaScript: динамические сайты, платный доступ и защита могут оставаться анонсом. Лимиты: XML/HTML 4 МБ, изображение 10 МБ, 30 изображений, 20 секунд на HTTP-запрос. Браузер получает картинки через авторизованный локальный API.

Просмотр удаляет анонс, статью, изображения и staging; поздний ответ не возвращает контент. Ошибки авторизации, частоты и доступности видны по фидам; остальные продолжают сбор. RSSHub Telegram собирается только при явном выборе ограниченного транспорта RSS, без отметок Telegram. Настройки AI сохраняются, но обработка в этом тикете не выполняется.

Проверки и границы: [RSS](docs/verification/rss-reading.md).

## Telegram с медиа

Запуск с существующим окружением клиента:

```sh
uv run python -m oko --telegram-project /Users/dabondarev/repo_personal/telegram-mcp
```

Око запускает мост в `.venv` указанного проекта и использует его `.env`, клиентов и защиту сессий. Авторизация не копируется в Око; вход и создание сессий здесь не выполняются. Занятый аккаунт показывается как ошибка, без остановки другого клиента. Выбор аккаунта обязателен. В «Подписки и настройки» можно подключить публичный username либо ID доступного приватного канала/обычной группы; импортированный Telegram-фид подключается в его настройках. При повторе сохраняется один фид в одной папке. Forum topics явно отклоняются.

Страницы истории по 100 сообщений сохраняются вместе с заданиями и позицией. Для первоначальной истории используется период фида, затем сбор догоняет ID; удалённая или недоступная сохранённая граница даёт предупреждение о возможном пробеле. Позиции RSS и Telegram разделены. Незавершённый материал другого транспорта требует возврата к исходному способу сбора для повтора.

Альбом — одна карточка, ID его частей сохраняются как служебные данные. Текст доступен до окончания загрузки. Изображения, видео, кружочки, аудио и файлы заранее сохраняются локально; неподдерживаемое вложение или сбой оставляют материал неполным с причиной и повтором. Очень свежий альбом остаётся неполным до повторной проверки. Лимит одного вложения — 200 МБ, скачивания — 180 секунд; превышение явно показывается. В этой минимальной версии готовые вложения передаются через память, видео в браузер — авторизованным запросом и Blob, поэтому большие альбомы требуют заметной памяти. Обработка AI и расшифровка не вызываются.

Все части и временные файлы удаляются при «Просмотрено». Остановка моста прекращает скачивание и освобождает сессию. Отметки прочитанного Telegram на этом этапе не отправляются: UI объясняет, что сохранённые настройки автопрочитывания относятся к следующему этапу.

[Проверки Telegram и ограничения реального подключения](docs/verification/telegram-reading.md).
