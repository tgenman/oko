# Око

Локальный читатель: папки → карточки → материал. Работают синтетический источник, импорт OPML, папки и наследуемые настройки; настоящие RSS, Telegram, YouTube и AI описаны в следующих тикетах.

## Запуск

Python 3.11+ и uv:

```sh
uv sync --extra dev
uv run python -m oko --demo
```

Браузер открывается автоматически. Повтор той же команды открывает действующий экземпляр. `--data /путь` выбирает хранилище; по умолчанию это `data/` текущего каталога. `--no-browser` оставляет открытие браузера вызывающему коду. Без `--demo` новые источники не подключаются; сохранённые материалы доступны.

Открытие и копирование сохраняют материал. «Просмотрено» удаляет его содержимое. Если требуется повторно пройти демонстрацию с тремя публикациями, используйте другой каталог `--data`.

Вкладка посылает heartbeat раз в 2 секунды. Через 6 секунд без связи задания приостанавливаются; процесс ждёт переподключения ещё 15 секунд и выходит; на завершение принадлежащих ему задач отведено дополнительно до 0,5 секунды (две границы по 250 мс), плюс завершение HTTP-сервера. «Остановить Око» завершает все вкладки сразу. Автозапуска нет. Замороженная вкладка может потерять связь; после сна сбор требует нового heartbeat. Таймауты настраиваются `--lease` и `--grace`; значения должны быть положительными.

## Подписки и настройки

«Подписки и настройки» → «Импорт OPML» → выбрать файл → разрешить конфликты папок → импортировать. Повторный импорт объединяет известные идентичности, сохраняет исходные URL и настроенные поля. Один фид находится в одной папке. Вложенные папки показываются путём «Родитель / Папка»; буквальный слеш имени отображается как `\/`, обратный — как `\\`, чтобы не смешивать разные структуры. Числовые префиксы задают порядок, остальные папки сохраняют порядок импорта. Для уже известного фида, пришедшего в другую папку, также требуется явный выбор.

Распознаются Telegram-адреса и RSSHub `/telegram/channel/<username>` с известными параметрами отображения `show…` в пути ([контракт RSSHub](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/telegram/channel.ts)). Фильтрующие и неизвестные параметры остаются неоднозначным подключением: RSS можно выбрать явно, с ограничениями. YouTube RSS с `channel_id` сопоставляется с каналом. Распознавание не проверяет доступность источника. Импорт не запускает сеть и не переносит счётчик непрочитанного News Explorer.

Настройки Око, папки и фида переопределяются по отдельным полям. «Сбросить» возвращает наследование. Режимы оригиналов, тезисов и обзоров сочетаются; промпты, период обзора, расписание (`off` либо местное `HH:MM`) и имя обработчика сохраняются, их выполнение добавляется последующими задачами. Важность, первоначальный период (сутки), разрешение публичного AI и настройки Telegram принадлежат самому фиду. AI и очистка начальной истории выключены, автопрочитывание не выбрано. Сохранение не отправляет отметки Telegram.

Контракт адаптеров: `Store.subscriptions.effective('feed', feed_id)` или `GET /api/settings/feed/<id>` возвращает `effective` с `value/scope/owner`, собственные `overrides` и `feed` с разрешениями, адресами, транспортом и периодом. `null` в PATCH настройки сбрасывает поле. `create_app(..., source_feed=feed_id)` связывает внедрённый источник с конфигурацией; позиции и идентичности публикаций разделены по фидам. Настройки подписок сохраняются в той же SQLite без контента публикаций. Импортированные фиды показывают необходимость подключения; одно поле `transport` выбирает способ сбора.

В читателе доступны выбор папки, «Новые сверху» (по умолчанию), «Старые сверху» и «Сначала важное» (при равной важности новые сверху). Счётчики отражают доступные непросмотренные карточки.

## Хранение и восстановление

SQLite хранит идентичности, состояние, позиции и очередь. Содержание находится в `content/<id>/1/original.md`: первая строка — JSON-заголовок, далее Markdown. Запись: staging → fsync → атомарное перемещение → транзакция полноты. При перезапуске сироты удаляются, незавершённые задания восстанавливаются. Удаления имеют приоритет; их ошибка блокирует новый сбор до успешного повтора.

Просмотр фиксируется транзакцией до физического удаления. Поздние результаты проверяют поколение задания и просмотр. Адаптеры должны поддерживать отмену и ограниченные сетевые таймауты. Если адаптер игнорирует отмену, его поколение инвалидируется, ожидание ограничено 250 мс; при завершении собственный цикл событий Око закрывается после ещё 250 мс. Это не останавливает чужие процессы. После удаления остаются ID, URL и служебное состояние; заголовок и текст в SQLite не записываются. Ошибки сохраняются в виде безопасных категорий. Повреждённая база сохраняется с видимой ошибкой, без пересоздания. Гарантии восстановления предполагают исправный диск. Стирание физических секторов и пользовательского буфера обмена не выполняется.

Сервер слушает IPv4 loopback. API требует случайный токен сессии из ссылки запуска; проверяет Host и Origin. UI не исполняет Markdown/HTML материалов, выводит текст через `textContent`. Ответы имеют `no-store`, CSP и запрет встраивания. Постоянные браузерные хранилища не используются. Просмотр сбрасывает открытый материал в других вкладках через BroadcastChannel и опрос API (500 мс); pagehide очищает DOM, возврат из bfcache перезагружает страницу.

## Проверки

```sh
uv run python -m pytest
uv run mypy oko
node --check oko/web/app.js
```

Основная граница — API с настоящими временными SQLite/файлами, управляемым временем и синтетическими источниками. Процессные тесты открывают loopback и аварийно завершают дочерний процесс в точках транзакции и записи. Тестовые fault hooks передаются только Python-кодом, через HTTP не доступны.
