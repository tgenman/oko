# Око

Локальный читатель: папки → карточки → материал. Работают RSS/Atom со статьями и локальными изображениями, синтетический источник, импорт OPML, папки и наследуемые настройки. Telegram реализован и ожидает проверки свободной сессии; адаптер тезисов llama.cpp реализован и ожидает настоящую модель. Codex проверен. YouTube реализован; настоящая приёмка ожидает доступность сети YouTube.

В «Добавить фид → RSS / YouTube» вставьте адрес RSS/Atom-фида и нажмите «Проверить фид». После проверки название подставляется автоматически; его можно изменить, выбрать или создать папку и нажать «Добавить». До сохранения подписка и папка не создаются. Повторное добавление показывает «Уже добавлен» и открывает существующий фид с его настройками. YouTube-фид канала автоматически использует сборщик YouTube, как и при импорте OPML: список видео из Atom, превью и доступные субтитры при включённых тезисах или высокой важности. Тезисы включены по умолчанию для всех фидов. Видео и аудио не скачиваются.

При подключении RSS/YouTube или Telegram выберите начальную историю: последние N публикаций (по умолчанию 20) либо начиная с даты включительно. Дата означает начало выбранного дня в вашем часовом поясе; будущая дата недопустима. Количество — целое от 1. Набор последних N закрепляется при первом успешном обращении к источнику, а новые поступления собираются дополнительно. Материалы доступны по мере сохранения; готовности тезисов ждать не требуется.

В настройках фида видны выбранная граница, прогресс, неполнота и ошибки начальной истории. «Приостановить историю» сохраняет прогресс и оставляет сбор новых публикаций работающим; «Продолжить историю» возвращается к прежнему набору. Набор, прогресс и пауза сохраняются после перезапуска. Временные ошибки повторяются с задержкой, окончательная недоступность показана отдельно. Повторное подключение открывает существующий фид без изменения истории; расширение истории уже подключённого фида не добавлено. OPML сохраняет прежние правила.

Переключатель «Диагностика» в шапке открывает нижнюю панель исключений браузера, API, сборщиков и обработки с временем, источником и traceback. Одинаковые ошибки объединяются со счётчиком и временем первого/последнего появления; ошибки разных фидов разделяются. Запись работает и при закрытой панели; последние 100 групп сохраняются в `data/debug.json` (или выбранном `--data`) после перезапуска. Ошибки дочерних Telegram/YouTube-процессов передают исходный traceback. Штатная отмена задач и обнаруженное удаление публикации источником не считаются ошибками. Токен сессии скрывается, локальные сообщения и traceback сохраняются без переменных стека. Если сервер недоступен, ошибки браузера остаются в текущей вкладке и отправляются после восстановления связи; при закрытии вкладки неотправленные ошибки теряются.

## Запуск

Codex на macOS: Око предпочитает непосредственно проверенный бинарник из `ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`; если его нет, ищет CLI в PATH. `OKO_CODEX_BINARY` задаёт явный путь для другой установки. Диагностика, каталог и обработка используют один выбранный файл; допуск требует проверенного SHA-256. Текущая проверенная сборка — `0.162.0-alpha.17.2`. Shell-обёртка из `codex-cli/bin/` не используется: профиль запрещает запуск других программ. Обновление приложения с изменением бинарника потребует повторной проверки допуска. Сохранённые модели Око автоматически не заменяются.

На этом Mac можно открыть **Око.app** в папке проекта двойным щелчком и перетащить его в Dock. Терминал не открывается; браузер открывается автоматически. Приложение использует существующую `.venv`, хранилище `data/` и авторизацию Telegram. Повторный запуск открывает действующий экземпляр. Остановка — кнопкой «Остановить Око» или закрытием всех вкладок с последующим штатным завершением процесса.

Исходник запуска — `scripts/launch.applescript`. Пересобрать приложение после изменения исходника: `osacompile -o Око.app scripts/launch.applescript`. Приложение должно оставаться в корне проекта; журнал запуска находится в `data/launcher.log`.

Python 3.11+ и uv:

```sh
uv sync --extra dev
uv run python -m oko
# Демонстрация без настоящих источников:
uv run python -m oko --demo
```

Браузер открывается автоматически. Повтор той же команды открывает действующий экземпляр. `--data /путь` выбирает хранилище; по умолчанию это `data/` текущего каталога. `--no-browser` оставляет открытие браузера вызывающему коду. Без `--demo` подключаются импортированные RSS/Atom. При открытой вкладке сбор выполняется при запуске, для новых подписок, по кнопке «Обновить источники» и раз в пять минут.

Открытие и копирование сохраняют материал. «Просмотрено» удаляет его содержимое. Если требуется повторно пройти демонстрацию с тремя публикациями, используйте другой каталог `--data`.

Вкладка посылает heartbeat раз в 2 секунды. Через 6 секунд без связи задания приостанавливаются; процесс ждёт переподключения ещё 15 секунд и выходит; на завершение принадлежащих ему задач отведено дополнительно до 0,75 секунды (две задачи и завершение цикла, по 250 мс), плюс завершение HTTP-сервера. «Остановить Око» завершает все вкладки сразу. Автозапуска нет. Замороженная вкладка может потерять связь; после сна сбор требует нового heartbeat. Таймауты настраиваются `--lease` и `--grace`; значения должны быть положительными.

## Подписки и настройки

На главном экране доступны отдельные меню «Добавить фид», «Фиды и папки» и «Настройки Око». В «Фидах и папках» выберите объект в списке: справа откроются его настройки, наследуемые значения и прогресс истории. На узком экране вернуться к списку можно кнопкой «Назад». Общие параметры находятся в «Настройки Око → Обработка и представление», подключения llama.cpp и Codex — в разделе «Подключения моделей».

Для YouTube выбор последних N обычных видео и записей трансляций выполняется через yt-dlp, без Shorts и скачивания видео/аудио. В настройках подключённого фида можно явно загрузить последние N видео: известные учитываются, просмотренные не возвращаются, уменьшение N не удаляет сохранённое. Подбор идёт ограниченными порциями; после ошибки или исчерпания порции доступно ручное продолжение. Остановка сохраняет уже загруженное. Новые поступления собираются независимо через RSS; история по дате ограничена его доступным окном. Даты старых видео могут отсутствовать — в этой группе сохраняется порядок источника. [Проверки истории](docs/verification/uncommitted-completion.md).

После добавления открываются настройки нового фида; повторное подключение открывает существующий без изменения его истории. После OPML открывается список фидов. Несохранённые поля сохраняются отдельно для объектов и форм в пределах открытой вкладки; закрытие меню не сохраняет их автоматически. Успешное добавление очищает форму. Одновременно открыто одно меню; закрытие и Escape возвращают к прежнему чтению и кнопке открытия.

YouTube-подписки из OPML подключаются автоматически по `channel_id`. Для отключённого фида включите «Собирать обновления YouTube» в его настройках. Тезисы включены по умолчанию для всех фидов. Для YouTube включённые тезисы или высокая важность запрашивают доступные субтитры. Полученный текст повторно не запрашивается. Тезисы используют выбранный обработчик и эффективный промпт; для Codex требуется разрешение публичного AI. Субтитры, локальное превью и тезисы удаляются по «Просмотрено». Нет загрузки полного видео или ASR. Отсутствие субтитров, ошибка и повтор показаны явно. Поставщик — youtube-transcript-api 1.2.4, один отменяемый запрос до 60 секунд; блокировки и доступность YouTube могут мешать сбору. [Проверки и ограничение настоящего подключения](docs/verification/youtube-updates.md).

«Добавить фид» → «Импорт OPML» → выбрать файл → разрешить конфликты папок → импортировать. Повторный импорт объединяет известные идентичности, сохраняет исходные URL и настроенные поля. Один фид находится в одной папке. Вложенные папки показываются путём «Родитель / Папка»; буквальный слеш имени отображается как `\/`, обратный — как `\\`, чтобы не смешивать разные структуры. Числовые префиксы задают порядок, остальные папки сохраняют порядок импорта. Для уже известного фида, пришедшего в другую папку, также требуется явный выбор.

Распознаются Telegram-адреса и RSSHub `/telegram/channel/<username>` с известными параметрами отображения `show…` в пути ([контракт RSSHub](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/telegram/channel.ts)). Фильтрующие и неизвестные параметры остаются неоднозначным подключением: RSS можно выбрать явно, с ограничениями. YouTube RSS с `channel_id` сопоставляется с каналом. Распознавание не проверяет доступность источника. Парсер импорта не обращается к сети; в работающем читателе очередь начинает сбор импортированных RSS. Счётчик непрочитанного News Explorer не переносится.

Настройки Око, папки и фида переопределяются по отдельным полям. «Сбросить» возвращает наследование. Режимы оригиналов, тезисов и обзоров сочетаются; промпты, период обзора, расписание (`off` либо местное `HH:MM`) и имя обработчика сохраняются. Адаптер llama.cpp реализован и ожидает проверки настоящей модели; Codex проверен. Обзоры, фильтрация и расписания добавляются последующими задачами. Важность, начальная история, разрешение публичного AI и настройки Telegram принадлежат самому фиду. У старых фидов сохранённая граница остаётся прежней; изменение отображения настроек не запускает историю заново. AI и очистка начальной истории выключены, автопрочитывание не выбрано. При работающем Око выбранные Telegram-настройки запускают безопасную накопительную синхронизацию.

Контракт адаптеров: `Store.subscriptions.effective('feed', feed_id)` или `GET /api/settings/feed/<id>` возвращает `effective` с `value/scope/owner`, собственные `overrides` и `feed` с разрешениями, адресами, транспортом и периодом. `null` в PATCH настройки сбрасывает поле. `create_app(..., source_feed=feed_id)` связывает внедрённый источник с конфигурацией; позиции и идентичности публикаций разделены по фидам. Настройки подписок сохраняются в той же SQLite без контента публикаций. Импортированные фиды показывают необходимость подключения; одно поле `transport` выбирает способ сбора.

В читателе доступны выбор папки, «Новые сверху» (по умолчанию), «Старые сверху» и «Сначала важное» (при равной важности новые сверху). Счётчики отражают доступные непросмотренные карточки.

## Хранение и восстановление

Действиями читателя управляет `oko/reader/runtime.py`: просмотр, повтор, переключение источника, подключение, закрытие вкладки и остановка согласуются внутри модуля. Изменения состояния и фиксация результатов последовательны; сетевые ожидания проходят вне блокировки. HTTP-код читает Store и передаёт действия Runtime, не управляя активным заданием и очисткой самостоятельно. [Согласованная архитектура](docs/architecture/reader-work.md).

SQLite хранит идентичности, состояние, позиции и очередь. Содержание находится в `content/<id>/1/original.md`: первая строка — JSON-заголовок, далее Markdown. Запись: staging → fsync → атомарное перемещение → транзакция полноты. При перезапуске сироты удаляются, незавершённые задания восстанавливаются. Удаления имеют приоритет; их ошибка блокирует новый сбор до успешного повтора.

Просмотр фиксируется транзакцией до физического удаления. Поздние результаты проверяют поколение задания и просмотр. Адаптеры должны поддерживать отмену и ограниченные сетевые таймауты. Если адаптер игнорирует отмену, его поколение инвалидируется, ожидание ограничено 250 мс; при завершении собственный цикл событий Око закрывается после ещё 250 мс. Это не останавливает чужие процессы. После удаления остаются ID, URL и служебное состояние; заголовок и текст в SQLite не записываются. Очередь сохраняет безопасные категории ошибок; отдельный журнал диагностики сохраняет сообщения исключений и traceback. Повреждённая база сохраняется с видимой ошибкой, без пересоздания. Гарантии восстановления предполагают исправный диск. Стирание физических секторов и пользовательского буфера обмена не выполняется.

Сервер слушает IPv4 loopback. API требует случайный токен сессии из ссылки запуска; проверяет Host и Origin. UI не исполняет Markdown/HTML материалов, выводит текст через `textContent`. Ответы имеют `no-store`, CSP и запрет встраивания. Постоянные браузерные хранилища не используются. Просмотр сбрасывает открытый материал в других вкладках через BroadcastChannel и опрос API (500 мс); pagehide очищает DOM, возврат из bfcache перезагружает страницу.

## Проверки

Для нового checkout включите обязательные локальные проверки: `./scripts/install-hooks`. Перед коммитом проверяются staged-синтаксис и JavaScript `no-undef`; push не повторяет тесты. Полный набор выполняется в CI для pull request и push в `main`. Подготовка окружения и выбор отдельных наборов и файлов описаны в [инструкции проверок](tests/browser/README.md).

```sh
./scripts/check ui
./scripts/check all
```

Настройка окружения и выбор runtime описаны в [инструкции проверок](tests/browser/README.md). Команда не устанавливает зависимости. Состав режимов и правила выбора проверки: [порядок разработки](docs/agents/development.md).

Основная граница — API с настоящими временными SQLite/файлами, управляемым временем и синтетическими источниками. Процессные тесты открывают loopback и аварийно завершают дочерний процесс в точках транзакции и записи. Тестовые fault hooks передаются только Python-кодом, через HTTP не доступны.

[Результаты браузерной проверки](docs/verification/first-reader.md), [тикет первого пути](.scratch/oko-implementation/issues/01-first-reader-path.md), [следующие задачи](.scratch/oko-implementation/README.md).

## RSS/Atom

Первый проход нового фида использует выбранное количество или дату; старые фиды и OPML сохраняют прежний первоначальный период (по умолчанию сутки). Сохранённая граница импорта применяется после перезапуска: доступное окно RSS перечитывается, известные ID/URL пропускаются. RSS/YouTube предоставляют только текущее окно фида; отдельный архив не загружается. Если запрошено 100 публикаций, а доступны 15, показан фактический объём; полнота выбранного периода может оставаться неподтверждённой. Записи без даты помечены «Дата неизвестна» и включаются в режим даты; неоднозначный порядок сопровождается предупреждением о точности выбора последних N. Уже выбранные публикации сохраняют ссылки и анонсы для продолжения, даже если выпали из окна; ещё не обнаруженные старые записи вне окна восстановить нельзя. GUID используется в области фида; без него — нормализованный URL. Неоднозначный GUID с разными ссылками не скрывает второй материал и не подменяет анонс старого задания.

Анонс сохраняется до фиксации позиции вместе с заданиями. Затем выполняется попытка извлечь статью из HTML и сохранить PNG/JPEG/GIF/WebP. При неудаче доступны анонс, причина неполноты и «Повторить загрузку». Извлечение эвристическое, без JavaScript: динамические сайты, платный доступ и защита могут оставаться анонсом. Лимиты: XML/HTML 4 МБ, изображение 10 МБ, 30 изображений, 20 секунд на HTTP-запрос. Браузер получает картинки через авторизованный локальный API.

Просмотр удаляет анонс, статью, изображения и staging; поздний ответ не возвращает контент. Ошибки авторизации, частоты и доступности видны по фидам; остальные продолжают сбор. RSSHub Telegram собирается только при явном выборе ограниченного транспорта RSS, без отметок Telegram. Тезисы сохранённого текста доступны при включённом режиме и подключённой модели llama.cpp.

Проверки и границы: [RSS](docs/verification/rss-reading.md).

## Telegram с медиа

Запуск с существующим окружением клиента:

```sh
uv run python -m oko --telegram-env /Users/dabondarev/repo_personal/telegram-mcp/.env
```

Минимальный клиент находится в Око и вызывает Telethon напрямую. MCP и код/окружение проекта `telegram-mcp` не используются. Из существующей `.env` читаются настройки авторизации, без копирования файла и сессий. Поддерживаются именованные StringSession и существующие `.session` (относительные пути считаются от `.env`), device identity и proxy; пулы `TELEGRAM_SESSION_STRINGS` пока не поддерживаются. Собственный процесс клиента позволяет принудительно остановить зависшее скачивание. Защита сессии совместима с прежним клиентом: занятый аккаунт показывается как ошибка, без остановки другого клиента. Старый флаг `--telegram-project` оставлен как сокращение пути к `.env`, без импорта его кода. Вход и создание сессий здесь не выполняются.

В «Добавить фид → Telegram» аккаунт выбирается из списка собственного клиента. Можно подключить публичный username либо ID доступного приватного канала/группы; импортированный или уже подключённый Telegram-фид настраивается в «Фиды и папки» через отдельный блок переподключения без повторной начальной истории. Подключение блокируется до заполнения обязательных полей и на время запроса. Для форумной группы нажмите «Загрузить темы группы» и выберите тему, включая «Общее». Каждая тема — отдельный фид со своим курсором и настройками; повторное подключение сохраняет один фид в одной папке. Отметки прочитанного относятся только к выбранной теме, весь форум вместо неё не подтверждается. [Проверки формы и тем](docs/verification/telegram-topics.md). Код совместимой блокировки адаптирован из telegram-mcp; [лицензия](docs/licenses/telegram-mcp-Apache-2.0.txt).

Страницы истории по 100 сообщений сохраняются вместе с заданиями и позицией. При новом подключении последние N либо период с даты выбираются от новых сообщений к старым с фиксированной верхней границей; альбом считается одной публикацией и дочитывается целиком. Сбор новых сообщений идёт отдельно от начальной истории. Старые фиды без нового выбора продолжают прежний обход от сохранённой границы. Удалённая или недоступная сохранённая граница даёт предупреждение о возможном пробеле. Позиции RSS и Telegram разделены. Незавершённый материал другого транспорта требует возврата к исходному способу сбора для повтора.

Для режима количества сначала сохраняется список выбранных ID, затем загружается содержимое: удалённая из списка публикация не заменяется более старой. Telegram не предоставляет атомарный снимок всего канала; сообщение, исчезнувшее до получения его ID во время порционного подбора, восстановить невозможно. Это ограничение явно обозначается при выборе истории.

Альбом — одна карточка, ID его частей сохраняются как служебные данные. Текст доступен до окончания загрузки. Изображения, видео, кружочки, аудио и файлы заранее сохраняются локально; неподдерживаемое вложение или сбой оставляют материал неполным с причиной и повтором. Очень свежий альбом остаётся неполным до повторной проверки. Лимит одного вложения — 200 МБ, скачивания — 180 секунд; превышение явно показывается. В этой минимальной версии готовые вложения передаются через память, видео в браузер — авторизованным запросом и Blob, поэтому большие альбомы требуют заметной памяти. Тезисы через llama.cpp используют сохранённый текст; расшифровка аудио и видео не выполняется.

Все части и временные файлы удаляются при «Просмотрено». Остановка моста прекращает скачивание и освобождает сессию. Telegram подтверждается накопительно: при автопрочитывании — после полного сохранения текста и медиа, иначе — после «Просмотрено». Позднее сообщение ждёт более ранние; старая история до зафиксированного начала импорта очищается только при отдельном разрешении. Очередь хранит ID и основание допустимости, переживает удаление контента и перезапуск. Серверная отметка другого клиента не удаляет материал в Око. Статус ожидания и ошибки видны в индикаторе обработки. Неподдерживаемые forum topics не подтверждаются как весь диалог.

[Проверки Telegram и ограничения реального подключения](docs/verification/telegram-reading.md).

## Субтитры YouTube и прокси

В «Настройки Око → Субтитры YouTube» можно выбрать прямое подключение либо HTTP/HTTPS-прокси. Адрес вводится без логина и пароля; учётные данные задаются отдельными полями. Пустые поля сохраняют прежние учётные данные, флажок удаления удаляет их явно. Сохранение не проверяет YouTube и не выполняет платный запрос. Прокси применяется только к получению дорожек и субтитров, не к Atom, превью и другим источникам. При отказе прокси прямое подключение автоматически не включается. Переменные `HTTP_PROXY`/`HTTPS_PROXY` не используются.

Для всех фидов действует общий интервал 10 секунд между началами загрузок субтитров. Одна загрузка может содержать несколько HTTP-запросов SDK. После распознанной блокировки или HTTP 429 действует общая пауза от 15 минут; повторные блокировки увеличивают её вдвое до 6 часов. Более длинный `Retry-After` имеет приоритет. Пауза видна в настройках и сохраняется после перезапуска и смены прокси. Сбор других источников и чтение продолжаются. После паузы работа возобновляется только при открытом читателе, без одновременного запуска накопленных запросов.

После трёх попыток одного материала требуется явный повтор; ручной повтор не обходит общую паузу. Отсутствие дорожки и обычный сетевой сбой не включают общую паузу и требуют явного повтора. Полученные субтитры повторно не запрашиваются. Эти интервалы — правила Око, а не гарантия доступности YouTube.

Настройки прокси сохраняются в `youtube-proxy.json` внутри каталога данных с правами `0600`; ответы чтения настроек не содержат учётных данных. Worker получает настройки через stdin, а не аргументы процесса. Для его ошибок сохраняются класс исключения и позиции стека; строки исходного кода, цепочки исключений, URL и учётные данные в диагностике не передаются. [Спецификация](.scratch/youtube-request-control/spec.md).

## Тезисы через llama.cpp

В «Настройки Око → Подключения моделей → Модель llama.cpp» укажите адрес одного `llama-server`, например `http://127.0.0.1:8080`, и точный ID модели из `/v1/models` (путь GGUF либо `--alias`). Адрес вводится без `/v1`, секретов и query. Сохраните и проверьте подключение. Око не устанавливает движок, не скачивает модель и не запускает сервер. В настройках Око, папки или фида выберите «llama.cpp», включите «Тезисы публикаций» и задайте промпт. Каждое поле наследуется отдельно. Подготовка уже сохранённых публикаций начинается в очереди; открытие карточки генерацию не запускает.

Для фидов без разрешения публичного AI отметьте подтверждение «Сервер выполняет модель на этом компьютере, без прокси и удалённого RPC» только для соответствующего подключения. Перед каждым заданием Око проверяет loopback-адрес, одну загруженную модель, владельца `llamacpp`, размер весов и GGUF-путь/build info из `/props`. Подтверждение сохраняется для данного подключения и сбрасывается в форме при смене адреса или модели. Метаданные не аттестуют произвольный сервер; без подтверждения, при удалённом адресе, неизвестных метаданных или списке нескольких моделей требуется разрешение публичного AI. Исчезнувшая модель блокирует генерацию. Проверка подключения не отправляет публикации. HTTP-клиент не использует системный proxy и не следует редиректам.

Старое подключение Ollama и значения `ollama`/`ollama:<model>` не перенаправляются автоматически. Укажите новое подключение и выберите `llamacpp` на тех уровнях наследования, где был выбран старый обработчик. Промпты, папки и разрешения сохраняются; старый выбор показывает ожидание настройки. Ключ старого подключения остаётся неиспользуемыми служебными данными.

Отправляется полный текст и промпт; материалы свыше 150 000 символов входа получают явную ошибку без обрезки. Ответ ограничен 2 МБ, вывод — 4096 токенами. Око принимает только завершённый `finish_reason=stop`, JSON по схеме и точные исходные ID/URL. Незавершённый ответ и попытка tool call не публикуются. Скрытого переключения обработчика нет.

Тезисы и раскрываемый оригинал доступны вместе. «Просмотрено» удаляет содержимое в Око. Вход и необработанный ответ остаются в памяти Око, без собственных логов/копий. Результат хранится в `theses.md`; SQLite содержит состояние и версии. Смена настроек, разрешений, остановка и просмотр отменяют старую работу; поздний результат не публикуется. Око закрывает свой HTTP-запрос и не останавливает общий сервер llama.cpp. После неизвестного исхода возможен повтор, но публикуется только актуальный результат.

Сервером управляет пользователь. Для выполнения условий без постоянных копий запускайте его без логирования содержимого и без сохранения slots, например с `--log-disable`, без `--log-file`, `--slot-save-path` и подробного логирования. `cache_prompt=false` в запросе отключает повторное использование prompt cache; это не обещание физического стирания памяти сервера. Око не управляет чужими файлами и кэшами.

[Проверки и ограничения llama.cpp](docs/verification/llamacpp-theses.md). Настоящая модель ещё скачивается: реальная интеграция пока не принята.

## Codex

В «Настройки Око → Подключения моделей → Codex» проверьте CLI и существующий вход. Для нужного фида включите «Разрешить публичный AI», выберите Codex и включите тезисы в настройках Око, папки или фида. Запрет проверяется до подготовки входа; автоматического fallback нет.

Поддерживается проверенная macOS-сборка CLI 0.136.0 с конкретным SHA-256; обновлённая или другая сборка остаётся недоступной до проверки. Внешний sandbox ограничивает файлы и запуск программ; инструменты отключены. Текст передаётся через stdin, ответ валидируется, runtime-файлы хранятся только в staging и удаляются. Используется прежний вход ChatGPT; Око не копирует секреты и не требует платный API. До каждого задания свежие лимиты проверяются через отдельный изолированный app-server без передачи публикаций; неизвестная или исчерпанная квота закрывает допуск. Поддерживается вход ChatGPT; остаток квоты не резервируется, достаточность подписки для любого объёма не обещается. [Настоящие проверки и ограничения](docs/verification/codex-theses.md).

## Структура проекта

`oko/collection` содержит источники и их workers, `processing` — общий контракт AI и adapters Codex/llama.cpp, `reviews` — фильтрацию, события и обзоры. `reader` управляет чтением и работой Око, `storage` — SQLite/файлами, `subscriptions` — подписками и наследованием настроек. Запуск остаётся `python -m oko`.

Тесты сгруппированы в `tests/reader`, `collection`, `processing`, `reviews` и `lifecycle`; общие синтетические adapters и процессные помощники находятся в `tests/support`. Полная проверка: `./scripts/check all`. Подробности: [структура пакетов](docs/architecture/package-layout.md).

При повторном сборе Око проверяет правки в доступном окне RSS/YouTube и перечитывает известные непросмотренные Telegram-сообщения. Возможности и ограничения видны в UI. Новое содержимое сохраняется отдельной версией с исходными медиа; предыдущие версии доступны до просмотра. Исчезновение записи из RSS/Atom не считается удалением. Недоступный в источнике материал остаётся локально. Тезисы, события и обзоры обновляются по текущим версиям; состав созданного обзора сохраняет прежние ID. Проверки и границы приёмки: [версии источников](docs/verification/source-revisions.md).
