# Контракт читателя

`openapi.yaml` — редактируемый источник всех 50 операций `/api/` в OpenAPI 3.1. Первоначальный baseline взят из действующего HTTP и дополнен ответами, которые раньше возвращались как словари. FastAPI не перезаписывает этот файл. Обработка, допустимость действий и состояние вкладки остаются ответственностью приложения.

Команды из корня checkout:

```sh
python scripts/api.py validate
python scripts/api.py bundle --output /tmp/oko-openapi.json
python scripts/api.py docs
```

После установки закреплённых npm-зависимостей последняя команда открывает самостоятельный Swagger по `http://127.0.0.1:8766/docs`. Можно задать `--port` и `--assets`. Читатель, Runtime, Store и внешние источники не создаются. Все assets локальные; Try it out и Authorize отсутствуют. Просмотр не выполняет API-запросов. Встроенная в работающий читатель документация с явной авторизацией поставляется отдельно.

Bundle содержит те же локальные references, без внешних `$ref`. Его канонические UTF-8 байты: JSON с `ensure_ascii=False`, `sort_keys=True`, `separators=(',', ':')` и одним завершающим переводом строки. По этим байтам сборка считает SHA-256 для согласованности контракта, библиотек и документации.

Пустой JSON schema в `ValidationError.input` и значениях `ctx` намеренно допускает произвольные диагностические JSON-данные. Остальные ответы перечисляют DTO, обязательность и nullable-поля. Ограничения, зависящие от каталога моделей, часового пояса и текущего состояния, описаны в контракте и дополнительно проверяются сервером.

Проверки проходят через команду bundle, существующий HTTP interface и настоящий Swagger в Playwright: `tests/api/test_contract.py` и `tests/browser/test_api_docs.cjs`. Они используют временные хранилища и синтетические adapters.

## Изменения контракта

`baseline.json` хранит полный проверенный контракт до следующего согласованного изменения. `npm run api:compat` сравнивает его с canonical OpenAPI. Изменения wire shape, обязательности/nullability, ограничений, путей, operationId, auth, headers, media types и HTTP-ответов останавливают проверку как **потенциально несовместимые**. Это консервативный сигнал для ревью: даже совместимое добавление требует разбора. Description/title/example/summary и корневые info/tags не считаются wire changes; реальные properties с такими именами сохраняются при сравнении.

Автоматический diff не доказывает семантическую совместимость. Изменения defaults, правил времени, принадлежности/состава, identity, PATCH/reset, побочных эффектов и ошибок отдельно проверяются человеком по спецификации, HTTP/browser-тестам и всем потребителям. Breaking change повышает major в `info.version`; совместимое дополнение — minor, исправление документации — patch. Генерация и сборка никогда не обновляют baseline автоматически.

После ревью зафиксируйте документ с прежней/новой версией, изменившимся поведением, совместимостью потребителей, порядком перехода и выполненными проверками. Затем явно выполните:

```sh
npm run api:baseline -- --review path/to/semantic-review.md
npm run api:generate
npm run api:check
```

Обновление требует изменённого `info.version` и непустого документа ревью. Команда записывает baseline и `baseline.review.json`: исходную/новую версии, SHA-256 обоих контрактов и полный текст ревью. Это сохранённое свидетельство решения; команда не проверяет качество текста и не заменяет независимого reviewer. Документ и evidence коммитятся вместе с контрактом и обеими generated-библиотеками.

`api:check`, frontend build и package build проверяют совместимость и deterministic regeneration во временных каталогах без изменения checkout. Pre-commit при API/codegen/config изменениях дополнительно материализует соответствующие **байты Git index** во временный каталог и сравнивает обе generated-библиотеки с результатом генерации. Unstaged изменения не исправляют и не портят результат index checks; удалённые staged файлы также обнаруживаются. Изменение уже существующего baseline требует в index соответствующего evidence и новой версии. Первоначальный baseline в этой миграции совпадает с полным текущим контрактом.

Все contract references должны быть существующими локальными JSON pointers. `$ref`, `$dynamicRef` и `$recursiveRef` проверяются до OpenAPI validation; внешние references не загружаются. Node, Python и генераторы нужны для разработки/сборки и отсутствуют в пути обычного запуска читателя.
